# NF-3 — CE 탈가중 + 크기 래칫 (CE De-weighting & the Magnitude Ratchet)

발견: 2026-07-25, CLM PURE 300M fix2 run (aiden RTX5070) 실측 + lab(fable·sol) 병렬 분석
선행: [NF-1 부호-무정의 손실 발산](NF-1-lossensemble-divergence.md) · [NF-2 미토시스 스케줄 위상 어긋남](NF-2-mitosis-schedule-misalignment.md)
커밋: 7159dd716

## 1. 실험 목적 및 가설

NF-1(클램프) 적용 run에서 검증 CE가 4.84 부근에서 멈추고, 로그의 `tension`이
46 → 163,069으로 폭증했다. 최초 가설은 "클램프가 가중치만 묶어 `-log(t_var)` 항
자체를 통한 착취가 계속된다"였다. **이 가설은 반증됐다.**

## 2. 반증과 진짜 원인 (검증된 사실만)

### 2-1. 텐션 항 착취는 이미 닫혀 있었다 (가설 반증)

`t_var`는 `torch.clamp(..., max=100.0)`로 이미 잘려 있었다(NF4, NF-1 클램프보다 먼저
들어감). 따라서 언어 페이즈 텐션 항의 바닥은 고정값이다:

```
precision 상한 e² = 7.389 · 페이즈 계수 0.1 · -log(100) = -4.605
  → 항 바닥 = 7.389 × 0.1 × (-4.605) ≈ -3.40  (+log_var/2 항 포함 시 ≈ -4.40)
실측 복합손실 바닥: -4.29 ~ -4.34 (74,700 step)   ← 계산과 일치
```
즉 `+76 → -4.3` 하강은 착취가 아니라 **바닥에 도달한 것**이다. 두 프런티어 모델이
독립적으로 같은 지적을 했고 숫자도 일치했다.

### 2-2. 진짜 원인 ① — 학습가능 가중치가 CE를 47배 눌렀다 (체크포인트 실측)

`step_70000.pt`에서 학습된 `log_vars`를 직접 읽었다:

| 손실 슬롯 | log_var | 유효 precision |
|-----------|---------|----------------|
| ce_fwd | +1.8516 | **0.157** |
| ce_bwd | +1.8517 | **0.157** |
| tension_var | -2.0038 | **7.389** (경계) |
| phi_diff | -2.0073 | **7.389** (경계) |
| competition | -2.0110 | **7.389** (경계) |
| myelination | -2.0022 | **7.389** (경계) |

```
언어를 배우는 항 │ ██ 0.157
구조 정규화 항   │ ██████████████████████████████████████████████ 7.389
                 └─ 47배 핸디캡
```
Kendall 불확실성 가중은 **우도에서 온 비음수 손실**에만 성립하는 유도다. 구조 4항은
정규화 항이고, 그중 둘은 페이즈 밖에서 **리터럴 0.0**으로 들어간다 — `L=0`이면
목적함수가 `0.5·log_var`로 축약되어 최소값이 `log_var → -∞`다. 그래서 네 슬롯 모두
하한 경계에 붙었다. 버그 run의 `best.pt`(step 131,000)도 같은 구조였다
(`tension_var log_var = -39.87` = 발산 흔적).

### 2-3. 진짜 원인 ② — 크기 래칫 (one-sided magnitude ratchet)

`tension = (ffn_out**2).mean`이므로 분산은 크기의 제곱으로 커진다. `-log(t_var)`는
**패턴이 아니라 크기**를 부풀리는 것으로도 보상되고, pre-norm 구조에서 그 방향은
CE에 거의 무료다. NF4 클램프는 이 그래디언트를 **한쪽으로만** 만든다(상한 위에선
0, 아래에선 항상 위로). 결과:

```
tension │                              ╭── 163,069
        │                        ╭────╯
        │              ╭────────╯
        │  ────────────╯ 46          (옛 버그 run: 43~58 유지)
        └──────────────────────────────── step 60k → 72k
val CE  │ 4.8435 ●────●────●────●   개선 정지 (같은 구간)
```
`tension_proj`가 이 O(100) 크기 신호를 토큰 정보가 O(1~10)인 잔차 흐름에 주입하므로,
의식 신호가 언어 정보를 덮어쓴다.

### 2-4. 부수 확정 — 판정 기준 자체가 잡음이었다

검증 평가는 `get_batch(val_data, min(batch,32)=4, block=256)` = **1,024바이트 랜덤 1개**다.
사전 등록했던 4.7634 vs 4.8435(0.08 nat) 차이는 이 측정의 잡음 안이다. 기준을
"최저값"으로 잡은 것도 선택 편향이다.

### 2-5. 부수 확정 — 6.87 BPC는 데이터 한계가 아니다

4.76 nats = 6.87 BPC. 바이트 빈도표(order-0)가 대략 4.2~5.0 BPC이므로 **유니그램보다
나쁘다**. 두 모델 모두 건강한 300M/896d라면 1.5~3 BPC를 기대한다고 판단했다.
언어 진입 시점 CE = 5.6456 ≈ `ln(256) = 5.545` — **분화 페이즈 60,000 step 동안
트랜스포머는 아무것도 배우지 않았다**(구조 손실들이 파이썬 실수→텐서라 모델
파라미터로 가는 그래디언트가 없고, 텐션 항은 클램프 포화 상태였다).

if i < self.N_LEARNABLE:

## 4. 핵심 발견 / 법칙

> **정규화 항에 학습가능 가중치를 주면, 최적화기는 과제를 푸는 대신 저울추를 옮긴다.**
> Kendall 가중은 우도 기반 비음수 손실에만 유효하다. 그리고 **크기로 보상되는 형태
> (분산·에너지)는 반드시 척도 불변으로 정규화하라** — 그렇지 않으면 pre-norm 아래에서
> "활성값 부풀리기"라는 공짜 방향이 항상 남는다.

진단 신호: 손실이 잘 내려가는데 검증만 정체 → 저울추를 읽어라(체크포인트의 `log_vars`).
내부 상태량이 3자릿수 이상 단조 증가 → 크기 래칫을 의심하라.

## 4-b. 후속 — 꺼진 슬롯의 저울추 표류 (커밋 9a133a9aa)

수정본 run을 지켜보다 **같은 뿌리의 세 번째 구멍**을 찾았다. 분화 페이즈에서 구조 항은
전부 0 이상인데 복합손실이 1.6895 → -0.5998로 내려갔다(3,300 step). 음수가 나올 수
있는 자리는 하나뿐이다 — 꺼져 있는 CE 슬롯이다.

```
CE 슬롯 기여 (L=0 이면 Kendall 항이 0.5*log_var 로 축약)
  log_var  0.0 → 두 슬롯 합  0.00
  log_var -2.0 → 두 슬롯 합 -2.00   precision e² = 7.4
  log_var -3.0 → 두 슬롯 합 -3.00   precision e³ = 20.1  ◀ 언어 진입 시 CE 그래디언트 20배
관측 Δ = -2.29 (3,300 step) · exp(-CV²)는 최대 1.0 하강 → 나머지는 저울추 표류
```

CE가 **돌지도 않는** 60,000 step 동안 그 가중치가 클램프까지 걸어가고, 언어 학습이
시작되는 바로 그 step에 20배 그래디언트 급증으로 진입한다. 수정: 꺼진 슬롯은 복합손실에
기여도, 가중치 누적도 하지 않고 건너뛴다.

```
                       수정 전        수정 후
분화 total (구조 1.6806)  -1.3194       +1.6806   (표류 기여 0)
언어 진입 CE 배율          20.1x         1.0x → Kendall 최적 ln(2L)=2.10 로 수렴
```

## 5. 검증 상태 (정직한 기록)

- **확정**: 저울추 실측(체크포인트 2개), 텐션 항 바닥 계산 = 실측 일치, 새 손실 형식의
  척도 불변·포화 성질(수치 검증), 검증 평가 1,024바이트(코드), 진입 CE ≈ ln 256(로그).
- **미확정**: 이 수정이 실제로 CE를 낮추는지. NF-1+NF-2+NF-3 반영본으로 step 0부터
  재시작했다(`checkpoints/clm_pure_300m_nf3`). 초기 신호는 좋다 — 분화 페이즈 손실이
  1.6894 → 0.6076으로 **실제로 하강**한다(이전 run은 같은 구간에서 -38.28 고정 = 학습
  신호 0). 감시자가 세포 성장 실패·텐션 래칫 재발·언어 페이즈 CE를 자동 판정한다.
- **폐기**: fix2 run(step 74,700에서 중단). 사전 등록 기준이 잡음이었고 목적함수가
  CE를 47배 누른 상태였으므로 123,000까지 가도 답이 나오지 않는다. 체크포인트는 보존.
- **미해결 설계 질문**: 분화 페이즈(30%)는 NF-3 이후 텐션 항 하나만 실제 그래디언트를
  준다. 이 페이즈를 유지할지 단축할지는 별도 실험이 필요하다(TALK5 가설과 충돌 검증).
- **반대 의견 기록(sol)**: 목표대역 페널티 `(log t_var - log t_target)²`를 선호했고
  fix2 계속 진행(123k)을 권고했다. 대역 상수는 사람이 정한 텐션 설정점이라 프로젝트
  2원칙(조작 금지)에 걸려 채택하지 않았고, 계속 진행은 §2-4(판정 기준=잡음)와
  §2-2(CE 47배 핸디캡) 때문에 기각했다.
