# KEY-REFRESH-1 — 질문 열쇠 상태 새로 고침

상태: 사전등록, 결과 미확인

## 배경

`QUERY-REFRESH-2`는 질문 상황 처리 횟수를 6회에서 8회로 늘려 상황 25% 손상 행동을
`94.82~95.31%`로 회복했다. 그러나 열쇠 25% 손상은 `89.94~90.53%`, 상황과 열쇠를 함께
25% 손상한 조건은 `88.57~89.26%`로 등록 기준 90%에 못 미쳤다.

실제 공용 흐름의 `trace_episode()`는 저장할 때의 열쇠와 질문할 때의 열쇠를 모두
`key_sense_steps=3`으로 처리한다. 앞선 상황 경로와 같은 종류의 처리 시간 병목인지 확인하려면
저장 자료와 상황 경로는 고정하고 질문 열쇠의 처리 횟수만 분리해야 한다.

## 가설

질문 열쇠 상태를 3회에 너무 일찍 읽은 것이 남은 부분 단서 손실의 원인이라면, 질문 열쇠만 더
처리했을 때 열쇠 손상과 양쪽 손상 행동이 모든 독립 엔진에서 회복되고 이후 후보에서도 유지될
것이다.

## 고정 조건

- 자료: `QUERY-REFRESH-2`와 같은 1,024개 독립 사건
- 독립 실행: 같은 `prototype_seed × engine_seed` 네 조합
- 저장 상황 처리: 6회
- 질문 상황 처리: 검증된 8회
- 저장 열쇠 처리: 3회
- 질문 열쇠 후보: `3, 4, 6, 8, 12회`
- 값·방해 입력 처리, 사건 순서, 시작값, 25% 손상 위치, 얼린 상황·열쇠·값 판독기,
  `VectorMemory`, 상황 중심 주소는 모두 그대로 유지
- 각 후보는 같은 사건 시작값에서 독립적으로 전체 경로를 다시 실행
- 결과를 본 뒤 후보, 문턱, 판독기, 주소 폭 또는 학습 자료를 바꾸지 않음

공용 `trace_episode()`에는 `query_key_sense_steps`를 선택 항목으로 추가한다. 지정하지 않은 기존
호출은 `key_sense_steps`를 그대로 사용해야 하며, 저장 열쇠 지문은 후보 사이에서 같아야 한다.

## 유효성 기준

모든 후보와 독립 실행에서 다음을 만족해야 한다.

- 온전한 입력의 기억 선택·최종 행동 90% 이상, 값별 최저 맞힘률 75% 이상
- 정확한 상황+열쇠 주소 비교의 선택 99% 이상, 최종 행동 90% 이상
- 저장 내용을 맞바꾼 비교의 최종 행동 5% 이하
- 공용 기억 API 결과 일치 100%
- 얼린 판독기 가중치 불변
- 자료·정답·저장 상황·저장 열쇠·저장 값 지문 불변
- 등록된 저장/질문 처리 호출 횟수와 실제 감사값 일치
- 3회 조건이 `QUERY-REFRESH-2`의 8회 상황 결과를 예측·선택·진단·상태 지문까지 재현

하나라도 어기면 `KRF0_INVALID`다.

## 회복 기준과 닫힌 판정

열쇠 손상과 양쪽 손상 각각에서 기억 선택·최종 행동이 90% 이상이어야 회복으로 센다. 최초
회복 후보 이후의 모든 더 긴 후보에서도 두 조건이 계속 통과해야 `지속 회복`이다. 또한 3회
기준에서 양쪽 손상이 90% 미만이고, 최초 지속 회복 후보의 양쪽 손상 최종 행동이 모든 독립
엔진에서 최소 1%p 올라야 원인성이 성립한다.

- `KRF1_KEY_PATH_RECOVERED_AND_SUSTAINED`: 두 손상 조건이 지속 회복하고 원인성도 성립
- `KRF2_RECOVERED_NOT_SUSTAINED`: 한 후보에서는 회복하지만 뒤의 후보에서 다시 실패
- `KRF3_IMPROVED_NOT_RECOVERED`: 모든 독립 엔진에서 1%p 이상 개선되지만 지속 회복하지 못함
- `KRF4_KEY_REFRESH_NOT_CAUSAL`: 위 조건을 만족하는 개선이 없음
- `KRF0_INVALID`: 유효성 기준 실패

공용 기본 처리 횟수는 `KRF1`일 때만 후속 `KEY-REFRESH-2`에서 선택적으로 연결한다. 이 실험은
기억 검색의 처리 시간을 검사하며 생물학적 기억이나 의식의 증거가 아니다.
