# GATE-RETRIEVAL-CONTROL-1 — 문장 의미 검색 양성 비교

상태: 완료 · `GRC0_INVALID`
등록일: 2026-08-12

## 질문과 범위

`GATE-2`는 다양한 대화에서 중요한 문장을 고르는 검사를 수행했지만, seed `7331`에서 모든 문장을
저장한 비교조차 후속 질문 정답률 85.94%에 머물렀다. 정답 문장만 남기면 100%였으므로 첫 실패
구간은 저장 선택보다 뒤의 기존 글자 3개 묶음 검색 순위다.

이번 검사는 저장 선택을 완전히 제외하고, 같은 고정 문장 의미 표현으로 질문과 후보를 비교하면
양성 검색 경로가 성립하는지만 묻는다. 일반 문장 검색 검사이며 Anima 고유 기능, 주관적 이해 또는
의식을 검사하지 않는다. 실제 사용자 대화와 공용 기억 기본값도 변경하지 않는다.

## 고정 자료와 표현

- `GATE-2`와 같은 seed `1337`, `7331`, 평가 1,024회차를 그대로 생성한다.
- 회차마다 사실 한 문장과 방해 문장 일곱 개, 후속 질문 하나를 사용한다.
- 사실 종류는 선호·약속·목표·사용자 정보이며 위치는 `1·3·5·7`번째에 같은 수로 배치한다.
- 회차당 세 번의 주제 이동, 문장 순서, 문장 틀, 임시 식별 문자열과 자료 지문을 바꾸지 않는다.
- 모든 후보를 저장한 것으로 보고 검색 상위 3개 안에 사실 문장이 있는지를 센다.
- `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` revision
  `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`를 사용한다.
- 최대 128토큰, attention mask 평균, L2 정규화, CPU 실행을 유지한다. 질문과 후보의 384차원 문장
  표현 사이 코사인 유사도를 사용하며 대화 역할 2차원은 검색 거리에 넣지 않는다.
- Python 3.13, `torch==2.8.0`, `transformers==4.55.4`를 사용한다.
- 유사도가 같으면 앞선 후보를 먼저 고르는 고정 순서를 사용한다.

## 고정 비교

- `semantic_retrieval`: 고정 문장 의미 표현으로 모든 후보 검색
- `character_retrieval`: `GATE-2`의 기존 글자 3개 묶음 검색
- `oracle_memory`: 정답 사실만 검색 목록에 둔 양성 비교
- `shuffled_query`: 각 질문을 같은 seed의 다른 회차 후보와 결정적으로 맞바꾼 가짜 비교
- `no_memory`: 검색 후보가 없는 정보 없음 비교

질문 맞바꾸기는 원래 회차를 고정된 한 칸 순환해 자기 회차와 겹치지 않게 한다. 각 조건은 전체
정답률, 사실 종류별·위치별 정답률, 정답 사실의 순위와 상위 오답 대비 거리, 결과 지문을 기록한다.
자료·모델·환경·지문·유한값·결정성이 하나라도 다르면 닫힌 판정기가 결과를 무효로 처리한다.

## 사전 판정

두 seed 모두 다음 조건을 만족해야 한다.

- `semantic_retrieval` 전체 정답률 95% 이상
- 사실 네 종류별 정답률 각각 90% 이상
- 사실 위치 `1·3·5·7`별 정답률 각각 90% 이상
- `oracle_memory` 99% 이상
- `shuffled_query` 25% 이하, `no_memory` 5% 이하
- 의미 검색이 가짜 질문보다 50%p 이상 높음
- 의미 검색이 기존 글자 검색보다 5%p 넘게 낮지 않음

판정은 다음과 같다.

- `GRC1_SEMANTIC_RETRIEVAL_VALID`: 모든 통제와 두 seed의 전체·종류·위치 기준 통과
- `GRC2_SEMANTIC_RETRIEVAL_LOSS`: 통제는 유효하지만 의미 검색의 전체·종류·위치 기준 중 하나 미달
- `GRC0_INVALID`: 자료·모델·환경·지문·결정성·양성·가짜·정보 없음 비교 중 하나라도 무효

`GRC1`이면 같은 검색 표현을 사용해 기존 `GATE-2`의 저장 선택 결과를 별도 사전등록 후 다시
판정한다. `GRC2`이면 결과를 보고 검색 상위 수, 문장, 모델 또는 기준을 조정하지 않고 처음 무너진
사실 종류·위치만 후속 검사한다. 어떤 결과에서도 실제 대화 저장 기본값과 원문 보존 방식은 바꾸지
않는다.

결과를 보기 전에 README와 이 문서를 GitHub `main`에 먼저 고정하고 그 커밋을 실행 사양의
`preregistration_commit`으로 사용한다.

## 실행 결과

사전등록은 GitHub `main`의 `b9bd07c6a`에 고정했다. 등록한 Python 3.13.13, PyTorch 2.8.0,
Transformers 4.55.4 CPU 환경에서 두 자료를 실행했다. 각 자료는 평가 1,024회차·8,192문장과
질문 1,024개로 구성됐고, 원문·질문 중복 0, 사실 네 종류와 위치 네 곳 각 256회, 회차당 주제 이동
3회를 모두 확인했다.

| 조건 | seed 1337 후속 질문 | seed 7331 후속 질문 |
|---|---:|---:|
| 전체 문장 의미 검색 | 19.92% | 2.34% |
| 기존 글자 3개 묶음 검색 | 99.61% | 85.94% |
| 정답 사실만 남긴 검색 | 100% | 100% |
| 다른 회차 질문으로 의미 검색 | 22.36% | 2.15% |
| 기억 없음 | 0% | 0% |

의미 검색의 사실 종류별 최저 정답률은 두 자료 모두 0%였고, 위치별 최저 정답률은
`17.97% / 1.95%`였다. 정답 사실의 평균 순위도 `6.08 / 7.55`위로 상위 3개 밖이었다. 반면 기존
글자 검색과 정답만 남긴 비교는 같은 자료에서 훨씬 높았으므로 사실 문장, 질문 정답, 자료 생성이
깨진 것은 아니다.

## 판정과 다음 단계

사전 판정은 `GRC0_INVALID`다. 의미 검색이 등록한 전체·종류·위치 기준에 크게 못 미쳤을 뿐 아니라,
다른 회차 질문보다 50%p 높아야 한다는 가짜 비교 격차도 실패했다. 따라서 이 결과로 `GATE-2`의
저장 선택을 다시 판정하지 않고 실제 대화 검색 기본값도 변경하지 않는다.

결과가 가리키는 첫 실패 구간은 “전체 문장 하나를 검색 주소로 사용하는 방식”이다. 고정 문장 의미
표현은 선호·약속 같은 일반 뜻에는 민감하지만, 이번 회차의 임시 주제 문자열을 해당 사실과 안정적으로
묶지 못했다는 해석이 가장 잘 맞는다. 다음은 이미 공용 기억에서 검증한 열쇠와 내용을 분리하는
방식을 재사용해, 주제 주소로 후보를 찾고 문장 의미로 순위를 정하는
`GATE-RETRIEVAL-CONTROL-2`다. 결과를 보고 이번 모델, 상위 3개, 문장 또는 기준을 조정하지 않았다.

최종 결과 JSON SHA-256은
`24e9bab29ae9901c7034e7d4848be86629ea3a6714b6f16ccf80609f4ad1f65c`, 판정 JSON은
`274fce882bb782787194bd4c4e63a34a151d86a6ffb8468dfcb9f1dd8d3b1795`다. 독립 전체 재실행은
결과와 판정이 바이트 단위로 같았다. HF 조직 보관소의
`gate-retrieval-control1-semantic-retrieval` revision에 결과·판정·manifest를 커밋
`b648a59b93a2bbe15f089a76486059555cc56ae3`으로 올렸다. 새 임시 폴더로 다시 내려받아 manifest
두 항목을 전수 확인했으며 manifest SHA-256은
`44f20aa714fd12b9d3e8854eb41089f657e509d43c2020b9153770de0afad40f`다. 로컬 CPU에서만
실행했으며 실제 대화 런타임은 변경하지 않았다.
