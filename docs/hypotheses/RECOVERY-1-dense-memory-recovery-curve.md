# RECOVERY-1 — 기억 주소의 촘촘한 회복 곡선

상태: 완료 — `RC1_ORDERED_RECOVERY_REPRODUCED`
등록일: 2026-08-10  
선행 결과: `DECAY-1=D5_NON_MONOTONIC_OR_MIXED`

## 질문

`DECAY-1`에서 저장 후보 세 개의 최종 정확도는 방해 입력 0개에서 `84.0% / 86.7%`였지만,
4개에서 `91.1% / 92.8%`, 8개에서 `93.0% / 95.3%`로 회복했다. 2개에서는 seed 경계가
갈렸고 측정점도 `0 / 2 / 4 / 8`뿐이어서, 순서 있는 회복인지 한 자료 묶음의 우연한 흔들림인지
아직 구분할 수 없다.

이번 검사는 새 기억 구조를 만들지 않는다. `DECAY-1`의 얼린 폭 32 주소 변환, 기존
`VectorMemory`, 감각 순서와 값 상태 판독을 그대로 사용한다. 새 독립 자료에서 정답 주소가 세
후보 중 어떻게 이동하는지 촘촘히 기록해 앞선 회복 모양의 재현 여부만 판정한다.

## 고정 실행 흐름

- seed: `1337 / 7331`
- 독립 자료 묶음: `3`
- 묶음별 평가 회차: `512`, 시간점별 총 `1,536`
- 준비·저장 사건: `3`, 질문 대상은 첫 두 사건
- 열쇠·값·상황 종류: 각각 `8`
- 질문 전 방해 입력: `0 / 1 / 2 / 3 / 4 / 5 / 6 / 7 / 8`
- 주소 변환: `KEY-1` seed별 폭 32 얼린 선형 변환
- 기억: 기존 `VectorMemory`, cosine top-1
- 상태 특징 폭·감각 단계·값 원형: `DECAY-1`과 동일
- 셀 수: 등록 범위 `2~48`, 주소 입력은 기존 셀 평균
- 장치: CPU

각 자료 묶음은 목표 값·질문 위치·질문 열쇠·질문 상황이 정확히 균형이고 지문이 서로 겹치지
않는다. 같은 seed·자료 묶음·회차는 아홉 시간점에서 같은 엔진 초기 난수를 사용한다. 자료 묶음
사이에는 자료 생성 난수와 엔진 초기 난수가 모두 겹치지 않는다.

## 기록값

각 seed·자료 묶음·시간점에서 다음을 기록한다.

- 최종 행동 정확도와 값별 재현율
- 올바른 저장 위치 선택 정확도와 선택 위치 혼동표
- 정답 주소의 `1 / 2 / 3위` 횟수
- 정답 주소, 가장 강한 오답 주소, 세 번째 사건 주소의 평균 cosine 유사도
- `정답 - 가장 강한 오답`, `정답 - 세 번째 사건` 평균 여유
- 기억 API와 직접 cosine top-1 선택의 일치율
- 주소 변환 호출 수·폭, 셀 수, 초기 난수 지문

자료 묶음별 수치와 세 묶음을 합친 수치를 모두 저장한다. 합친 수치만 좋아지고 개별 묶음의
방향이 갈리는 일을 숨기지 않는다.

## 비교와 통제

각 시간점에서 아래 네 조건을 같은 내부 상태로 계산한다.

1. `stable_three_candidates`: 얼린 안정 주소와 저장 후보 세 개
2. `stable_two_candidates`: 같은 첫 두 사건만 저장하는 양성 비교
3. `exact_three_candidates`: 정확한 원-핫 주소 세 개
4. `exact_three_partner_swap`: 정확 주소의 내용을 한 칸 돌린 가짜 비교
5. `exact_three_recovered`: 정상 연결을 새 기억에 다시 저장한 복구 비교

두 후보 양성 비교는 모든 시간점에서 두 seed의 합친 최종 정확도·선택 정확도 90% 이상이어야
한다. 정확 주소는 모든 seed·묶음·시간점에서 선택 99%, 최종 정확도 90%, 값별 최저 재현율 75%
이상이어야 한다. 내용 맞바꾸기는 5% 이하, 복구 예측과 기억 API 일치는 100%여야 한다.

## 조건 통과와 회복 기준

세 후보 안정 주소의 한 시간점은 seed별로 세 묶음을 합친 값이 아래를 모두 만족할 때 통과한다.

- 저장 위치 선택 정확도 90% 이상
- 최종 정확도 90% 이상
- 값별 최저 재현율 75% 이상
- 올바른 저장 내용의 값 판독 정확도 90% 이상

순서 있는 회복은 seed별로 다음을 모두 만족해야 한다.

1. 0단계는 실패하고 8단계는 통과한다.
2. 8단계 최종 정확도와 선택 정확도가 0단계보다 각각 `5%p` 이상 높다.
3. 합친 결과가 처음 통과한 뒤 더 긴 시간점에서 다시 실패하지 않는다.
4. 세 독립 자료 묶음 각각에서 8단계 최종 정확도와 선택 정확도가 0단계보다 높다.

두 seed의 첫 통과 시간 차이는 원인 확정 조건으로 쓰지 않고 그대로 보고한다.

## 사전 판정

- `RC1_ORDERED_RECOVERY_REPRODUCED`: 두 seed가 위 순서 있는 회복 기준을 모두 만족
- `RC2_RECOVERY_REPRODUCED_MIXED`: 두 seed 모두 0단계 실패·8단계 통과와 `5%p` 개선을
  보이지만 중간에 재실패하거나 독립 자료 묶음의 방향이 하나 이상 갈림
- `RC3_RECOVERY_NOT_REPRODUCED`: 통제는 유효하지만 두 seed의 0단계 실패→8단계 통과 모양이
  반복되지 않음
- `RC4_DELAY_LOSS`: 0단계에서 통과한 seed가 더 긴 시간점에서 실패하며 8단계까지 회복하지 않음
- `RC0_INVALID`: 원본·지문·얼림·자료 독립성·양성 비교·가짜 비교·복구 조건 중 하나라도 무효

판정 우선순위는 `RC0 → RC4 → RC1 → RC2 → RC3`이다. `RC1` 또는 `RC2`여도 기다리는
단계를 기억 기능으로 추가하지 않는다. 정답과 오답 주소의 유사도 이동이 어느 후보에서 생기는지
확인한 뒤 최소 원인을 따로 사전등록한다. `RC3`이면 `DECAY-1`의 회복 관찰은 일반 경계로 쓰지
않고 현재 검증 용량을 사건 두 개로 유지한다.

결과를 본 뒤 시간점·자료 묶음 수·회차 수·문턱·seed·주소 가중치를 조정하지 않는다. 구현의
단일 기준 파일은 `measurement/recovery_registry.py`이며, 그 파일의 `preregistration_commit`은
README와 이 문서를 먼저 고정한 Git 커밋을 가리켜야 한다.

## 실행 후 판정기 정밀도 수리

구현 고정 커밋 `1357f59c1`로 전체 계산을 끝낸 뒤, 판정기가 seed 1337의 방해 입력 1개 조건을
`pooled result does not match replicates`로 차단했다. 원인은 합친 정확도를 `torch.float32` 평균으로
계산한 `0.8645833135`와 같은 정답 수에서 나온 세 자료 묶음의 Python 평균 `0.8645833333`을
절대 허용오차 `1e-9`로 비교한 것이다. 차이는 약 `1.99e-8`이며 정답 수·혼동표·실험 자료의
불일치가 아니다.

최초 산출물은 `measurement/recovery_invalid_precision_results.json`과
`measurement/recovery_invalid_precision_verdict.json`에 원형 보존한다. 수리는 합친 값과 묶음별
값의 동일성 검사 허용오차만 `1e-7`로 바꾼다. 등록된 자료·시간점·seed·주소 가중치·과학 판정
문턱은 바꾸지 않고, 계산된 결과 JSON도 다시 만들지 않는다. 이 수리 등록 커밋 뒤 판정기 자동
검사와 기존 결과 재판정을 먼저 통과해야 연구 결과를 해석한다.

## 결과

정밀도 수리 뒤 기존 결과 JSON의 SHA-256은 최초 무효 판정 때와 같은
`9b456430ea894c13d2b9f33b3a60837e902a0ba31bfde17b0dbb2ef35fe6a73f`였다. 즉 판정기만
수리했고 실험 결과는 다시 만들거나 바꾸지 않았다.

아래 값은 세 독립 자료 묶음 1,536회차를 합친 최종 행동 정확도다. 괄호는 올바른 저장 위치를
고른 비율이다.

| 방해 입력 | seed 1337 | seed 7331 |
|---:|---:|---:|
| 0 | 85.2% (85.2%) | 88.1% (88.5%) |
| 1 | 86.5% (86.6%) | 89.6% (90.2%) |
| 2 | 88.4% (88.6%) | 91.2% (91.8%) |
| 3 | 90.8% (91.0%) | 92.7% (93.3%) |
| 4 | 92.1% (92.4%) | 93.2% (93.8%) |
| 5 | 93.1% (93.4%) | 93.8% (94.4%) |
| 6 | 93.4% (93.7%) | 94.4% (95.0%) |
| 7 | 93.4% (93.8%) | 94.9% (95.4%) |
| 8 | 93.7% (94.1%) | 95.2% (95.8%) |

seed 1337은 방해 입력 3개에서, seed 7331은 2개에서 처음 등록 문턱을 통과했고 이후 다시
실패하지 않았다. 0→8단계 최종 정확도는 `+8.53%p / +7.10%p`, 주소 선택은
`+8.92%p / +7.23%p` 개선됐다. 각 seed의 세 자료 묶음을 따로 봐도 최종 정확도와 주소 선택이
모두 같은 방향으로 개선됐다. 묶음별 최종 정확도 개선 범위는 seed 1337 `+7.23~9.77%p`, seed
7331 `+5.47~8.01%p`였다.

정답 주소와 가장 강한 오답 주소의 평균 cosine 여유는 seed 1337에서 `0.284→0.420`, seed
7331에서 `0.360→0.516`으로 시간점마다 커졌다. 정답 주소가 1위인 회차도 각각
`1,308→1,445 / 1,360→1,471`로 늘었다. 따라서 최종 행동만 우연히 좋아진 것이 아니라,
질문 주소가 세 저장 후보를 구분하는 모양 자체가 같은 방향으로 바뀌었다.

두 후보 양성 비교는 모든 시간점에서 `98.3~99.6%`였고 등록 문턱을 통과했다. 각 자료 묶음의
정확 주소 정상 팔은 `99.0~100%`, 내용 맞바꾸기는 `2.0~3.9%`, 복구는 정상과 100% 일치했다.
기억 API와 직접 cosine 선택, 주소 폭 32, 얼린 가중치, 시간점별 초기 난수 지문도 전부
일치했다.

## 판정과 해석

두 seed 모두 0단계 실패, 8단계 통과, 5%p 이상 개선, 통과 뒤 재실패 없음, 세 독립 자료 묶음의
같은 개선 방향을 만족했다. 최종 판정은 `RC1_ORDERED_RECOVERY_REPRODUCED`다.

이 결과는 현재 안정 주소가 사건 세 개를 즉시 찾을 때 충돌하지만, 몇 번의 추가 감각 처리 뒤에는
정답 주소와 오답 주소 사이가 벌어진다는 뜻이다. 기억 내용이 새로 생겼거나 용량이 늘었다는 뜻은
아니다. 두 후보 정확도는 시간이 길수록 약간 낮아졌으므로, 기다림이 모든 기억을 일반적으로
개선한다고도 해석하지 않는다. 의식의 증거도 아니다.

다음은 `RESET-1`이다. 같은 내부 갱신 횟수에서 `새 방해 단어 / 같은 중립 단어 반복 / 의미 입력
없는 내부 갱신`을 분리해, 회복이 단순한 상태 안정화인지 새 감각이 앞선 후보 충돌을 씻어내는
효과인지 확인한다. 이 분리 전에는 지연이나 방해 입력을 기억 기능으로 고정하지 않는다.

최종 결과·판정·최초 정밀도 무효본과 manifest는 비공개 HF 조직 보관소
`dancinlab/anima-lab-research-archive`의 `recovery1-dense-curve` revision에 보존했다. Hugging Face
커밋은 `c4e7579b00864c0c66f72fb16c5d5f4b8837ff16`이며, 원격의 다섯 항목을 새 임시 폴더에
다시 내려받아 네 산출물의 SHA-256을 전수 확인했다.
