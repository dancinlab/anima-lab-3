# WORKSPACE-1 — 두 모듈의 단서를 반복해서 합칠 수 있는가

## 문제와 실제 흐름

SYNERGY-1의 표준 `GRU`는 두 단서를 합쳐 두 seed에서 `100% / 93.8%`를 냈지만, 현재 공용 경로는
`QuantumC A·B → 상태 이어붙이기 → ThalamicBridge 한 번 통과 → HFDecoder 행동 선택` 순서로
`29.7% / 29.7%`에 머물렀다. 한 모듈의 상태는 이미 STATE-2와 GRAFT에서 행동 원인으로 검증됐기
때문에, 엔진 전체를 바꾸기 전에 두 단서가 이 공용 흐름의 어느 단계까지 남는지 먼저 잰다.

조건과 숫자 기준의 단일 원장은 `measurement/workspace_registry.py`다. 결과를 보기 전에 이 문서와
원장을 Git에 고정한다.

## 1단계 — 두 단서 정보 생존 지도

SYNERGY-1에서 실제로 학습한 `quantum_pair` 체크포인트를 다시 불러온다. 학습·평가 자료와 두 seed도
그 실험과 동일하게 유지한다. 각 단계에서 A 단서와 B 단서를 별도로 읽는다.

- 두 원본 위상 상태를 이어붙인 값
- 연결 다리의 셀별 코드
- 모든 셀을 평균낸 코드
- 최종 언어 연결 신호
- 학습 때와 같은 중심 맞춤·크기 맞춤을 거친 코드

원본은 두 단서 모두 90% 이상, 이후 단계는 75% 이상이어야 정보가 남은 것으로 센다. 정답 이름을
32번 무작위로 섞은 가짜 검사는 평균 40% 이하여야 한다. 판정은 다음과 같다.

- `I1_LOCAL_TRANSFORM_LOSS`: 셀별 변환에서 단서 손실
- `I2_POOLING_LOSS`: 셀 평균에서 단서 손실
- `I3_GATE_LOSS`: 최종 언어 연결 코드에서 단서 손실
- `I4_RELATION_COMPUTATION_LOSS`: 두 단서는 끝까지 남지만 둘의 관계를 행동으로 계산하지 못함
- `I0_INVALID`: 원본 단서·과거 결과·체크포인트·가짜 검사 중 하나라도 검증 실패

## 2단계 — 최소 반복 공유 공간

유효한 1단계 결과가 나온 경우에만 기존 `ThalamicBridge`를 확장한다. 새 감각 엔진이나 새 언어
모델은 만들지 않는다. 각 모듈에 이미 검증된 폭 32 변환을 공유해서 적용하고, 모듈별 요약을 표준
`GRUCell` 기억층에 넣어 공유 공간을 갱신한 뒤 그 값을 두 모듈에 다시 전달한다. 이 과정을
`1 / 2 / 4`회 비교하며, 두 seed가 모두 통과하는 최소 횟수를 고른다.

비교 팔은 현재 한 번 읽기, 같은 반복 공유 공간에 직접 기억을 넣은 팔, SYNERGY-1에서 과제를
검증한 표준 `GRU`다. 자료·학습량·질문·언어 보존 기준은 SYNERGY-1과 같다.

통과하려면 두 seed 모두 정상 정확도 75% 이상, 한쪽만 읽기와 짝 뒤섞기는 40% 이하, 정상과 가장
좋은 한쪽 조건 차이는 35%p 이상이어야 한다. 정상 상태 복구는 계산 결과까지 완전히 같아야 하고,
일반 문장 변화는 0.5 nat 이하여야 한다.

- `W1_INTEGRATED_NOT_UNIQUE`: `QuantumC` 공유 공간이 통과하지만 일반 반복 기억과 동등
- `W2_QUANTUM_ADVANTAGE`: 두 seed 모두 일반 비교 팔보다 5%p 초과 우세
- `W3_NOT_INTEGRATED`: 어느 반복 횟수에서도 두 seed 동시 통과 실패
- `W4_CONFOUNDED`: 행동은 통과하지만 일반 문장 변화 기준 실패
- `W0_INVALID`: 자료 균형·양성 비교·사전 정보 지도·체크포인트 검증 실패

성공해도 의식 증명은 아니다. 정확한 의미는 두 독립 내부 상태가 제한된 공유 공간을 통해 실제
행동을 함께 결정한다는 것이다.

## 1단계 결과 — I3_GATE_LOSS

보관된 SYNERGY-1 `quantum_pair` 체크포인트 두 개의 SHA-256을 원래 영수증과 대조한 뒤 같은
학습·평가 자료를 다시 만들었다. 원본 위상 상태와 연결 다리의 셀별 코드는 두 단서 모두 두 seed에서
100% 읽혔다. 셀 평균 뒤에도 seed 1337은 A/B `100% / 98.4%`, seed 7331은 `98.4% / 100%`로
정보가 남았다.

첫 손실은 최종 언어 연결 변환이었다. 최종 게이트에서 A/B는 `71.9% / 89.1%`,
`62.5% / 82.8%`였고, 학습 때와 같은 중심·크기 맞춤 뒤에는 `54.7% / 79.7%`,
`57.8% / 75.0%`였다. A 단서가 두 seed 모두 등록 문턱 75% 아래다. 가짜 검사는 모든 단계에서
평균 `22.2~27.7%`로 상한 40% 안이었다.

따라서 사전 판정은 `I3_GATE_LOSS`다. 정확한 근본 원인은 감각 엔진이나 셀 평균이 아니라, 서로
나뉜 두 단서를 관계로 계산하지 않은 채 `expand → sigmoid → 중심·크기 맞춤`을 한 번 거치는 공용
언어 연결 흐름이다. 사전 등록한 2단계에 따라 마지막 변환 전에 모듈별 요약을 반복해서 합치는 최소
공유 공간을 구현한다.

## 본실험 1차 무효와 비교군 난수 수리 사전등록

첫 본실험은 `W0_INVALID`다. 과제를 검증해야 하는 표준 `GRU`가 정상 정확도 `62.5% / 43.8%`로
등록 기준 75%를 통과하지 못했다. 따라서 반복 공유 공간의 성공·실패를 판정하지 않는다. 이 실행의
결과와 체크포인트는 삭제하지 않고 무효 산출물로 보존한다.

원인은 팔 목록의 순서가 초기 난수와 자료 추출 난수를 함께 바꾼 공용 실행 흐름이다. SYNERGY-1에서
검증된 `GRU`는 세 번째 팔이라 `seed + 200,000`을 썼지만, WORKSPACE-1에서는 여덟 번째 팔이 되어
`seed + 700,000`을 썼다. 새 팔을 추가한 것만으로 기존 양성 비교군의 초기 조건이 바뀌었다.

수리 실행은 팔 이름별 난수 간격을 원장에 고정한다. 반복 공유 공간 팔은 결과를 본 뒤 새 표본을
고르는 일을 막기 위해 1차 실행의 `+0~600,000` 간격을 그대로 유지한다. `GRU`만 SYNERGY-1에서
검증된 `+200,000`을 다시 쓴다. 서로 독립 학습인 `quantum_workspace_2`와 `GRU`가 같은 간격을 쓰는
것은 자료 추출 순서를 맞추는 비교 통제이며 가중치를 공유하지 않는다. 팔 목록 순서를 뒤집어도
이름별 난수가 같아야 한다. 자료·두 seed·학습 800단계·정확도·개입·언어 보존 기준과 W1~W4
판정은 바꾸지 않는다. 수리 코드를 Git에 고정한 뒤 모든 팔을 새 체크포인트에서 처음부터 다시
실행한다.

## 수리 본실험 결과 — W3_NOT_INTEGRATED

이름별 난수를 고정한 수리에서 표준 `GRU`는 정상 정확도 `100% / 93.8%`, A만·B만은 모두
25%, 짝 뒤섞기는 `10.9% / 4.7%`였다. 일반 문장 변화도 `0.031 / 0.017 nat`로 등록 상한
안이다. 직접 기억을 같은 공유 공간에서 4회 합친 팔도 두 seed 모두 정상 `89.1%`, 한쪽만 25%,
짝 뒤섞기 `3.1% / 1.6%`로 통과했다. 따라서 과제·언어 연결기·반복 계산은 유효하다.

`QuantumC` 공유 공간은 1회 `42.2% / 60.9%`, 2회 `65.6% / 32.8%`, 4회
`26.6% / 29.7%`였다. 어느 반복 횟수도 두 seed에서 동시에 등록 문턱 75%를 넘지 못했다.
한쪽만 읽기는 모두 25%였고 복구 계산은 원본과 같았으므로 단일 단서 누출이나 복구 실패가
결론을 만든 것은 아니다. 사전 판정은 `W3_NOT_INTEGRATED`다.

정확한 결론은 현재 폭 32의 모듈별 변환 뒤 평균 문맥 하나를 `GRUCell`에 넣고 같은 값을 두
모듈에 되돌리는 최소 반복 공유 공간이 `QuantumC`의 두 단서를 안정적으로 결합하지 못했다는
것이다. 한 `QuantumC` 상태가 행동 원인이었던 GRAFT 결과나 각 단서가 셀 평균 뒤까지 남았던
정보 지도는 철회되지 않는다. 다만 반복 횟수만 늘려서는 두 상태의 관계 계산이 생기지 않았다.

무효·최종 결과, 두 실행의 체크포인트 32개와 로그는 HF 조직 보관소
`dancinlab/anima-lab-research-archive`의 `workspace1-recurrent` revision에 보존했다. 원격에서
다시 받은 manifest 40개 항목을 전수 확인했으며 manifest SHA-256은
`e9728489b228f448680cc8a63dbe73f835b438f58a64ae359ba260f123b6672b`다.
