# VALUE-1 — 연속 사건 수에 따른 값 판독 경계

상태: 완료 · `VB1_READOUT_VALID_THROUGH_16`
등록일: 2026-08-11
선행 결과: `CONJUNCTION-1=CJ0_INVALID`

## 질문

`CONJUNCTION-1`에서 정확한 상황+열쇠 주소는 저장 위치를 100% 찾았지만, 16개 사건 뒤 저장된
답 상태를 행동으로 읽는 정확도는 76%대였다. 이 실패가 처음 나타나는 사건 수는 4·8·12·16 중
어디인가?

이번 검사는 주소 변환이나 관계 결합을 바꾸지 않는다. 기억 위치는 정답 사건의 정확한 주소로
고정하고, 연속해서 처리한 사건 수에 따른 답 상태 판독만 측정한다.

## 고정 자료와 흐름

- `CONJUNCTION-1`의 상황 8종, 열쇠 8종, 값 8종, 감각 단어, 상태 폭 96을 그대로 쓴다.
- 평가 512회차는 질문 상황×열쇠×정답 512조합을 각각 한 번 포함하며 선행 평가와 다른 고정
  자료 seed를 쓴다.
- 각 회차는 활성 상황·열쇠·값 네 종류와 16개의 고유 상황×열쇠 쌍을 유지한다.
- 16개 사건을 네 묶음으로 재배열한다. 각 묶음에는 활성 값 네 종류가 정확히 한 번씩 나오며,
  질문 사건은 첫 묶음에 포함한다.
- 사건 수 4·8·12·16은 같은 재배열의 앞부분을 사용한다. 따라서 짧은 조건의 전체 감각 흐름은
  긴 조건의 접두 구간과 완전히 같다.
- 각 사건 수는 같은 회차와 같은 엔진 시작 seed에서 별도로 시작한다. 사건 수 이외의 초기 상태,
  감각 처리, 방해 입력, 자체 갱신, 질문 흐름은 같다.
- 값 원형 seed 1337·7331 × 엔진 시작 seed 1337·7331의 네 조합을 평가한다.
- 기억 주소는 상황·열쇠의 정확한 one-hot 결합으로 고정한다. 학습, 주소 다시 맞춤, 결과를 본 뒤
  자료량·순서·문턱 변경은 하지 않는다. 장치는 CPU다.

## 비교 조건

1. 정확 주소로 저장하고 검색한 값 상태
2. 같은 정확 주소에 다른 값 내용을 한 칸 돌려 저장한 가짜 비교
3. 정상 내용을 새 기억 장치에 다시 저장한 복구 비교

각 조건은 최종 값 판독, 값별 맞힘률, 저장 위치 선택, 저장된 내용 직접 판독, 기억 API 일치와
주소 거리 차이를 기록한다.

## 유효 조건과 문턱

- 선행 `CONJUNCTION-1` 결과·판정과 값 원형 체크포인트의 SHA-256 파일 지문 일치
- 512회차 전부 고유하고 질문 상황×열쇠×정답 512조합이 정확히 한 번씩 존재
- 모든 회차에서 16개 원본 쌍이 고유하고 네 값 균형 묶음이 각각 네 개 존재
- 사건 수별 입력은 등록된 공통 순서의 정확한 접두 구간이며 질문 사건이 항상 포함
- 정확 주소 선택 99% 이상, 기억 API 일치 100%
- 정상 값 판독과 최종 정확도 90% 이상, 값별 최저 맞힘률 75% 이상이면 해당 사건 수 통과
- 내용 한 칸 돌리기 정확도 5% 이하
- 복구 예측은 정상 예측과 100% 일치
- 네 평가 조합, 사건 수별 512회차, 고정 초기 상태와 상태 폭이 모두 유지

원본 지문, 자료 균형, 접두 순서, 입력 모양, 필수 수치 중 하나라도 어긋나면 무효다.

## 사전 판정

- `VB1_READOUT_VALID_THROUGH_16`: 4·8·12·16개가 모두 통과
- `VB2_BOUNDARY_12`: 4·8·12개 통과, 16개 실패
- `VB3_BOUNDARY_8`: 4·8개 통과, 12개부터 실패
- `VB4_BOUNDARY_4`: 4개만 통과
- `VB5_BELOW_4`: 4개부터 실패
- `VB6_NON_MONOTONIC`: 더 짧은 조건이 실패한 뒤 더 긴 조건이 다시 통과
- `VB0_INVALID`: 선행 자료, 균형, 실행, 주소, 가짜 또는 복구 조건 실패

판정 우선순위는 `VB0 → VB6 → VB1~VB5`다. 경계가 확인돼도 의식 증거가 아니며, 다음 실험은
경계 직전과 직후에서 사건 수·시간·감각 간섭을 분리하는 `VALUE-MECHANISM-1`이다.

결과를 보기 전 이 문서와 README를 커밋하고 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 실행과 결과

사전등록 커밋은 `ec4dca3fc`, 실행기 커밋은 `70058fed7`다. 등록된 512회차 × 사건 수 4조건 ×
값 원형·엔진 시작값 4조합을 로컬 CPU에서 전부 실행했다.

|---|---:|---:|---:|---:|---:|
| 1337 · 1337 | 100% | 100% | 100% | 100% | 0.20% |
| 1337 · 7331 | 100% | 100% | 100% | 100% | 0.39% |
| 7331 · 1337 | 100% | 100% | 100% | 100% | 0.20% |
| 7331 · 7331 | 100% | 100% | 100% | 100% | 0.20% |

표의 값은 최종 값 판독 정확도다. 모든 칸에서 저장 위치 선택, 저장 내용 직접 판독, 값별 최저
맞힘률, 복구 예측과 기억 API 일치도 100%였다. 자료 512회차는 모두 고유했고 모든 접두 구간은
질문 사건을 포함하며 값 네 종류를 같은 횟수로 담았다.

## 판정과 다음 단계

판정은 `VB1_READOUT_VALID_THROUGH_16`이다. 질문 사건이 첫 위치에 있으면 16개 사건을 처리해도 값
상태가 흐려지지 않았다. 따라서 `CONJUNCTION-1`의 실패를 사건 수나 기억 용량 탓으로 볼 수 없다.

두 실험의 핵심 차이는 질문 사건의 처리 위치다. 다음 `VALUE-MECHANISM-1`은 16개 사건과 정확
주소를 유지하고 질문 사건만 `1·5·9·13·16번째`로 옮겨 순서 효과를 직접 측정한다. 이번 결과는
값 상태 흐름의 검사이며 의식 증거가 아니다.
