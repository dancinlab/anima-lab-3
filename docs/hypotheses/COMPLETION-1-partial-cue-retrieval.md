# COMPLETION-1 — 불완전한 단서의 기억 복원

상태: 사전등록
등록일: 2026-08-11
선행 결과: `ADDRESS-CENTER-2=AC1_CONTEXT_CENTER_INTEGRATED_NOT_UNIQUE`

## 질문과 고정 가설

`ADDRESS-CENTER-2`는 온전한 상황·열쇠 상태를 합친 공용 기억 주소에서 선택
`93.85~94.34%`, 최종 행동 `93.16~93.36%`를 재현했다. 다음 질문은 저장된 기억을 찾을 때
입력 상태 일부가 빠져도 같은 사건을 복원할 수 있는가다.

이번 실험은 새 복원 층을 만들지 않는다. 온전한 주소를 저장한 기존 `CompositeStateTransform →
VectorMemory` 경로가 질문 단서 손상을 얼마나 견디는지 먼저 측정한다. 성공하면 일반적인 가까운
이웃 검색의 손상 허용 범위를 확인하는 것이며, Anima·해마·의식에 고유한 기능으로 해석하지
않는다.

## 고정 구현과 설계

- `ADDRESS-CENTER-2` 결과·판정과 상황·열쇠·값 변환의 파일 지문을 실행 전에 확인한다.
- 같은 1,024회차, 네 원형/엔진 시작값 조합, 사건 16개와 감각 순서를 그대로 사용한다.
- 저장할 때는 온전한 상황·열쇠 상태를 공용 변환에 넣는다.
- 질문할 때만 각 상태의 폭 96 좌표 일부를 0으로 바꾸고 모든 셀에 같은 가림표를 적용한다.
- 가림표는 `completion1|data_seed|episode_index|component` 문자열의 SHA-256에서 결정형으로
  만들며 정답·원형 seed·엔진 seed·결과를 입력으로 쓰지 않는다.
- 제거 비율 25%·50%·75%는 각각 정확히 24·48·72개 좌표다. 남은 값의 크기는 다시 키우지 않는다.
- 상황은 기존 6회, 열쇠·값은 3회 처리한다. 얼린 변환·폭 64 주소·코사인 거리·값 판독은
  바꾸지 않는다.
- 새 층, 추가 학습, 검색 후보 조정, 처리 횟수 변경, 결과를 본 뒤 가림표를 고르는 작업은 하지
  않는다.

평가 조건은 다음으로 고정한다.

- `full_cue`: 손상 없는 공용 상황 중심 주소
- `context_half_cue`: 질문 상황 좌표만 50% 제거
- `key_half_cue`: 질문 열쇠 좌표만 50% 제거
- `both_quarter_missing`: 질문 상황·열쇠 좌표를 각각 25% 제거
- `both_half_missing`: 질문 상황·열쇠 좌표를 각각 50% 제거
- `both_three_quarters_missing`: 질문 상황·열쇠 좌표를 각각 75% 제거하는 경계 진단
- `exact_context_key_control`: 실제 범주의 정확 주소를 직접 준 양성 비교
- `exact_context_key_partner_swap`: 저장 내용만 한 칸 바꾼 가짜 비교

`full_cue`는 `ADDRESS-CENTER-2` 정상 조건의 사건별 예측·선택과 전체 지표가 모두 같아야 한다.
가림표와 제거 좌표 수는 네 평가 조합에서 완전히 같아야 하며, 각 질문은 저장 때 쓴 상태와 같은
원본에서 파생돼야 한다.

## 유효성 및 판정

원본 지문, 자료 구성, 상태 모양, 처리 호출 수, 공용 변환 호출 수, 주소 폭과 얼린 가중치가
등록값과 맞아야 한다. 정확 주소 비교는 기억 선택 99% 이상, 행동 90% 이상, 값별 최저 맞힘률
75% 이상이어야 한다. 내용 맞바꾸기는 행동 5% 이하여야 한다. 모든 공용 기억 반환은 직접
코사인 계산과 100% 같아야 한다.

네 평가 조합 모두에서 다음 기준을 적용한다.

- `full_cue`: 기억 선택·행동 각각 90% 이상, 값별 최저 맞힘률 75% 이상
- `both_quarter_missing`: 기억 선택·행동 각각 90% 이상
- `context_half_cue`, `key_half_cue`: 기억 선택·행동 각각 80% 이상
- `both_half_missing`: 기억 선택·행동 각각 75% 이상, 값별 최저 맞힘률 60% 이상
- 75% 제거 조건은 경계 위치만 기록하며 성공 판정 기준에는 넣지 않는다.

판정은 다음 순서를 따른다.

- `CP1_PARTIAL_CUE_COMPLETION_VALID_NOT_UNIQUE`: 25%·성분별 50%·동시 50% 기준과 모든 통제가 통과한다.
- `CP2_FRAGILE_CUE_PATH`: 두 성분 25% 제거부터 90% 기준을 통과하지 못한다.
- `CP3_CONTEXT_PARTIAL_LOSS`: 25% 조건은 통과하지만 상황만 50% 제거한 조건이 80%에 못 미친다.
- `CP4_KEY_PARTIAL_LOSS`: 25% 조건과 상황 절반은 통과하지만 열쇠 절반이 80%에 못 미친다.
- `CP5_COMBINED_PARTIAL_LOSS`: 성분별 절반은 통과하지만 둘을 함께 절반 제거하면 75%에 못 미친다.
- `CP6_VALUE_READOUT_LOSS`: 기억 선택은 통과하지만 동시 절반 제거의 행동 또는 값별 맞힘률이
  기준에 못 미친다.
- `CP0_INVALID`: 원본·자료·가림표·호출·모양·고정 변환·정상 재현·양성 또는 가짜 비교가 어긋난다.

`CP1`이면 새 구조 없이 기존 공용 기억 경로의 부분 단서 허용 범위를 기록하고 다음
`GATE-1`로 이동한다. `CP2~CP4`이면 첫 손실 성분을 분리한 뒤 그 입력 표현만 진단한다. `CP5`면
각 성분 정보는 남지만 합친 주소의 거리 여유가 부족한지 측정한다. `CP6`이면 주소가 아니라 값
판독 경로만 추적한다.

어떤 성공 판정도 경험을 스스로 재구성한다는 생물학적 해마 기능이나 의식을 증명하지 않는다.

결과를 보기 전 이 문서와 README를 커밋하고, 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.
