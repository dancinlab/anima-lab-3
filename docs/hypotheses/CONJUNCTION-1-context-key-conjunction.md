# CONJUNCTION-1 — 상황·열쇠 결합 기억 검사

상태: 진행 전 · 사전등록  
등록일: 2026-08-11  
선행 결과: `CONTEXT-2=CX2I_PATH_RECOVERED_NOT_UNIQUE`

## 질문

상황 상태와 열쇠 상태가 각각 여러 답에 반복될 때, 공용 기억 경로가 두 부분의 쌍을 함께 사용해
한 번 저장한 값을 찾고 행동으로 읽을 수 있는가?

`CONTEXT-2`는 모든 사건의 열쇠가 같아 상황 하나만으로 정답을 찾을 수 있었다. 이번 과제는 기존
상황·열쇠·값 8종 중 회차마다 각각 4종을 고르고, 활성 상황 4개 × 활성 열쇠 4개의 모든 16쌍을
저장한다. 각 상황과 각 열쇠는 활성 값 4개에 한 번씩 연결되는 균형표를 사용하므로 어느 한쪽만으로는
정답이 정해지지 않는다.

## 고정 자료와 흐름

- 전체 상황 8개, 열쇠 8개, 값 8개와 `CONTEXT-2`의 감각 단어·상태 폭 96을 그대로 쓴다.
- 각 회차에는 질문 항목을 포함한 상황·열쇠·값 4종씩만 활성화한다.
- 한 회차에는 상황×열쇠 16쌍이 정확히 한 번씩 나오며 값은 4회씩 나온다.
- 쌍→값 표는 회차마다 순열로 바꾼 4×4 라틴 정사각형이다. 각 행과 열에는 값 4개가 한 번씩
  나오므로 상황 하나 또는 열쇠 하나만으로는 우연 기준 25%다.
- 질문 상황×질문 열쇠×정답의 512조합은 평가 자료 전체에서 정확히 같은 횟수로 나온다.
- 평가 1,024회차는 서로 다른 자료이며 `CONTEXT-1·2` 평가 자료와 다른 고정 seed를 쓴다.
- 값 원형 seed 1337·7331 × 엔진 시작 seed 1337·7331의 네 조합을 독립 평가한다.
- `CONTEXT-2`에서 얼린 폭 32 상황 변환과 폭 32 열쇠 변환을 다시 맞추지 않는다.
- 공용 호출은 `store((상황 상태, 열쇠 상태), 값 상태)` 16회와
  `retrieve((질문 상황 상태, 질문 열쇠 상태), top_k=1)` 1회다.
- 주소 폭 64, 두 부분의 같은 비중, 감각 흐름, 자체 갱신 8회, 값 판독은 선행 실험과 같다.
- 평가 중 학습, 주소 다시 맞춤, 결과를 본 뒤 문턱 조정은 하지 않는다. 장치는 CPU다.

## 비교 조건

1. 공용 합성 주소 정상 조건
2. 장치 밖에서 같은 주소를 계산한 기준
3. 공용 주소의 상황 부분만 가린 조건
4. 공용 주소의 열쇠 부분만 가린 조건
5. 정확한 상황+열쇠 주소 양성 비교
6. 정확 주소에서 상황만 남긴 비교
7. 정확 주소에서 열쇠만 남긴 비교
8. 정확 주소의 저장 내용을 한 칸 돌린 가짜 비교
9. 정상 내용을 새 공용 기억에 다시 저장한 복구 비교

정상 조건은 저장 위치 선택, 최종 행동, 값별 재현율, 저장 내용 판독과 기억 API 일치를 기록한다.
상황·열쇠 단독 조건은 최종 행동뿐 아니라 질문 쌍별 선택 편향도 기록한다.

## 유효 조건과 문턱

- 선행 `CONTEXT-2` 결과·판정과 상황·열쇠·값 원형 체크포인트의 SHA-256 파일 지문 일치
- 1,024회차 전부 고유하고 질문 상황×열쇠×정답 512조합이 정확히 균형
- 모든 회차에서 16개 상황×열쇠 쌍이 중복 없이 존재하고 행·열별 값 4개가 각각 한 번씩 존재
- 정상 공용 경로: 선택·최종 행동 각각 90% 이상, 값별 최저 재현율 75% 이상, 내용 판독 90% 이상
- 장치 밖 기준과 정상 공용 경로: 예측·선택 100% 일치
- 공용 상황 차단과 공용 열쇠 차단: 각각 최종 행동 35% 이하
- 정확한 두 부분 주소: 선택 99%, 최종 행동 90%, 값별 최저 재현율 75% 이상
- 정확한 상황 단독과 열쇠 단독: 각각 최종 행동 35% 이하
- 내용 한 칸 돌리기: 최종 행동 5% 이하
- 복구 예측과 정상 공용 경로 예측: 100% 일치
- 기억 API와 직접 cosine 선택: 100% 일치
- 공용 팔마다 회차당 입력 두 부분, 저장 16회, 검색 1회, 변환 17회, 주소 폭 64
- 상황·열쇠 변환은 평가 전후 얼린 상태이고 가중치가 완전히 같음

원본 지문, 자료 균형, 라틴 정사각형, 입력 모양, 호출 횟수, 주소 폭, 네 평가 조합, 양성·가짜·복구
조건, 필수 수치 중 하나라도 어긋나면 무효다.

## 사전 판정

- `CJ1_CONJUNCTION_VALID_NOT_UNIQUE`: 네 평가의 정상 공용 경로와 모든 통제가 통과
- `CJ2_COMPONENT_COLLISION`: 정확한 두 부분 주소는 통과하지만 정상 공용 주소 선택이 하나 이상 실패
- `CJ3_VALUE_READOUT_LOSS`: 정상 선택은 통과하지만 값 판독이나 최종 행동이 하나 이상 실패
- `CJ4_NOT_CONJUNCTIVE`: 정상 팔이 통과해도 상황·열쇠 단독 통제 중 하나가 35%를 초과
- `CJ0_INVALID`: 선행 자료, 균형표, 실행, 양성, 가짜, 복구 조건 중 하나라도 실패

판정 우선순위는 `CJ0 → CJ4 → CJ2 → CJ3 → CJ1`이다. `CJ1`은 공용 기억이 두 부분으로 된
주소를 실제로 사용한다는 뜻이지만, 표준 벡터 검색도 가능한 기능이므로 의식 증거가 아니다.

`preregistration_commit`으로 고정한다.
