# GATE-WRITE-MECHANISM-1 — 저장 선택 seed 요인 분해

상태: 완료 — `GWM4_MULTIFACTOR`

## 질문

`GATE-3`에서 결정형 저장 선택기는 seed 1337의 약속 문장을 21.48%만 저장했지만 seed 7331에서는
100% 저장했다. 현재 자료 생성기는 하나의 seed를 문장 틀, 임시 주제·값 식별 문자열, 방해 문장
순서에 함께 사용한다. 실패가 어느 요인에서 생겼는지 분리한다.

## 변경 전 실제 흐름

- `gate2.build_calibration()`과 `gate2.build_evaluation()`은 같은 seed로 문장 틀과 임시 식별 문자열을
  만든다.
- 사실 종류가 네 개이고 문장 틀도 종류마다 네 개라 `(seed + index) % 4`는 같은 사실 종류 안에서
  회차별로 돌지 않는다. 각 seed는 사실 종류마다 한 문장 틀만 사용한다.
- 평가 방해 문장 종류의 시작 순서도 같은 seed로 정한다.
- `GATE-3`의 문장 의미 모델, `canonical_ridge` 맞춤, 0.5 문턱과 검증된 검색 흐름은 결정형이다.

## 고정 조건

- `GATE-3`의 고정 문장 의미 모델 revision, 4,096개 보정 문장, 1,024회차 평가, 8개 후보,
  `canonical_ridge`, ridge 0.001, 선택 문턱과 검색 방식은 바꾸지 않는다.
- 기준 자료는 seed 1337과 7331이다. 각 자료에서 상대 seed의 한 요인만 맞바꾼다.
- `baseline`, `template_swap`, `identifier_swap`, `layout_swap`, `all_swap`을 측정한다.
- `template_swap`은 보정·평가의 문장 틀 출처만 상대 seed로 바꾼다.
- `identifier_swap`은 임시 주제·값·발화 문자열의 숫자 출처만 상대 seed로 바꾼다.
- `layout_swap`은 보정 자료 섞기와 평가 방해 문장 순서 출처만 상대 seed로 바꾼다.
- `all_swap`은 세 출처를 모두 상대 seed로 바꾼다.
- 검색 결과를 다시 학습하거나 결과를 본 뒤 문턱·문장 틀·학습량을 바꾸지 않는다.

## 감사 조건

- 각 팔은 4,096개 보정 문장과 8,192개 평가 후보를 가져야 한다.
- 보정과 평가 원문은 서로 겹치지 않고 각 집합 안에서 모두 고유해야 한다.
- 한 요인 맞바꾸기에서 지정한 요인의 지문만 상대 기준과 같고 나머지 요인 지문은 원 기준과
  같아야 한다.
- 문장 의미 모델 revision, 특징 폭, 점수·선택 지문과 종류별 점수 분포를 기록한다.
- 기준 팔은 기록된 `GATE-3`의 저장 선택과 종류별 결과를 정확히 재현해야 한다.

## 판정

모든 팔에서 방해 문장 저장률은 25% 이하, 종류별 방해 문장 저장률은 50% 이하이어야 한다. 이
양성 조건이나 감사 조건이 하나라도 실패하면 `GWM0_INVALID`다.

- `GWM1_TEMPLATE_CAUSAL`: 문장 틀만 맞바꾸면 두 seed의 전체 중요 사실 저장률과 약속 저장률이
  상대 기준까지 남은 차이의 80% 이상 이동하고, 식별 문자열·순서만 맞바꾸면 10%p 미만 움직인다.
- `GWM2_IDENTIFIER_CAUSAL`: 임시 식별 문자열만 맞바꿀 때 위와 같은 80% 이상의 상호 이동이
  생기고, 문장 틀·순서만 맞바꾸면 10%p 미만 움직인다.
- `GWM3_LAYOUT_CAUSAL`: 방해 문장 순서만 맞바꿀 때 위와 같은 80% 이상의 상호 이동이 생기고,
  문장 틀·식별 문자열만 맞바꾸면 10%p 미만 움직인다.
- `GWM4_MULTIFACTOR`: 모든 요인을 맞바꾸면 상대 기준이 재현되지만 단일 요인 어느 것도 위의
  단독 원인 기준을 만족하지 않는다.
- `GWM5_UNEXPLAINED`: 모든 요인을 맞바꿔도 상대 기준 방향으로 이동하지 않는다.

단독 원인 판정에서 상대 기준 방향은 seed 1337 팔이 seed 7331 기준 쪽으로 오르고, seed 7331 팔은
seed 1337 기준 쪽으로 내려가는 것을 뜻한다. 결과가 경계에 정확히 놓이면 더 강한 결론이 아니라
`GWM4_MULTIFACTOR`로 판정한다.

80%는 이미 기록된 두 기준 사이 차이를 분모로 계산한다. 전체 저장률 차이는 23.73%p이므로 절대
25%p 기준은 상대 기준을 완전히 재현해도 통과할 수 없어 실행 전에 폐기했다. 이 정정 뒤에 처음
실험을 실행한다.

## 안전 범위

이 실험은 저장 선택 자료 생성과 진단만 다룬다. 실제 대화 원문 보관, 장기 검색 기본값, 사용자
기억 자료는 변경하지 않는다. 통과해도 일반 문장 분류의 원인 분해이며 Anima 고유 기능이나 의식의
증거가 아니다.

기준 팔은 기록된 `GATE-3` 선택 지문을 정확히 재현했다. 세 요인을 모두 맞바꾸면 보정·평가 자료,
선택 지문과 결과가 상대 기준과 정확히 같아졌다. 방해 문장 전체 저장률의 최댓값은 0.279%, 종류별
최댓값은 1.953%로 등록 상한보다 충분히 낮았다.

문장 틀만 바꾸거나 식별 문자열만 바꾸면 실패 자료 1337은 거의 완전히 회복했다. 그러나 성공 자료
7331에서 어느 하나만 실패 쪽으로 바꾸면 성능이 무너지지 않았다. 순서만 바꾸면 두 자료 모두 선택
지문까지 기준과 같았다. 따라서 어느 한 요인이 양방향으로 결과를 옮기는 단독 원인은 아니다. 낮은
성능은 1337 쪽 문장 틀과 1337 모양 임시 식별 문자열이 함께 있을 때만 나타나는 상호작용이다.

## 판정과 다음 단계

사전 판정은 `GWM4_MULTIFACTOR`다. `GATE-3`의 seed 차이는 학습 난수나 검색 문제가 아니며, 한
seed가 사실 종류마다 한 문장 틀만 쓰는 자료 생성과 뜻 없는 임시 문자열 모양이 함께 만든 자료
민감성이다. 실제 대화 저장 기본값은 바꾸지 않는다.

다음은 문장 틀을 회차별로 균형 순환하고, 임시 숫자 표찰 대신 학습·평가에서 겹치지 않는 자연스러운
주제·값 어휘를 쓰는 `GATE-WRITE-CONTROL-1`이다. 네 문장 틀 각각과 새 자연 어휘 묶음에서 모두
통과하기 전에는 자동 저장 선택을 실제 대화에 연결하지 않는다.

등록 환경은 Python 3.13.13, torch 2.8.0, transformers 4.55.4, CPU였다. 독립 재실행에서 판정
JSON과 선택 체크포인트 10개는 바이트 단위로 같았고, 결과 JSON은 체크포인트 임시 경로만 달랐다.
경로를 정규화한 결과 내용은 바이트 단위로 같았다. 최종 결과 SHA-256은
`780684bb0535400a6ecbf5d5cc63c31822c81ad19e6c3f7b1f6f5cce689328a2`, 판정 SHA-256은
`c28fd0a9b162b09e006c0d9f5843cb62150ad64a9a3be9d4f77f613637469897`다.
