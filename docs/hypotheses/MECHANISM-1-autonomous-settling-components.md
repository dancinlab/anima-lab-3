# MECHANISM-1 — 자체 안정화를 만드는 내부 계산 분리

상태: 사전등록

선행 결과: `SETTLE-1=ST1_AUTONOMOUS_SETTLING_CAUSAL`

## 질문

`SETTLE-1`은 외부 감각 없는 `QuantumC.step()` 8회가 완전 정지보다 기억 주소와 최종 행동을
두 seed 모두에서 회복시킨다는 인과성을 확정했다. 그러나 한 step에는 여러 계산이 들어 있으므로
무엇이 회복을 만드는지는 아직 모른다. 새 기능을 추가하기 전에 현재 정상 실행의 활성 계산을
하나씩 끄고 필요 원인을 찾는다.

## 얼리는 항목

- `SETTLE-1`의 폭 32 `StableKeyProjector`, 값 원형, `VectorMemory`, cosine 주소 선택
- seed `1337 / 7331`, 사건 세 개, 저장 후보 세 개, 외부 입력 없는 갱신 8회
- 자료 묶음 여섯 개, 묶음당 512회차, 질문 가능한 첫 두 사건
- 주소 선택·최종 행동 90%, 값별 최저 재현율 75%, 내용 판독 90%
- 정확 주소·내용 맞바꾸기·복구·두 후보 양성 비교
- 같은 시작 상태와 질문 난수, 짝지은 양측 정확 검정

결과를 본 뒤 자료 수, 갱신 횟수, 문턱, 주소 가중치, 값 판독, 계산 묶음을 바꾸지 않는다.

## 새 독립 자료

`RECOVERY-1`·`RESET-1`·`SETTLE-1`과 겹치지 않는 새 시작값으로 여섯 자료 묶음을 만든다. 각
묶음은 정답 값, 질문 위치, 질문 열쇠, 질문 상황이 정확히 균형이어야 하고 모든 선행 자료와 사건
지문이 하나라도 겹치면 무효다.

## 팔

- `intact`: 정상 `QuantumC.step()` 8회
- `frozen`: 내부 상태를 전혀 갱신하지 않음
- `without_phase_rotation`: 고유 위상 속도에 의한 회전 쓰기만 끔
- `without_amplitude_interference`: 이웃 간섭이 진폭에 쓰이는 계산만 끔
- `without_neighbor_phase_morphism`: 이웃 평균 쪽으로 위상을 섞는 쓰기만 끔
- `without_frustration_regulation`: 좌절도 이동평균·잡음·평탄화 쓰기를 끔
- `without_amplitude_normalization`: 셀별 최대값 정규화 쓰기만 끔
- `without_structural_adaptation`: 셀 분할·병합 쓰기만 끔

계산 차단은 자체 갱신 8회에만 적용하고 질문 감각 경로는 정상으로 되돌린다. 모든 팔은 같은 회차
초기 상태와 질문 난수를 쓴다. 좌절도 조절을 끈 팔도 정상 팔이 사용했을 난수는 같은 순서로
소비한 뒤 상태 쓰기만 막아 질문 시점의 난수 차이를 만들지 않는다.

현재 정식 설정에서 `hebb_eta=0`, `repel_gamma=0`, `diff_gain=0`, `wave_dim_k=0`이므로 앞의 세
선택 기능은 실행되지 않고, 기존 셀별 스칼라 파동은 바로 다음 최대값 정규화에서 정확히 상쇄된다.
활성 원인이 아닌 계산을 켜거나 이름만 바꾼 팔은 만들지 않는다. 장력 기록과 Φ는 읽기 전용이라
상태를 바꾸지 않으므로 후보가 아니다.

## 유효성

`intact`는 두 seed 모두 최종 행동·주소 선택 90% 이상과 값별 최저 재현율 75% 이상을 통과해야
한다. `frozen`은 `SETTLE-1`과 같이 상태가 바뀌지 않아야 하며 `intact`보다 낮아야 한다. 모든
팔의 정확 주소·맞바꾸기·복구·두 후보 비교, 체크포인트 지문, 주소 변환 동결, 자료 균형과 중복
없음, 실제 차단 목록과 갱신 횟수, 유한값을 닫힌 판정기가 확인한다.

## 필요 원인 판정

계산 하나는 seed별로 다음을 모두 만족할 때 필요 원인으로 센다.

1. 해당 계산을 끈 팔의 최종 행동과 주소 선택이 `intact`보다 각각 5%p 이상 낮다.
2. 짝지은 정답·오답 변화의 양측 정확 검정이 최종 행동과 주소 선택 모두 `p ≤ 0.01`이다.
3. 여섯 자료 묶음 중 적어도 다섯 묶음에서 두 점수가 모두 낮다.
4. 정답 주소와 가장 강한 오답 주소 사이 평균 간격이 줄어든다.

판정 이름은 다음으로 고정한다.

- `MC1_SINGLE_COMPONENT_NECESSARY`: 정확히 한 계산이 두 seed 모두에서 필요하다.
- `MC2_DISTRIBUTED_COMPONENTS_NECESSARY`: 둘 이상 계산이 두 seed 모두에서 필요하다.
- `MC3_NO_SINGLE_COMPONENT_NECESSARY`: 어느 단일 계산 차단도 두 seed에서 기준만큼 무너뜨리지 않는다.
- `MC4_SEED_CONDITIONAL_COMPONENT`: 필요 계산이 seed 사이에서 일치하지 않는다.
- `MC0_INVALID`: 양성 비교나 실행 통제가 하나라도 깨진다.

`MC1`이면 해당 계산을 보존한 채 `CAPACITY-2`에서 안정화 후 용량을 다시 잰다. `MC2`면 필요한
계산들의 최소 조합을 별도 사전등록한다. `MC3`이면 단일 요소가 아니라 상호작용이므로 결과를 보고
조합을 고르지 않고 전 요소 제거 후 하나씩 복구하는 별도 실험을 등록한다. `MC4`면 seed별 초기
상태 차이를 먼저 분석한다. 어떤 판정도 의식의 증거로 해석하지 않는다.
