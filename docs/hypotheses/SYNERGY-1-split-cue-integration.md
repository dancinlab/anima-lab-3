# SYNERGY-1 — 두 모듈의 부분 단서를 함께 쓸 수 있는가

## 사전등록

STATE-2와 GRAFT B2에서 한 `QuantumC` 상태가 행동의 원인이 됐고, META-1에서는 그 상태가 오류
가능성도 담았다. 이번 질문은 한 모듈로는 알 수 없는 답을 두 독립 모듈의 상태를 함께 읽을 때만
구할 수 있는지다. 조건과 숫자 기준의 단일 원장은 `measurement/synergy_registry.py`다.

독립 `QuantumC` 두 개에 단서를 하나씩 준다. A 모듈과 B 모듈은 각각 네 단서 중 하나만 받으며,
정답은 두 단서 번호를 더해 4로 나눈 나머지다. 모든 16개 조합을 같은 횟수로 제시하므로 어느 한
모듈만 보면 A~D 정답은 정확히 같은 횟수다. 각 모듈의 초기 상태·방해 단어·지연도 상대 모듈의
단서와 독립적으로 만든다. 따라서 한쪽 상태나 실행 seed가 다른 쪽 정답을 새게 할 수 없다.

공용 실행 경로는 `QuantumC.get_phase_states()` 두 묶음을 이어 `ThalamicBridge` 폭 32와 기존
`HFDecoder` 행동 연결로 보낸다. 새 공유 공간이나 의식 점수는 추가하지 않는다. 같은 감각값을
그대로 보관하는 직접 기억과, 두 단서를 차례로 읽는 표준 `GRU` 순환 기억층을 양성 비교군으로 둔다.
세 팔은 같은 언어 모델·질문·행동 토큰·학습 횟수·일반 문장 보존 손실을 쓴다.

다음 개입을 결과 전에 고정한다.

- 정상: 두 모듈의 원래 짝을 함께 읽음
- A만: B 상태를 0으로 차단
- B만: A 상태를 0으로 차단
- 짝 뒤섞기: A는 유지하고, B를 다른 단서이면서 정답도 달라지는 사례로 교체
- 복구: 원래 짝을 다시 넣고 정상 출력과 비트 단위로 같아야 함

두 비교군은 두 seed 모두 정상 정확도 80% 이상, 한 모듈만 본 정확도와 짝 뒤섞기 정확도는 40%
이하, 정상과 가장 좋은 한쪽 조건 차이는 35%p 이상이어야 검사가 유효하다. `QuantumC`는 정상
75% 이상을 요구한다. 모든 팔에서 중립 문장의 분포 변화는 KL 0.50 nat 이하이며 복구 정확도는
정상과 완전히 같아야 한다.

- `Y0_INVALID`: 균형·seed·체크포인트·직접 기억·GRU 비교군 또는 숫자 유효성 실패
- `Y1_INTEGRATED_NOT_UNIQUE`: `QuantumC`가 두 단서를 원인적으로 합치지만 일반 비교군과 동등
- `Y2_QUANTUM_ADVANTAGE`: 두 seed 모두 `QuantumC`가 두 일반 비교군보다 5%p 초과 우세
- `Y3_NOT_INTEGRATED`: 두 seed 중 하나라도 `QuantumC` 결합 기준 실패
- `Y4_CONFOUNDED`: 결합은 되지만 일반 언어 변화가 등록 상한 초과

통과해도 “부분의 합보다 많은 신비한 정보”나 의식을 증명하지 않는다. 정확한 뜻은 현재 내부 상태
경로가 서로 독립적인 두 단서를 한 행동에 함께 사용할 수 있다는 것이다. 일반 기억이나 `GRU`도
같이 통과하면 이는 일반적인 정보 결합 능력으로 정리한다.

## 결과

### 1차 — Y0_INVALID

표준 `GRU`는 정상 정확도 `100% / 93.8%`, A만·B만은 모두 25%, 짝 뒤섞기는 `10.9% / 4.7%`,
중립 문장 변화는 `0.031 / 0.017 nat`로 두 seed 모두 과제를 검증했다. 반면 직접 기억은 정상
`32.8% / 39.1%`이고 중립 문장 변화도 등록 상한을 넘었다. `QuantumC`는 정상
`29.7% / 29.7%`였다. 원래 규칙은 직접 기억과 `GRU`가 모두 성공해야 유효하므로 1차 판정은
`Y0_INVALID`다. 이 결과는 `measurement/synergy_invalid_{results,verdict}.json`에 보존한다.

근본 원인은 직접 기억을 과제 양성 비교군으로 잘못 지정한 것이다. 직접 저장은 두 단서를 보존하지만
두 값의 비선형 관계를 계산하는 장치가 아니다. 반면 학습 가능한 표준 순환 기억층 `GRU`는 두 단서를
차례로 읽고 등록 기준을 모두 통과했으므로 과제가 풀 수 있는지 검증하는 비교군 역할을 실제로 했다.
직접 기억의 실패는 과제 무효가 아니라 단순 저장만으로 결합 계산을 하지 못했다는 비교 결과다.

### 비교군 역할 수리 — 사전등록

새 정본은 `synergy1_split_cue_modular_sum_control_role_repair`다. 과제 유효성은 `GRU` 두 seed의
통과로만 판정한다. 직접 기억은 삭제하거나 숨기지 않고 같은 학습량의 비교 팔로 유지한다. 두
`QuantumC`, 16개 균형 조합, 독립 seed, 학습 800단계, 한쪽 차단·짝 뒤섞기·복구, 정확도·차이·
일반 문장 보존의 모든 숫자 기준은 1차와 같다. 결과는 이 수리를 Git에 고정한 뒤 새 체크포인트로
처음부터 다시 실행한다.
