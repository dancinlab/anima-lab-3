# CONTEXT-1 — 상황과 열쇠를 함께 쓰는 기억 주소 양성 비교

상태: 완료 · `CX1_CONTEXT_KEY_VALID_NOT_UNIQUE`
등록일: 2026-08-10  
선행 결과: `SEPARATION-2=SP3_CONTEXT_NOT_IN_KEY_STATE`

## 질문

같은 열쇠를 공유하는 사건 네 개에서, 따로 감각한 상황 상태와 열쇠 상태를 각각 안정된 주소로
바꿔 함께 사용하면 질문 상황에 맞는 사건을 찾을 수 있는가?

`SEPARATION-2`는 값과 기억 장치는 정상인데 열쇠를 읽는 순간의 상태에 앞선 상황이 남지 않음을
확인했다. 이번 검사는 새 기억 구조를 만들지 않는다. 기존 실행 흐름이 이미 따로 만든 상황 상태와
열쇠 상태를 보존해, 두 결정형 주소를 단순히 이어 붙이는 표준 양성 비교만 수행한다.

## 고정 흐름

- 새 독립 회차마다 `상황→열쇠→값` 사건 네 개를 차례로 감각한다.
- 정상 사건은 같은 열쇠 하나, 서로 다른 상황 네 개, 서로 다른 값 네 개를 가진다.
- 방해 입력 두 개와 외부 입력 없는 정상 자체 갱신 8회 뒤 `상황→열쇠`를 다시 감각한다.
- 저장 때의 상황 상태와 열쇠 상태, 질문 때의 상황 상태와 열쇠 상태를 각각 보존한다.
- 열쇠는 `CANONICAL-2`에서 얼린 결정형 폭 32 변환을 그대로 쓴다.
- 상황은 평가와 겹치지 않는 별도 1,024회차의 저장·질문 상황 상태로 같은 결정형 폭 32 변환을
  한 번 계산한다. 값이나 행동 정답은 사용하지 않는다.
- 최종 주소는 정규화한 `상황 주소`와 `열쇠 주소`를 같은 비중으로 이어 붙인 폭 64 벡터다.
- 기존 `VectorMemory`, 값 상태 원형, 최종 값 판독은 바꾸지 않는다.
- 값 원형 seed `1337 / 7331` × 엔진 시작 seed `1337 / 7331`의 네 조합을 모두 평가한다.
- 각 조합은 새 독립 2,048회차이며 자료와 엔진 시작값은 조합 사이에서 짝을 맞춘다.
- 장치는 CPU다.

## 비교 조건

1. 결정형 상황 주소와 기존 열쇠 주소를 함께 쓰는 정상 조건
2. 정상 주소에서 상황 부분을 0으로 가린 조건
3. 정상 주소에서 열쇠 부분을 0으로 가린 조건
4. 결정형 주소로 서로 다른 열쇠 네 개를 찾는 양성 비교
5. 정확한 `상황+열쇠` 원-핫 주소 양성 비교
6. 정확 주소의 저장 내용을 한 칸 돌린 가짜 비교
7. 정상 내용을 새 기억에 다시 저장한 복구 비교

모든 조건에서 저장 위치 선택, 최종 행동, 값별 재현율, 저장 내용 판독, 기억 API와 직접 cosine
선택의 일치, 주소 여유를 기록한다. 상황·열쇠 주소 가중치, 값 원형, 원본 결과와 판정 파일의
SHA-256 지문도 검사한다.

## 유효 조건과 문턱

- 별도 평가 상태의 상황 분류: 정확도 99%, 상황별 최저 재현율 95% 이상
- 서로 다른 열쇠 조건: 선택·최종 행동 각각 90% 이상
- 정확한 `상황+열쇠`: 선택 99%, 최종 행동 90%, 값별 최저 재현율 75% 이상
- 상황 부분 가림: 최종 행동 35% 이하
- 내용 한 칸 돌리기: 최종 행동 5% 이하
- 복구 예측과 정상 합성 주소 예측: 100% 일치
- 기억 API와 직접 선택: 100% 일치
- 정상 합성 주소: 선택·최종 행동 90%, 값별 최저 재현율 75%, 내용 판독 90% 이상

자료 중복·균형 오류, 네 평가 조합 누락, 원본 지문 변경, 보정·평가 자료 중복, 주소 폭이나 같은
비중 변경, 평가 중 주소 재계산, 자체 갱신 횟수 변경, 필수 수치 누락이나 유한하지 않은 값이 하나라도
있으면 무효다.

## 사전 판정

- `CX1_CONTEXT_KEY_VALID_NOT_UNIQUE`: 네 조합의 합성 주소가 정상 기준을 모두 통과
- `CX2_CONTEXT_CODE_LOSS`: 유효한 통제 아래 별도 평가 상황 상태 분류가 하나 이상 실패
- `CX3_COMPOSITION_LOSS`: 상황 분류는 통과하지만 합성 주소 선택이 하나 이상 실패
- `CX4_VALUE_READOUT_LOSS`: 합성 주소 선택은 모두 통과하지만 값 판독이나 최종 행동이 실패
- `CX0_INVALID`: 원본·자료·실행·양성·가짜·복구 조건 중 하나라도 실패

판정 우선순위는 `CX0 → CX2 → CX4 → CX1 → CX3`이다. `CX1`이면 상황과 열쇠를 선택적으로 함께
받는 주소 입력을 공용 `VectorMemory` 경로에 최소 확장한 뒤 같은 전체 행동을 재검증한다. `CX2`면
상황 감각 자체의 시간 안정성을 분해한다. `CX3`면 이어 붙이기 전 두 주소의 거리와 비중만
분해하며 결과를 보고 구조를 추가하지 않는다. `CX4`면 주소 뒤 값 판독만 검사한다. 어떤 판정도
의식 증거가 아니다.

결과를 보기 전 이 문서와 README를 먼저 커밋하고, 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 결과

사전등록 커밋은 `db66f1163`, 실행기·판정기 커밋은 `a0a73c515`다. 상황 주소는 평가와 겹치지
않는 1,024회차 × 엔진 시작값 2개의 10,240개 상태로 한 번 계산했다. 값과 행동 정답은 사용하지
않았고, 입력 설계 행렬의 rank는 97이었다. 새 2,048회차에서 보정·평가 사건 지문 중복은 0이었다.

합성 주소의 값별 최저 재현율은 `82.03~88.28%`, 서로 다른 열쇠 양성 비교의 최종 행동은
`96.04~96.63%`, 정확한 `상황+열쇠` 주소는 `95.75~96.39%`였다. 저장 내용을 한 칸 돌리면
`2.93~3.52%`였고 복구 예측과 기억 API 직접 선택은 네 조합 모두 100% 일치했다. 모든 주소
가중치는 평가 중 얼린 채 유지됐다.

## 판정과 다음 단계

판정은 `CX1_CONTEXT_KEY_VALID_NOT_UNIQUE`다. `SEPARATION-2`에서 같은 열쇠 사건이 실패한 첫
원인은 상황 정보 자체의 소실이 아니라 공용 기억 호출이 열쇠 시점 상태 하나만 주소로 받았기
때문이다. 따로 보존한 상황 상태는 새 자료에서도 100% 읽혔고, 이를 주소에 포함하자 전체 행동이
회복됐다.

열쇠를 가려도 이번 과제는 통과했다. 모든 저장 항목이 같은 열쇠이고 상황만 다르므로 예상된
결과이며, 이번 실험이 상황과 열쇠의 관계 계산을 증명하지는 않는다. 다음 `CONTEXT-2`는 현재
합성 입력을 기본값이 꺼진 선택형 공용 기억 경로로 연결하고 같은 결과를 재검증한다. 그 뒤에만
상황 하나나 열쇠 하나로는 풀 수 없는 쌍 조합 검사를 등록한다. 이 결과는 의식 증거가 아니다.

결과와 두 주소 체크포인트는 비공개 HF 조직 보관소
`dancinlab/anima-lab-research-archive`의 `context1-composite-memory-address` revision에 보존했다.
Hugging Face 커밋은 `602a6947aa59600a39d53de43200de24b020f4ae`이며 새 임시 폴더로 다시
내려받아 5개 항목의 SHA-256을 전수 확인했다. 로컬 CPU에서만 실행했다.
