# VALUE-MECHANISM-1 — 값 상태의 처리 위치 효과

상태: 완료 · `VP2_LATE_POSITION_LOSS`
등록일: 2026-08-11
선행 결과: `VALUE-1=VB1_READOUT_VALID_THROUGH_16`

## 질문

16개 사건을 처리해도 질문 사건이 첫 위치에 있으면 값 상태 판독이 100%였다. 반면 질문 위치가
회차마다 달랐던 `CONJUNCTION-1`은 76%대였다. 저장된 답을 읽는 성능은 사건 수가 아니라 해당
답을 감각으로 처리한 순서에 따라 달라지는가?

## 고정 자료와 흐름

- `VALUE-1`과 같은 상황·열쇠·값 8종, 512회차, 값 원형 seed 2개 × 엔진 시작 seed 2개를 쓴다.
- 사건 수는 모든 조건에서 16개다.
- `VALUE-1`의 값 균형 순서를 기준으로 질문 사건을 `1·5·9·13·16번째`에 둔다.
- 위치를 옮길 때는 첫 사건과 목표 위치 사건만 맞바꾼다. 사건 집합, 각 값의 횟수, 질문 정답,
  방해 입력과 자체 갱신은 바꾸지 않는다.
- 모든 위치 조건은 같은 회차와 같은 엔진 시작 seed에서 별도로 시작한다.
- 기억 위치는 상황·열쇠의 정확한 one-hot 주소로 고정한다. 주소 변환, 학습, 결과를 본 뒤 위치·
  자료량·문턱 변경은 하지 않는다. 장치는 CPU다.

## 비교 조건과 문턱

1. 정확 주소의 정상 값 상태
2. 같은 주소에 다른 값 내용을 한 칸 돌려 저장한 가짜 비교
3. 정상 내용을 새 기억 장치에 다시 저장한 복구 비교

- 선행 결과·판정과 값 원형 파일 지문 일치
- 512회차 고유성·질문 삼중 조합 균형·16개 쌍 고유성 유지
- 위치별 질문 사건의 실제 저장 위치가 등록값과 정확히 일치
- 정확 주소 선택 99% 이상, 기억 API 일치 100%
- 정상 값 판독과 최종 정확도 90% 이상, 값별 최저 맞힘률 75% 이상이면 해당 위치 통과
- 가짜 내용 정확도 5% 이하, 복구 예측 100% 일치
- 다섯 위치가 같은 사건 집합과 같은 엔진 시작 상태를 사용

## 사전 판정

- `VP1_POSITION_INVARIANT`: 다섯 위치가 모두 통과
- `VP2_LATE_POSITION_LOSS`: 앞선 위치는 통과하고 뒤 위치부터 단조롭게 실패
- `VP3_POSITION_SPECIFIC`: 위치에 따른 차이는 있으나 통과·실패가 단조롭지 않음
- `VP4_POSITION_NOT_CAUSAL`: 위치별 차이가 5%p 미만인데 선행 실패를 재현하지 못함
- `VP0_INVALID`: 선행 자료, 사건 집합, 주소, 가짜 또는 복구 조건 실패

`VP2`는 값 상태의 절대적인 사건 용량 문제가 아니라 감각 처리 위치에 따른 상태 표현 변화가
원인이라는 뜻이다. `VP2`가 나오면 다음 `VALUE-2`는 같은 값의 시간별 상태를 같은 값 표현으로
맞추는 최소 결정형 변환을 양성 비교로 검증한다. 어떤 판정도 의식 증거가 아니다.

결과를 보기 전 이 문서와 README를 커밋하고 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 판정과 다음 단계

판정은 `VP2_LATE_POSITION_LOSS`다. 통과·실패 기준으로는 첫 위치만 통과하고 뒤 네 위치가 모두
실패했다. 뒤 위치 사이의 정확도는 완전히 단조롭지 않지만 모두 등록 문턱 아래이므로, 사건 수가
아니라 같은 값을 감각으로 처리한 절대 위치가 값 상태의 판독 가능성을 바꾼다는 원인이 재현됐다.

다음 `VALUE-2`는 새 기억 구조를 만들지 않는다. 이미 열쇠 주소에서 검증한 난수 없는 결정형 맞춤을
값 상태에 재사용하고, 공용 `VectorMemory`에 선택형 값 변환을 연결해 다섯 위치를 다시 검사한다.
이번 결과는 내부 상태 표현의 안정성 문제이며 의식 증거가 아니다.
