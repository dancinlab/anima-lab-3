# SEPARATION-1 — 닮은 사건 충돌 위치 검사

상태: 수리 사전등록 · 재실행 전
등록일: 2026-08-10  
선행 결과: `EPISODE-2=E2I_PATH_RECOVERED_NOT_UNIQUE`

## 질문

같은 열쇠를 공유하지만 앞선 상황과 값이 다른 사건 여러 개를 기존 공용 기억에 함께 저장했을 때,
`QuantumC`의 현재 주소 경로가 질문 상황에 맞는 사건을 구분하는가?

`EPISODE-2`는 서로 다른 열쇠 두 개를 찾는 경로를 검증했다. 이번에는 열쇠 정체성만으로 구분할 수
없는 사건 네 개를 사용한다. 새 기억층이나 해마식 분리 기능은 추가하지 않고, 정보가 처음 사라지는
위치만 찾는다. 통과해도 일반적인 열쇠 검색보다 고유하거나 의식의 증거라는 뜻은 아니다.

## 실행 흐름

- 한 회차에 `상황 → 열쇠 → 값` 사건 네 개를 차례로 감각한다.
- 정상 조건의 네 사건은 같은 열쇠를 공유하고, 상황과 값은 서로 다르다.
- 방해 입력 두 개 뒤 `상황 → 열쇠`를 다시 감각해 해당 위치의 값을 질문한다.
- `EPISODE-2`의 seed별 얼린 `StableKeyProjector`, 기존 `VectorMemory(key_transform=...)`,
  `EPISODE-1` 값 원형과 최종 값 판독을 그대로 쓴다.
- 비교 조건은 같은 회차·값·질문 위치를 유지하고 네 열쇠만 서로 다르게 만든다.
- 정확한 양성 비교는 상황과 열쇠 번호를 이어 붙인 표준 원-핫 주소를 같은 `VectorMemory`에 넣는다.
- 모든 팔은 같은 회차 자료와 seed별 엔진 초기값을 쓰며, 팔 순서와 무관한 전용 seed로 실행한다.

## 고정 사양

- seed: `1337 / 7331`
- 평가 회차: seed별 2,048
- 회차당 사건: 4개
- 열쇠·값·상황 종류: 각각 8개
- 정상 사건: 같은 열쇠 1개, 서로 다른 상황 4개, 서로 다른 값 4개
- 방해 입력: 2개
- 주소 변환: `KEY-1` seed별 폭 32 얼린 선형 변환
- 기억: 기존 `VectorMemory(capacity=4)`, cosine top-1
- 상태 특징 폭·감각 단계·값 원형: `EPISODE-1`과 동일
- 셀 수: 엔진의 등록 범위 2~48, 주소 입력은 기존과 같은 셀 평균
- 장치: CPU

모든 seed·회차·팔·문턱과 자료 생성 seed는 구현 단계의
`measurement/separation_registry.py`를 단일 기준으로 고정한다. 그 파일의
`preregistration_commit`은 README와 이 문서를 먼저 고정한 Git 커밋을 가리켜야 한다.

## 비교와 개입

1. `stable_similar_normal`: 같은 열쇠 사건 네 개를 공용 안정 주소로 검색
2. `raw_similar_normal`: 주소 변환을 끈 원시 내부 주소로 같은 사건 검색
3. `stable_distinct_key_control`: 네 사건의 열쇠를 다르게 만든 기존 능력 양성 비교
4. `exact_context_key_control`: 정확한 `상황+열쇠` 주소를 쓰는 표준 양성 비교
5. `exact_context_key_partner_swap`: 저장 내용을 한 칸 돌려 상황과 값의 원인을 끊음
6. `exact_context_key_recovered`: 정상 연결을 새 기억에 다시 저장해 복구
7. `context_removed_control`: 정확 주소에서 상황 부분을 모두 같게 만들어 4지선다 우연 기준 측정

각 정상 팔에는 최종 정확도, 저장 위치 선택 정확도, 값별 재현율, 올바른 값 상태 판독, 기억 API와
직접 cosine 선택의 일치율, 주소 여유를 기록한다. 복구 팔은 정상 양성 비교와 예측이 항목별로 같은지
기록한다.

## 무효 조건

- 사전등록 뒤 seed·회차·사건 수·팔·문턱·자료 생성 방식을 결과에 맞춰 바꿈
- `EPISODE-2` 판정·결과·주소 변환·값 원형 파일의 SHA-256 지문이 달라짐
- 주소 변환이나 값 원형을 새로 학습하거나 평가 중 가중치가 바뀜
- 회차 지문이 중복되거나 질문 위치·값·열쇠·상황 균형이 맞지 않음
- 서로 다른 열쇠 양성 비교의 선택 정확도 또는 최종 정확도가 90% 미만
- 정확한 `상황+열쇠` 양성 비교의 선택 정확도가 99%, 최종 정확도가 90%, 값별 최저 재현율이
  75% 미만
- 상황 제거 비교가 35% 초과, 내용 한 칸 돌리기가 5% 초과, 복구 예측 일치가 100% 미만
- 기억 API가 직접 cosine top-1 선택과 한 회차라도 다름
- seed·팔·필수 수치가 빠지거나 NaN·무한값이 있음

## 사전 판정

- `S1_SIMILAR_EPISODES_SEPARATED_NOT_UNIQUE`: 유효 조건을 모두 통과하고 두 seed의 안정 주소가
  선택 정확도 75% 이상, 최종 정확도 75% 이상, 값별 최저 재현율 60% 이상
- `S2_STABLE_ADDRESS_COLLISION`: 원시 내부 주소는 두 seed 모두 위 기준을 통과하지만 안정 주소가
  한 seed 이상 선택 기준에 미달. 시간 안정 변환이 사건 상황을 지운 첫 위치다.
- `S3_CONTEXT_ADDRESS_LOSS`: 정확 주소·서로 다른 열쇠 비교는 통과하지만 안정 주소와 원시 내부
  주소가 모두 한 seed 이상 선택 기준에 미달. 현재 열쇠 시점 주소가 앞선 상황을 보존하지 못한다.
- `S4_VALUE_READOUT_LOSS`: 안정 주소 선택은 두 seed 모두 통과하지만 최종 정확도나 값별 재현율이
  미달. 주소 뒤 값 상태 판독이 첫 손실이다.
- `S0_INVALID`: 원본·지문·얼림·자료·양성 비교·가짜 비교·개입·복구 조건 중 하나라도 무효

판정 우선순위는 `S0 → S4 → S1 → S2 → S3`이다. `S1`이면 새 구조를 추가하지 않고 사건 수와
상황 유사도를 높이는 별도 범위 검사를 등록한다. `S2`면 기존 변환 입력에 상황 상태를 보존하는 최소
확장만 비교한다. `S3`면 현재 상태를 억지로 넓히지 않고 상황과 열쇠를 함께 주소화하는 최소 표준
방식을 먼저 양성 비교한다. `S4`면 값 상태에서 행동까지의 판독만 분해한다.

## 최초 무효 실행과 수리 등록

커밋 `2dc5dc0fd`에서 문서를, `463aca71e`에서 실행기와 판정기를 고정한 뒤 최초 실행했다. 결과
파일이 만들어지기 전 seed 1337의 2,005번째 회차에서 기존 `_sense_token`이 상태 모양 오류로
중단했다. 회차가 두 사건에서 네 사건으로 길어지면서 `QuantumC`의 등록된 셀 병합이 일어나 셀
수가 48보다 줄었지만, 재사용한 `EPISODE-1` 검사는 정확히 `(48, 96)`만 허용하고 있었다.

기억 주소와 값 판독은 원래부터 셀 축을 평균내므로 셀 수가 달라도 특징 폭 96은 유지된다. 수리
실행은 `SEPARATION-1` 전용 감각 읽기에서 특징 폭 96, 유한값, 엔진의 원래 최소·최대인 2~48셀을
검사하고 실제 셀 수 범위를 결과에 기록한다. 자료 생성, seed, 회차 수, 감각 순서, 주소 계산,
가중치, 팔, 문턱과 판정은 바꾸지 않는다. 이 수리 문서 커밋을 registry의
`protocol_repair_commit`으로 고정한 뒤 처음부터 다시 실행한다.
