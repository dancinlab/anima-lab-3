# CUE-CONTEXT-1 — 저장 시점과 질문 시점의 상황 상태 분해

상태: 완료 · `CC3_QUERY_REFIT_INSUFFICIENT`
등록일: 2026-08-11
선행 결과: `CUE-ROBUST-1=CR2_CONTEXT_CATEGORY_NOT_RECOVERED`

## 질문과 고정 가설

`CUE-ROBUST-1`은 온전한 저장 시점의 상황 상태와 그 상태를 25% 가린 복사본으로 기존
`canonical_ridge` 판독기를 다시 맞췄다. 열쇠 범주는 보지 않은 가림표에서 90%를 넘었지만,
상황 범주는 `89.16~89.94%`에 머물렀다.

실제 호출 흐름에는 아직 분리하지 않은 시간 차이가 있다. 학습 자료는 각 사건을 저장할 때 바로
읽은 상황 상태만 포함한다. 반면 실제 기억 질문은 사건 16개와 방해 입력을 모두 처리한 뒤 같은
상황을 다시 읽은 상태를 사용한다. 따라서 현재 실패가 상황 정보 자체의 손상 때문인지, 저장
시점으로만 맞춘 판독기가 질문 시점 상태의 모양 변화를 보지 못했기 때문인지 알 수 없다.

고정 가설은 질문 시점의 상태 분포가 저장 시점과 달라져 남은 손실을 만든다는 것이다. 같은
회차·같은 상황의 저장 상태와 질문 상태에 동일한 가림표를 적용하고, 질문 시점 자료를 포함한
표준 결정형 판독기가 별도 평가 회차의 질문 상태만 회복하는지 검사한다.

## 고정 구현과 비교

- `CUE-ROBUST-1` 결과·판정·판독 체크포인트와 그 실험이 상속한 상황·열쇠·값·행동 원형
  체크포인트의 파일 지문을 실행 전에 확인한다.
- 기존 평가 1,024회차와 네 원형/엔진 시작값 조합, 사건 16개, 감각 순서, 상황 처리 6회,
  열쇠·값·방해 처리 횟수를 그대로 사용한다.
- 회차마다 정답 사건을 저장할 때 읽은 상황 상태와, 방해 입력 뒤 질문할 때 같은 상황을 다시
  읽은 상태를 한 쌍으로 고정한다. 두 상태의 라벨은 같아야 한다.
- 두 상태에 `COMPLETION-1`의 같은 회차별 25% 상황 가림표를 적용한다. 시간 비교에서 가림 위치가
  달라지는 혼선을 허용하지 않는다.
- 기존 손상 대응 상황 판독기로 저장/질문 시점의 온전한 상태와 25% 손상 상태를 각각 평가한다.
  정확도, 범주별 최저 맞힘률, 정답 중심과 가장 가까운 오답 중심의 거리 차이, 같은 회차 두 상태
  및 두 주소의 코사인 유사도를 기록한다.
- 별도 학습 자료는 `COMPONENT-2`의 512회차와 두 엔진 시작값을 재사용하되, 회차마다 정답 사건의
  저장 상태 하나와 질문 상태 하나만 사용한다. 평가 회차와 지문이 겹치면 무효다.
- 같은 입력 수와 같은 `canonical_ridge` 방식으로 `storage_only`, `query_only`, `combined` 세
  판독기를 만든다. 각 시점의 온전한 상태와 별도 고정값으로 만든 25% 손상 복사본을 1:1로 쓴다.
  `combined`는 회차마다 저장/질문 중 하나를 결정형으로 교차 선택해 전체 행 수를 늘리지 않는다.
- 학습 가림표는 평가 가림표와 완전 일치가 0개여야 한다. 같은 자료를 반복하거나 순서를 뒤집어
  맞춰도 체크포인트가 같아야 한다.
- `query_only`와 `combined`는 별도 평가 회차의 저장/질문 상태에만 평가한다. 공용 기억 기본값,
  주소 폭, 처리 횟수, 새 복원 층, 주의집중, 자료 수와 문턱은 바꾸지 않는다.
- 라벨을 한 칸 순환한 가짜 질문 판독은 평가 정확도 25% 이하여야 한다.

## 유효성 및 판정

자료·시작값·상태 모양·감각 호출 수·회차 쌍·가림표·체크포인트 지문·결정성이 등록값과 맞아야
한다. 기존 판독기의 질문 시점 온전한/손상 정확도는 `CUE-ROBUST-1`과 같아야 한다. 저장 상태와
질문 상태는 같은 상황 라벨을 가져야 하며, 각 범주 수와 각 학습 판독기의 행 수가 같아야 한다.

통과 기준은 네 평가 조합 모두에 적용한다.

- 온전한 상태: 범주 정확도 90% 이상, 범주별 최저 맞힘률 75% 이상
- 25% 손상 상태: 범주 정확도 90% 이상, 범주별 최저 맞힘률 75% 이상
- 질문 시점 자료를 포함한 판독기의 질문 상태 회복은 위 두 기준을 모두 통과해야 한다.
- 질문 회복 때문에 저장 시점의 온전한 정확도가 `storage_only`보다 2%p 넘게 떨어지면 회귀다.
- 가짜 판독은 온전한·손상 질문 상태 모두 25% 이하여야 한다.
- 유사도와 거리 차이는 원인 설명용으로 기록하되 결과를 본 뒤 성공 문턱으로 쓰지 않는다.

판정 순서는 다음으로 고정한다.

- `CC1_QUERY_TIME_SHIFT_CAUSAL`: 기존 판독기는 저장 시점 손상 상태를 통과하지만 질문 시점 손상
  상태는 실패하고, `query_only` 또는 `combined`가 질문 상태를 회복하며 저장 상태 회귀가 없다.
- `CC2_SHARED_PARTIAL_CUE_LOSS`: 기존 판독기가 저장 시점과 질문 시점의 손상 상태에서 모두
  실패한다. 시간대 차이만으로 설명할 수 없다.
- `CC3_QUERY_REFIT_INSUFFICIENT`: 기존 판독기는 저장 시점 손상 상태를 통과하고 질문 시점만
  실패하지만, 질문 자료를 포함해도 질문 상태가 회복되지 않는다.
- `CC4_QUERY_RECOVERY_WITH_STORAGE_REGRESSION`: 질문 자료로 질문 상태는 회복하지만 저장 시점
  온전한 정확도가 허용 범위보다 떨어진다.
- `CC5_NO_QUERY_TIME_LOSS`: 기존 판독기가 저장·질문 시점의 손상 상태를 모두 통과한다.
- `CC0_INVALID`: 원본·자료·호출·쌍·가림표·결정성·선행 결과 재현·가짜 비교 중 하나라도 어긋난다.

`CC1`이면 질문 시점 상태를 포함하는 최소 선택 기능을 별도 통합 실험에서 검사한다. `CC2`면
시간대가 아니라 두 시점에 공통인 손상 좌표 표현을 분해한다. `CC3`이면 선형 판독 한계를 먼저
검사한다. 이번 실험 안에서는 공용 기본값을 바꾸지 않는다.

어떤 성공 판정도 생물학적 기억 복원이나 의식을 증명하지 않는다. 이는 같은 범주의 내부 상태가
처리 시점에 따라 달라지는 일반적인 자료 분포 차이를 검사하는 표준 비교다.

결과를 보기 전 이 문서와 README를 커밋하고, 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 실행과 결과

사전등록 커밋은 `90808831e`, 실행기와 닫힌 판정기 커밋은 `0aa5b4059`다. 실행 사양에 기존
판독기의 온도·편향 상속이 빠진 최초 시도는 상태 생성 전에 입력 검증으로 종료됐고 결과 파일을
만들지 않았다. 누락된 값을 기존 SSOT에서 그대로 상속한 수정은 `d607c8a50`이다. 두 번째 시도는
모든 계산을 마쳤지만 선행 결과와 새 진단표의 열 목록이 다르다는 이유로 `CC0_INVALID`가 됐다.
공통 핵심 지표는 정확히 같고 거리 합계의 계산 순서 차이는 `0.000001` 이하만 허용하도록
대조기를 바로잡은 최종 실행 커밋은 `addad102c`다. 자료·기준·판정 순서는 바꾸지 않았다.

기존 손상 대응 판독기의 같은 회차·같은 상황 결과는 다음과 같다.

|---|---:|---:|---:|
| 1337 | 99.22% / 97.17% | 96.19% / 89.16% | 0.5987 / 0.7889 |
| 7331 | 99.02% / 97.27% | 96.48% / 89.94% | 0.5988 / 0.7890 |

저장 시점의 25% 손상 상태는 두 엔진 시작값 모두 정확도 90%와 범주별 최저 맞힘률 75%를
통과했다. 질문 시점은 정확도가 각각 89.16%, 89.94%이고 범주별 최저 맞힘률은 82.03%,
82.81%여서 정확도 기준만 실패했다. 선행 `CUE-ROBUST-1`의 온전한 질문과 손상 질문 지표는
범주별 맞힘률까지 정확히 재현됐다.

같은 1,024개 학습 쌍과 같은 결정형 판독 방식으로 시점만 바꾼 비교는 다음과 같다.

| 판독기 | 저장 시점 25% 손상 | 질문 시점 온전함 | 질문 시점 25% 손상 |
|---|---:|---:|---:|
| 저장 시점 전용 | 96.97~97.07% | 92.09~92.19% | 85.16~85.25% |
| 질문 시점 전용 | 92.77~92.97% | 83.01~84.08% | 78.71~79.30% |
| 두 시점 교차 혼합 | 95.12~95.21% | 86.04~86.13% | 79.98~80.57% |

질문 시점 전용 판독의 손상 질문 범주별 최저 맞힘률은 `74.22~75.00%`, 혼합 판독은
`71.88~73.44%`였다. 즉 질문 자료를 포함한 두 판독 모두 등록한 온전한 질문·손상 질문 기준을
회복하지 못했다. 라벨을 한 칸 돌린 가짜 질문 판독은 온전함 `6.05~6.54%`, 손상
`5.66~5.96%`로 가짜 기준 25% 이하였다.

학습 512회차와 평가 1,024회차의 지문은 0개 겹쳤고, 학습·평가 가림표 1,024개끼리도 완전

## 판정과 의미

판정은 `CC3_QUERY_REFIT_INSUFFICIENT`다. 저장 시점으로만 맞춘 기존 판독기가 질문 시점 손상
상태에서만 실패했으므로 처리 시점 차이는 남은 손실의 실제 구성 요소다. 그러나 질문 시점 자료로
같은 선형 판독기를 다시 맞추거나 저장·질문 자료를 섞어도 보지 않은 질문 상태가 회복되지
않았다. 따라서 “질문 상태 예시가 없었다”만으로 원인을 닫을 수 없고, 단순 자료 추가를 공용
수정으로 채택하지 않는다.

다음은 `CUE-ALIGN-1`이다. 같은 회차의 저장·질문 상태 쌍을 이용하되 행동 라벨 없이 질문 상태를
저장 시점 좌표에 맞추는 하나의 공통 선형 정렬부터 검사한다. 공통 정렬이 실패하면 시간 변화가
범주마다 다른지 분해하고, 그 전에는 비선형 복원 층이나 주의집중을 추가하지 않는다.

이 결과는 처리 이력에 따른 일반적인 내부 표현 변화이며 생물학적 기억 복원이나 의식의 증거가
아니다. 공용 기억 기본값은 바꾸지 않았다.

결과·판정·세 시점 판독기와 가짜 판독기 체크포인트는 비공개 Hugging Face 조직 보관소
`dancinlab/anima-lab-research-archive`의 `cue-context1-storage-query-shift` revision에 보존했다.
Hugging Face 커밋은 `b7f74c614e03c8cb5b2fd203b74cca9fa3358995`, manifest SHA-256은
`5bebe1187c0d18d6640dad0ef57ff9b8ecbf665d2ebd00465c0181ba45d252e7`이다. 새 임시
디렉토리로 다시 내려받은 결과·판정·체크포인트와 manifest를 전수 확인했다.
