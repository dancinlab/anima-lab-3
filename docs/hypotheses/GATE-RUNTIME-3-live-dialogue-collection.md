# GATE-RUNTIME-3 — 실제 대화 그림자 자료 수집

상태: 진행 중 — `GR31_COLLECTING`

사전등록 커밋: `55fc9dfd50155435c060ed542820e0a6a386092d`

## 질문

답변과 기존 기억을 바꾸지 않는 그림자 모드에서, 실제 Anima 대화가 사람 검토를 시작할 만큼
충분한 기간과 수량으로 모이는가?

## 변경 전 실제 흐름

- `GATE-RUNTIME-2`의 관리 DB에는 사용자 발화 13개·고유 12개·활동일 1일·세션 1개뿐이었다.
- 기본 `AnimaUnified`는 모델별 상태와 기억은 `data/<model>`에 두지만 대화 기록과 자율 학습
  기록 일부는 저장소 공용 경로에 남겼다. 상시 수집에 쓰면 원문 실행 자료와 Git 배포 상태가
  섞일 수 있었다.
- 그림자 기능은 명시적 `--memory-gate-shadow`에서만 켜지며 답변·원문 저장·기존 검색을 거르지
  않는다.

## 고정 수집 방식

- 실제 수집 런타임은 `--data-root .local/gate-runtime3/data`를 사용한다. 원문 DB와 그림자 기록은
  Git 및 HF 보관 대상 밖에 둔다.
- 공용 실행기는 `--data-root`를 주지 않은 기존 호출을 그대로 유지한다. 대화·자율 학습 기록도
  모델별 자료 경로를 사용해 여러 실행의 기록이 섞이지 않게 한다.
- 런타임은 로컬 `127.0.0.1:8765`에서 그림자 모드로 계속 실행한다. 별도 수집기는 15분마다 DB를
  읽기 전용으로 열어 원문 대신 행 지문과 건수만 기록하고, 같은 자료로 닫힌 판정기를 실행해
  `status.json`과 `verdict.json`을 함께 갱신한다.
- 수집 시작점은 빈 전용 DB다. 이후 기존 행의 수정·삭제를 허용하지 않고 새 행 추가만 허용한다.

## 자료 충분성 기준

- 사용자 발화 100개 이상, 고유 발화 90개 이상
- 활동일 7일 이상, 30분 간격 기준 세션 3개 이상
- 위 네 기준을 모두 채우기 전에는 선택 점수나 실제 안전성을 해석하지 않는다.

## 판정

- `GR30_INVALID`: 등록, 입력 모양, 기존 행 보존, 읽기 전용 검사 또는 원문 비노출 실패
- `GR31_COLLECTING`: 수집기는 정상이지만 하나 이상의 자료 기준 미달
- `GR32_READY_FOR_REVIEW`: 네 자료 기준을 모두 통과해 `GATE-RUNTIME-4` 사람 검토 가능

경계값은 통과로 센다. `GR32`도 저장 필터 적용 승인이 아니며 사람 검토를 시작할 조건일 뿐이다.
`GATE-RUNTIME-4`가 통과하기 전에는 `GATE-RUNTIME-5`와 그 뒤 `SWITCH-1 → REPLAY-1 → WORLD-1 →
AGENCY-1 → PCI-1`을 판정하지 않는다.

## 수집 시작 결과

- 로컬 Anima 런타임과 15분 수집기를 macOS 상시 서비스로 배포했다.
- 런타임 건강 검사: `http://127.0.0.1:8765` 응답 정상
- 시작 건수: 사용자 발화 0개, 고유 발화 0개, 활동일 0일, 세션 0개
- 시작 판정: `GR31_COLLECTING`
- 원문 DB·그림자 기록·상태는 `.local/gate-runtime3`에만 두며 Git과 HF 보관본에는 넣지 않는다.
- 상태 파일에는 원문 필드와 원문 문자열이 없고, 수집기 두 실행의 종료 상태는 0이었다.
- 최초 배포판은 상태 파일만 자동 갱신하고 판정 파일은 시작 시점에만 만들었다. 장기 수집이 기준을
  채워도 다음 단계 준비 상태가 자동 반영되지 않는 공용 흐름을 수정해, 매 수집마다 등록된 판정기를
  다시 실행하도록 했다. 수집 기준과 기존 자료는 바꾸지 않았다.
- 기존 Apple `faiss-cpu`의 `IndexFlatIP.search()`가 프로세스를 강제 종료하는 현상을 실제 검색
  검사에서 재현했다. 평면 인덱스를 그대로 복원해 같은 내적 순위를 NumPy로 계산하는 Apple
  경로로 공용 기억 검색을 고쳤다. 다른 운영체제에서는 기존 FAISS 검색을 유지한다.

아직 자료 기준을 하나도 채우지 않았으므로 선택 점수와 안전성은 해석하지 않는다. 실제 대화를
통해 네 수집 기준이 모두 충족된 뒤에만 `GATE-RUNTIME-4`를 시작한다.
