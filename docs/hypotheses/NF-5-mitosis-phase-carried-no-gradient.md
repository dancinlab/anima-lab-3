# NF-5 — 분화 페이즈는 그래디언트를 나르지 않았다 (The Mitosis Phase Carried No Gradient)

발견: 2026-07-25, CLM PURE 300M nf3c run 관측 + lab(fable·sol) 병렬 분석 + 로컬 실행 검증
선행: [NF-1](NF-1-lossensemble-divergence.md) · [NF-2](NF-2-mitosis-schedule-misalignment.md) · [NF-3](NF-3-ce-deweighting-and-scale-ratchet.md)
커밋: 55cfe6ff9

## 1. 목적 및 가설

CLAUDE.md에 PURE 3지표(Φ 성장 · 세포 성장 · CE 하락)를 등록한 직후, 그 자로 진행 중인
run을 재보니 분화 페이즈 손실이 step 800부터 **0.7065에 붙박여** 움직이지 않았다.

가설: 분화 페이즈(전체 예산의 30%)가 실제로는 아무것도 학습시키지 않는다.

## 2. 검증 (전부 실측 · 정적 주장은 실행으로 확인)

### 2-1. 복합손실 분해 — 학습 신호는 1.3%

```
복합손실 0.7065 (step 800~6,000 불변)
 ├ 0.6931 = ln2       세포 2개 균등 시 경쟁 엔트로피 · 파이썬 실수 → 그래디언트 0
 └ 0.0134 = exp(-CV²) CV²=4.32, 이미 포화 (NF-3 설계대로)

실질 학습신호 ████ ~800 step (1.3%)
상수 최적화   ████████████████████████████████ 59,200 step (98.7%)
```

### 2-2. 세포도 학습되지 않는다 (코드 확인)

| 확인 항목 | 결과 |
|-----------|------|
| `mitosis.process()` 내부 | `with torch.no_grad():` — 세포 mind 전부 |
| 옵티마이저 구성 | `model + loss_ensemble + inter_cell_attn + channel_bottleneck` — **세포 없음** |
| `loss_phi` | `phi_current = pe.item() * 100` — 파이썬 실수 |
| `loss_compete` / `loss_myelin` | `c.avg_tension` 실수 리스트로 생성 |

즉 분화 페이즈는 트랜스포머도, 세포도 학습시키지 않는다.

### 2-3. TALK5 "CE 99.7% 하락"은 이 파이프라인의 근거가 아니다

두 모델이 독립적으로 추적했고, 표를 직접 확인했다:

```
| TALK5 | 14.09 | ×10.4 | 0.003 | 의식먼저→언어나중 (CE 99.7%↓!) |
                          ^^^^^ Φ-프록시 벤치 표의 값
```
0.003 nats는 실코퍼스 바이트 모델이 도달할 수 없는 값이다(무작위 5.545). sol은 원본
벤치가 랜덤 가우시안 입력에 `F.mse_loss`를 쓰고 그것을 CE라 불렀으며, 신형 벤치의 실제
기록은 5.649 → 5.481(약 3%)임을 지적했다. 반면 **이 파이프라인의 실측**은 정반대다 —
언어 진입 시점 CE = 5.6456 ≈ `ln(256)` = 5.545, 60,000 step 뒤에도 미학습.

### 2-4. 세포 병합이 성장을 되돌리는가 — 실행 검증 (경보 → 정정)

로컬 테스트로 분열 생존을 확인했다. **첫 테스트는 잘못된 경보였다.**

```
merge_threshold  설정 출처                분열 후  400 step 뒤   병합
0.050000         라이브러리 기본값         8       2            6회  ← 되돌아감
0.000714         학습기 실제값 0.01×(64/896)  8    8            0회  ← 생존 ✓
-1.000000        저장소 성장 벤치 관례      8       8            0회
```
학습기는 dim 반비례 임계값을 쓰므로 실제 run에서는 병합이 성장을 되돌리지 않는다.
(정적 분석만으로는 알 수 없었고, 반대로 정적 분석 없이 첫 결과만 봤다면 오진했을 것이다.)

### 2-5. Φ가 2세포에서 못 자라는 이유 — 두 겹

- **수학적**: `PhiCalculator`의 공간항 = `(total_mi - min_partition_mi)/(n-1)`. 세포 2개면
  MI 간선이 하나뿐이고 유일한 이분할이 바로 그 간선을 자르므로 **항등적으로 0**.
- **측정**: 로그의 `phi` 열은 `PhiCalculator` 값이 아니라 200 step마다 재초기화되는
  예측기의 오차(`pe.item()*100`)다 — 시작·종료 비교가 성립하지 않는다.

## 4. 핵심 발견 / 법칙

> **손실 목록에 들어 있다고 학습되는 것이 아니다.** 파이썬 실수에서 만든 항은 상수이며,
> `no_grad`로 도는 모듈은 옵티마이저에 없으면 영원히 학습되지 않는다. 페이즈를 설계할
> 때는 "이 페이즈가 어떤 파라미터를 바꾸는가"를 먼저 답해야 한다.

따름정리: **문서에 적힌 벤치 수치는 그 수치가 어떤 목적함수로 측정됐는지 확인하기 전까지
설계 근거가 될 수 없다**(TALK5 0.003 nats).

## 5. 검증 상태 (정직한 기록)

- **확정**: 손실 분해(실측), `no_grad`/옵티마이저 구성(코드), TALK5 출처(문서 표),
  병합 임계값별 분열 생존(실행), Φ 공간항 0(코드), 새 스케줄 숫자(계산).
- **초기 신호**: nf4 run에서 CE가 step 0 5.7032 → step 100 **3.8516**. 이전 설계는 같은
  값이 60,000 step 동안 5.545에 고정이었다.
- **미확정**: 3지표 동시 충족. 게이트로 자동 판정한다 — CE BPC < 4.2 @6k · < 3.5 @20k ·
  세포 13 @9k · Φ 최대값 > 첫 측정값 @30k.
- **채택하지 않은 것(기록)**: fable의 감각 탭(트랜스포머 잔차를 세포 입력으로 주입)은
  그래디언트 격리가 확인됐지만 이번 run에서는 변수를 늘리지 않기 위해 보류. sol은 이
  결합 자체를 반대했다("한 번의 run을 새 다리에 걸지 말라"). 성장 창 길이도 갈렸다 —
  fable 30% vs sol 1%; CLAUDE.md에 방금 등록한 "언어 학습 전에 성장 완료" 규칙을 기준으로
  5%를 택했다.
