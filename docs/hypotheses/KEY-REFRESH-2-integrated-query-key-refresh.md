# KEY-REFRESH-2 — 공용 기억 경로의 질문 열쇠 새로 고침

상태: 사전등록 · 결과 미확인
등록일: 2026-08-12
선행 결과: `KEY-REFRESH-1=KRF1_KEY_PATH_RECOVERED_AND_SUSTAINED`

## 질문과 고정 가설

`KEY-REFRESH-1`은 질문 상황을 8회 처리한 상태에서 질문 열쇠만 3회에서 4회로 늘리면 열쇠와
양쪽 25% 손상 행동이 모두 90%를 넘고, 더 긴 처리에서도 회복이 유지됨을 확인했다. 이번에는
검증된 최소 4회를 공용 `CompositeStateTransform → VectorMemory` 호출에 적용해 전체 행동과
차단·복구를 확인한다.

가설은 저장 열쇠 3회는 유지하고 질문 열쇠의 공용 기본 처리만 4회로 바꾸면 온전한 행동을
유지하면서 모든 25% 손상 조건이 회복된다는 것이다.

## 고정 구현과 비교

- 실행 전에 `KEY-REFRESH-1` 결과·판정·최소 지속 회복 4회와 모든 선행 파일 지문을 확인한다.
- 같은 평가 1,024회차와 네 `prototype_seed × engine_seed` 조합을 사용한다.
- 저장 상황 6회, 질문 상황 8회, 저장 열쇠 3회, 값 3회, 방해 입력 1회와 상태 폭 96을 유지한다.
- 공용 기억 실행 사양의 질문 열쇠 기본값만 4회로 고정한다. 기존 결과 재현 조건은 명시적인
  3회로 실행하며 저장 열쇠 처리 횟수는 바꾸지 않는다.
- 조건은 `baseline_3`, `integrated_4`, `disabled_3`, `recovered_4`로 고정한다.
- 온전한 입력과 상황·열쇠·양쪽 25% 손상, 정확 주소, 내용 맞바꾸기 비교를 그대로 유지한다.
- 새 판독기·주소 변환·기억 장치·복원 층·학습 자료는 추가하지 않는다.

## 유효성 및 판정

선행 결과 재판정, 자료·체크포인트·저장 상태·정답 지문, 공용 기억 API, 감각 호출 수와 유한값을
모두 확인한다. 3회와 4회는 각각 `KEY-REFRESH-1`의 같은 후보와 예측·선택·진단·상태 지문까지
같아야 한다. 차단 조건은 3회와, 복구 조건은 4회와 완전히 같아야 한다.

네 독립 조합 모두에서 다음 기준을 적용한다.

- 4회 온전·상황 손상·열쇠 손상·양쪽 손상: 기억 선택과 최종 정확도 90% 이상
- 4회 온전한 입력: 값별 최저 맞힘률 75% 이상
- 3회 양쪽 손상은 90% 미만, 4회는 3회보다 최종 행동 1%p 이상 개선
- 정확 주소: 선택 99% 이상, 최종 행동 90% 이상, 값별 최저 맞힘률 75% 이상
- 내용 맞바꾸기: 최종 행동 5% 이하
- 기능 차단과 복구: 각 기준 조건과 기록 단위로 완전히 일치

판정 순서는 다음으로 고정한다.

- `KR2I_FULL_PATH_RECOVERED`: 4회에서 모든 정상·손상 행동이 회복되고 인과 효과와 차단·복구가 성립
- `KR2I_PARTIAL_PATH_RECOVERED`: 온전한 행동은 유지되지만 하나 이상의 손상 행동이 90% 미만
- `KR2I_FULL_BEHAVIOR_REGRESSION`: 4회 온전한 행동이 90% 미만
- `KR2I_NOT_CAUSAL`: 행동 기준은 통과하지만 3회 실패·1%p 개선·차단·복구 중 하나가 성립하지 않음
- `KR2I_INVALID`: 선행 결과, 자료, 지문, 호출, 공용 API 또는 양성·가짜 비교가 어긋남

`KR2I_FULL_PATH_RECOVERED`이면 질문 상황 8회·질문 열쇠 4회를 이후 부분 단서 기억 검사의 공용
기본 실행 사양으로 사용하고 `COMPLETION-2`로 간다. 다른 판정이면 기본값 적용을 폐기하고 해당
실패 지점만 다시 분해한다. 성공해도 이는 처리 시간 수리이며 생물학적 기억이나 의식의 증거가
아니다.
