# CAPACITY-1 — 안정 주소의 사건 수 경계

상태: 사전등록  
등록일: 2026-08-10  
선행 결과: `SEPARATION-1=S0_INVALID`, `EPISODE-2=E2I_PATH_RECOVERED_NOT_UNIQUE`

## 질문

`SEPARATION-1`의 서로 다른 열쇠 양성 비교는 사건 네 개에서 등록 기준을 통과하지 못했다. 같은
공용 기억 경로가 사건 두 개와 세 개에서는 정상인지, 그리고 최초로 무너지는 사건 수가 어디인지
확인한다.

이번 검사는 닮은 사건을 분리하는 새 기능을 추가하지 않는다. `EPISODE-2`에서 검증한 얼린 안정
주소, 기존 `VectorMemory`, 값 상태 판독과 `SEPARATION-1`의 감각 순서를 그대로 사용하고 회차당
사건 수만 2·3·4로 바꾼다. 통과해도 일반 기억보다 고유하거나 의식의 증거라는 뜻은 아니다.

## 실행 흐름

- 각 회차에 `상황 → 열쇠 → 값` 사건을 2개, 3개 또는 4개 차례로 감각한다.
- 한 회차의 열쇠·값·상황은 서로 다르며 질문 위치는 모든 사건 위치에 정확히 균형화한다.
- 방해 입력 두 개 뒤 질문 열쇠를 다시 감각하고 해당 위치의 값을 복원한다.
- `KEY-1`의 seed별 얼린 `StableKeyProjector`를 기존 `VectorMemory(key_transform=...)`에 연결한다.
- 같은 내부 상태에서 변환을 끈 원시 주소와 정확한 원-핫 열쇠 주소를 함께 비교한다.
- 내용 한 칸 맞바꾸기와 정상 연결 복구를 각 사건 수에서 수행한다.
- 모든 팔은 같은 회차 자료와 사건 수·seed별 전용 난수를 사용한다.

## 고정 사양

- seed: `1337 / 7331`
- 사건 수: `2 / 3 / 4`
- 평가 회차: 사건 수별·seed별 `1,536`
- 열쇠·값·상황 종류: 각각 `8`
- 방해 입력: `2`
- 주소 변환: `KEY-1` seed별 폭 32 얼린 선형 변환
- 기억: 기존 `VectorMemory(capacity=사건 수)`, cosine top-1
- 상태 특징 폭·감각 단계·값 원형: `EPISODE-1`과 동일
- 셀 수: 엔진의 등록 범위 2~48, 주소 입력은 기존과 같은 셀 평균
- 장치: CPU

1,536회차는 `값 8 × 열쇠 8 × lcm(2,3,4)=12`의 두 배라 모든 사건 수에서 목표 값, 질문
위치와 질문 열쇠가 정확히 균형을 이룬다. 모든 seed·회차·팔·문턱과 자료 생성 seed는 구현 단계의
`measurement/capacity_registry.py`를 단일 기준으로 고정한다. 그 파일의
`preregistration_commit`은 README와 이 문서를 먼저 고정한 Git 커밋을 가리켜야 한다.

## 사건 수별 비교

1. `stable_distinct_normal`: 기존 얼린 안정 주소를 공용 기억 경로에서 사용
2. `raw_distinct_control`: 주소 변환을 끈 원시 내부 주소 사용
3. `exact_key_control`: 정확한 원-핫 열쇠 주소를 같은 `VectorMemory`에 사용
4. `exact_key_partner_swap`: 저장 내용을 한 칸 돌려 열쇠와 값의 원인을 끊음
5. `exact_key_recovered`: 정상 연결을 새 기억에 다시 저장해 복구

각 팔에는 최종 정확도, 저장 위치 선택 정확도, 값별 재현율, 올바른 값 상태 판독, 기억 API와 직접
cosine 선택의 일치율, 주소 여유를 기록한다. 안정 주소는 회차마다 `사건 수 + 1`번만 변환되어야
하며 평가 전후 가중치가 같아야 한다.

## 무효 조건

- 사전등록 뒤 seed·회차·사건 수·팔·문턱·자료 생성 방식을 결과에 맞춰 바꿈
- `EPISODE-2` 판정·결과·주소 변환·값 원형 파일의 SHA-256 지문이 달라짐
- 주소 변환이나 값 원형을 새로 학습하거나 평가 중 가중치가 바뀜
- 회차 지문이 중복되거나 목표 값·질문 위치·질문 열쇠 균형이 맞지 않음
- 한 사건 수라도 정확 주소의 선택 정확도가 99%, 최종 정확도가 90%, 값별 최저 재현율이 75%
  미만
- 한 사건 수라도 내용 한 칸 맞바꾸기가 5% 초과 또는 복구 예측 일치가 100% 미만
- 기억 API가 직접 cosine top-1 선택과 한 회차라도 다름
- 셀 수·주소 폭·변환 호출 수가 등록 범위를 벗어남
- seed·사건 수·팔·필수 수치가 빠지거나 NaN·무한값이 있음

## 사건 수 통과 기준

한 사건 수는 두 seed 모두 다음을 만족할 때만 통과한다.

- 안정 주소 저장 위치 선택 정확도 90% 이상
- 안정 주소 최종 정확도 90% 이상
- 안정 주소 값별 최저 재현율 75% 이상
- 올바른 저장 내용의 값 판독 정확도 90% 이상

## 사전 판정

- `C1_CAPACITY_AT_LEAST_4`: 2·3·4개가 모두 통과
- `C2_CAPACITY_BOUNDARY_3`: 2·3개는 통과하고 4개는 실패
- `C3_CAPACITY_BOUNDARY_2`: 2개는 통과하고 3·4개는 실패
- `C4_CAPACITY_BELOW_2`: 2·3·4개가 모두 실패
- `C5_NON_MONOTONIC`: 작은 사건 수가 실패한 뒤 더 큰 사건 수가 다시 통과
- `C0_INVALID`: 원본·지문·얼림·자료·양성 비교·가짜 비교·복구 조건 중 하나라도 무효

판정 우선순위는 `C0 → C5 → C1 → C2 → C3 → C4`다. `C1`이면 새 구조를 추가하지 않고
`SEPARATION-1`의 같은 열쇠·다른 상황 주소 문제로 돌아간다. `C2`나 `C3`이면 첫 실패 사건 수의
시간별 주소 여유와 질문까지의 지연을 분해한다. `C4`면 `EPISODE-2`와 이번 감각 순서의 차이를
먼저 분해한다. `C5`면 용량 결론을 내리지 않고 더 큰 독립 회차로 비단조 결과를 재검증한다.

결과를 본 뒤 사건 수, 회차 수, 문턱, seed나 가중치를 조정하지 않는다.
