# CUE-ALIGN-1 — 저장·질문 상태의 공통 좌표 정렬

상태: 완료 · `CA4_NONLINEAR_OR_EPISODE_SHIFT`
등록일: 2026-08-11
선행 결과: `CUE-CONTEXT-1=CC3_QUERY_REFIT_INSUFFICIENT`

## 질문과 고정 가설

`CUE-CONTEXT-1`은 같은 회차·같은 상황인데도 저장 시점과 질문 시점의 상태 유사도가 약
`0.599`까지 낮아지고, 기존 손상 대응 판독기의 25% 손상 정확도가 `97.17~97.27%`에서
`89.16~89.94%`로 떨어짐을 확인했다. 질문 상태를 판독기에 더 넣는 방식은 손상 질문 정확도를
`78.71~80.57%`까지 오히려 낮췄다.

이번 고정 가설은 질문 상태가 상황 정보를 잃은 것이 아니라, 처리 이력 때문에 저장 상태와 다른
공통 좌표로 이동했다는 것이다. 행동 정답이나 상황 범주를 쓰지 않고 같은 회차의 `질문 상태 →
저장 상태` 쌍만으로 하나의 결정형 선형 정렬을 맞춘다. 별도 평가 회차의 질문 상태를 저장 좌표로
옮긴 뒤 기존 `CUE-ROBUST-1` 상황 판독기가 다시 읽을 수 있는지 검사한다.

공통 정렬이 실패하면 시간 변화가 상황 범주마다 다른지 진단한다. 이 진단은 실제 정답 범주로 여덟
정렬 중 하나를 고르는 상한 비교이므로 공용 기능으로 쓸 수 없고, 원인 위치만 판정한다.

## 고정 구현과 비교

- `CUE-CONTEXT-1` 결과·판정·정렬 전 판독 체크포인트와 그 상위 체크포인트 지문을 실행 전에
  확인한다.
- 학습은 그 실험의 512회차와 두 엔진 시작값에서 모은 1,024개 저장·질문 상태 쌍을 그대로
  재사용한다. 평가는 겹치지 않는 기존 1,024회차와 네 원형/엔진 조합을 그대로 쓴다.
- 상황 처리 6회, 사건 16개, 감각 순서, 열쇠·값·방해 처리 횟수, 상태 폭 96, 평가 가림표와 기존
  판독기를 바꾸지 않는다.
- `global_affine`은 질문 상태 96개와 상수항 하나에서 저장 상태 96개를 예측하는 하나의
  `canonical_ridge` 선형 변환이다. 범주 라벨과 행동 정답을 입력으로 받지 않는다.
- 온전한 쌍과 같은 위치를 25% 가린 질문·저장 쌍을 1:1로 함께 사용한다. 새 가림표는
  `CUE-CONTEXT-1` 학습 가림표와 같고 평가 가림표와 완전 일치가 0개여야 한다.
- `category_oracle`은 같은 방식의 정렬을 상황 범주별로 여덟 개 맞춘 진단 상한이다. 평가 때 실제
  범주로 정렬을 고르므로 통합 후보가 아니며, 공통 정렬 실패의 모양만 구분한다.
- `wrong_pair`는 각 질문 상태를 다음 상황 범주의 저장 상태와 결정형으로 잘못 짝지어 같은
  방식으로 맞춘 가짜 비교다. 정상 정렬과 같은 행 수·계산량을 사용한다.
- 정렬 전 `source`, 공통 정렬, 범주별 상한, 가짜 비교에 대해 온전한 질문과 25% 손상 질문의
  범주 정확도·범주별 최저 맞힘률·저장 쌍 유사도·잔차를 기록한다.
- 같은 입력 재맞춤, 행 역순 재맞춤, 독립 전체 재실행에서 체크포인트와 결과가 같아야 한다.
- 공용 기억 기본값, 판독기, 주소 폭, 처리 횟수, 비선형 복원, 주의집중은 이번 실험에서 바꾸지
  않는다.

## 유효성 및 판정

자료·시작값·회차 쌍·라벨 균형·상태 모양·감각 호출 수·가림표·원본 지문·선행 결과 재현·결정성이
등록값과 맞아야 한다. 정렬 학습과 평가는 회차 지문이 0개 겹쳐야 하며, 모든 정상 정렬은 유한한
값만 출력해야 한다. `global_affine` 학습 입력에 범주 라벨이나 행동 정답이 들어가면 무효다.

통과 기준은 네 평가 조합 모두에 적용한다.

- 온전한 질문: 범주 정확도 90% 이상, 범주별 최저 맞힘률 75% 이상
- 25% 손상 질문: 범주 정확도 90% 이상, 범주별 최저 맞힘률 75% 이상
- 공통 정렬은 정렬 전보다 손상 질문 정확도를 2%p 이상 개선해야 한다.
- 잘못 짝지은 가짜 정렬은 온전한·손상 질문 정확도 모두 25% 이하여야 한다.
- 범주별 상한은 원인 분해용이며 공용 성공 판정으로 쓰지 않는다.

판정 순서는 다음으로 고정한다.

- `CA1_COMMON_ALIGNMENT_VALID_NOT_UNIQUE`: 공통 정렬이 온전한·손상 질문 기준과 최소 개선 폭을
  모두 통과한다.
- `CA2_CATEGORY_DEPENDENT_WARP`: 공통 정렬은 실패하지만 범주별 상한은 온전한·손상 질문 기준을
  모두 통과한다.
- `CA3_FULL_ONLY_ALIGNMENT`: 공통 정렬은 온전한 질문만 통과하고 손상 질문은 실패한다.
- `CA4_NONLINEAR_OR_EPISODE_SHIFT`: 공통 정렬과 범주별 상한이 모두 실패한다.
- `CA5_NO_ALIGNMENT_GAIN`: 공통 정렬이 손상 질문 기준을 통과해도 정렬 전 대비 2%p 개선하지
  못한다.
- `CA0_INVALID`: 원본·자료·호출·쌍·가림표·결정성·선행 결과·가짜 비교 중 하나라도 어긋난다.

`CA1`이면 같은 공통 정렬만 공용 기억 호출에 선택적으로 연결하는 `CUE-ALIGN-2`를 진행한다.
`CA2`이면 범주를 모른 채 쓸 수 있는 하나의 공통 정렬로는 해결할 수 없으므로 범주별 잔차가
어디서 갈리는지 분해한다. `CA3`이면 정렬보다 가림 좌표 표현 문제를 먼저 다룬다. `CA4`이면
비선형 층을 만들기 전에 회차별 처리 이력과 상태 성분을 더 분해한다.

어떤 성공 판정도 생물학적 기억 복원이나 의식을 증명하지 않는다. 이는 같은 정보의 두 내부
표현을 표준 선형 변환으로 맞출 수 있는지 보는 일반 기억 진단이다.

결과를 보기 전 이 문서와 README를 커밋하고, 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 실행과 결과

사전등록 커밋은 `407384ca3`, 실행기와 닫힌 판정기 커밋은 `d03be3b71`이다. 등록한 1,024개
학습 쌍에 온전한 상태와 같은 위치를 25% 가린 상태를 1:1로 붙여 2,048행으로 맞췄다. 공통
정렬은 범주 라벨을 받지 않았고, 범주별 상한과 잘못 짝지은 비교에만 진단 라벨을 사용했다.

별도 평가 회차 결과는 다음과 같다. 같은 엔진 시작값을 공유하는 원형 시작값 두 조합은 완전히
같았으므로 범위는 두 독립 엔진 시작값을 나타낸다.

| 비교 | 온전한 질문 정확도 / 최저 범주 맞힘률 | 25% 손상 질문 정확도 / 최저 범주 맞힘률 |
|---|---:|---:|
| 정렬 전 기존 판독 | 96.19~96.48% / 89.84~91.41% | 89.16~89.94% / 82.03~82.81% |
| 하나의 공통 정렬 | 85.55~86.33% / 71.88~72.66% | 78.61~79.00% / 69.53~70.31% |
| 실제 범주를 알려 준 진단 상한 | 94.73~95.31% / 80.47~82.81% | 90.14~90.23% / 69.53~71.88% |
| 잘못 짝지은 비교 | 5.18% | 4.98~5.27% |

공통 정렬은 저장 상태와 질문 상태의 평균 유사도를 온전한 입력에서 약 `0.599 → 0.688`, 손상
입력에서 약 `0.598 → 0.614~0.615`로 높였다. 평균 제곱 오차도 온전한 입력은 약
`0.244 → 0.140`, 손상 입력은 약 `0.183 → 0.130`으로 줄였다. 하지만 기존 판독기가 사용하는
범주 경계를 보존하지 못해 실제 정확도는 정렬 전보다 `10.64~11.33%p` 낮아졌다.

범주별 상한은 평균 정확도만 보면 손상 질문에서 90%를 넘었지만, 가장 약한 범주의 맞힘률이
`69.53~71.88%`여서 등록 기준 75%를 통과하지 못했다. 따라서 하나의 공통 이동만의 문제도,
범주마다 다른 하나의 고정 이동만의 문제도 아니다. 잘못 짝지은 비교는 등록 상한 25%보다 크게
낮아 상태 쌍 대응 통제가 작동했다.

학습 512회차와 평가 1,024회차의 지문은 0개 겹쳤고 학습·평가 가림표도 완전 일치가 0개였다.
모든 정렬은 같은 입력 재맞춤과 행 역순 재맞춤에서 같은 체크포인트를 만들었다. 정상 실행과 별도
경로의 독립 전체 재실행은 결과 JSON SHA-256
`c3c94d5e29e63bf9d5e8713af3c6b1f23d77960b6b8b32c9b6c2e48563718ee6`, 판정 JSON
`9ed4ee51b06df9ffeac9a411322f10f566337d27a96f611ff8f701d6df37d563`로 바이트 단위까지 같았다.
정렬 체크포인트 SHA-256은
`271c6a26256e3473cf3db5afbb362f8486b783e6fc0997c888b099175bb11738`이다.

## 판정과 의미

판정은 `CA4_NONLINEAR_OR_EPISODE_SHIFT`다. 저장·질문 상태의 전체 거리를 줄이는 표준 선형
정렬은 가능했지만, 실제 기억 판독에 필요한 범주 경계를 함께 보존하지 못했다. 실제 범주를 미리
알려 준 여덟 개의 정렬도 모든 범주를 회복하지 못했으므로 범주별 고정 뒤틀림만으로도 설명할 수
없다. 공용 기억 기본값과 판독기는 바꾸지 않았다.

다음은 `CUE-HISTORY-1`이다. 같은 상황과 같은 가림표를 유지한 채 질문 전에 처리한 사건 순서와
방해 입력 이력만 맞바꿔, 약한 범주의 변화가 회차별 처리 이력에 묶이는지 먼저 분해한다. 그
전에는 비선형 복원 층이나 주의집중을 추가하지 않는다.

이 결과는 처리 이력에 따른 일반적인 내부 표현 변화이며 생물학적 기억 복원이나 의식의 증거가
아니다. 결과·판정·정렬 체크포인트는 비공개 Hugging Face 조직 보관소
`dancinlab/anima-lab-research-archive`의 `cue-align1-storage-query-alignment` revision에
보존했다. Hugging Face 커밋은 `9290a02208671b8631dcdcbbcb0446f0daaf53ed`, manifest
SHA-256은 `d86f4dc8d57f1b21c7ef28a38b46583002d29dde3636e144c5277f80222cb2dd`다. 새 임시
디렉토리로 다시 내려받아 세 산출물과 manifest를 전수 확인했다.
