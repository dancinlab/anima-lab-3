# COMPONENT-1 — 상황·열쇠 주소의 위치별 안정성 분해

상태: 완료 · `AC3_BOTH_COMPONENTS_LOSS`
등록일: 2026-08-11
선행 결과: `CONJUNCTION-2=CJ2_2_COMPONENT_COLLISION`

## 질문과 흐름

기존 폭 32 상황 변환과 폭 32 열쇠 변환 중 어느 성분이 16개 사건의 긴 감각 흐름에서 같은 종류를
같은 주소로 유지하지 못하는가?

- 선행 평가와 겹치지 않는 512회차, 엔진 시작값 1337·7331을 사용한다.
- 각 회차의 16개 사건에서 상황 상태와 열쇠 상태를 처리 위치 1~16별로 각각 수집한다.
- `CONTEXT-2`의 얼린 상황 변환과 결정형 열쇠 변환을 다시 맞추지 않는다.
- 각 변환의 기존 분류 출력으로 종류 8개를 읽고 위치별 혼동표와 종류별 맞힘률을 기록한다.
- 질문 시점 상태도 별도로 기록하지만 위치 판정에는 저장 사건만 사용한다.
- 값 변환, 기억 저장·검색, 결과를 본 뒤 문턱 조정은 하지 않는다. 장치는 CPU다.

## 유효 조건과 판정

- 선행 자료·판정·두 주소 체크포인트 지문 일치
- 512회차 고유성, 위치마다 상황·열쇠 상태 512개, 두 엔진 시작값의 같은 자료 사용
- 상태 폭 96, 주소 폭 32, 종류 8개와 유한값 유지
- 위치별 정확도 90%, 종류별 최저 맞힘률 75% 이상이면 해당 성분 위치 통과
- 주소 변환은 평가 전후 얼린 상태이고 가중치가 같음

사전 판정은 `AC1_CONTEXT_LOSS`, `AC2_KEY_LOSS`, `AC3_BOTH_COMPONENTS_LOSS`,
`AC4_COMPONENTS_STABLE`, `AC0_INVALID`다. 하나라도 뒤 위치에서 실패하면 해당 성분 손실로 센다.
실패한 성분만 다음 결정형 위치 안정화 대상으로 삼는다. 어떤 판정도 의식 증거가 아니다.

결과를 보기 전 이 문서와 README를 커밋하고 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 결과와 판정

사전등록 커밋은 `23078054b`, 실행기 커밋은 `2d8704cb4`다. 두 엔진 시작값 모두 상황 주소는
1~8번째를 100% 읽었지만 9번째 `50.6~50.8%`, 13번째 `24.8~25.2%`로 무너졌다. 같은 상황을
연속 처리한 다음 위치에서는 다시 회복돼 상황 전환 직후 상태에 취약했다.

열쇠 주소는 1~3번째 100%였고 5번째 `92.2~92.6%`부터 종류별 최저 맞힘률이 문턱 아래로
내려갔다. 16번째 정확도는 `74.4~76.0%`, 최저 맞힘률은 `18.9~30.2%`였다. 판정은
`AC3_BOTH_COMPONENTS_LOSS`다. 다음 `COMPONENT-2`는 두 성분 모두를 위치가 섞인 독립 자료로
결정형 맞춤하고, 안정 값과 함께 원래 결합 기억까지 재검증한다.
