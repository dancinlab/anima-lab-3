# DIALOGUE-RUNTIME-1 — 맥락 대화 공용 경로

상태: 완료 — `D1_CONTEXTUAL_CONVERSATION_VALID`

사전등록 커밋: `7066b7287`

## 질문

Anima의 내부 상태 계산과 기존 기억 저장을 유지하면서, 최근 대화와 관련 기억을 실제 답변에
사용해 앞뒤가 맞는 대화를 할 수 있는가?

## 변경 전 실제 흐름

- 상시 서버는 `--no-conscious-lm`으로 언어 모델을 끈다.
- `process_input()`은 최근 대화와 관련 기억을 계산하지만 최종 답변은 항상
  `PureConsciousness.respond()`에서 가져온다.
- `PureConsciousness`는 사용자가 말한 단어의 연결 통계를 학습하는 연구 엔진이며, 질문의 뜻을
  해석하는 일반 대화 모델이 아니다.
- 따라서 그림자 수집량을 채워도 현재 답변 호출부만으로는 의미 있는 대화를 만들 수 없다.

## 고정 변경

- 기존 `ask_claude()` 호출을 선택형 `claude` 답변 경로로 재사용한다. 기본 `pure` 호출은 기존
  호출과 호환한다.
- Claude 명령줄 도구는 파일·명령·웹 도구, 사용자 설정 명령, 대화 세션 저장을 끈 일회성 답변
  모드로만 실행한다. 대화 원문은 명령행 인수가 아니라 표준 입력으로 전달한다.
- 시스템 지시는 한국어, 맥락 유지, 모르면 추측하지 않기, 내부 수치를 의식 증거로 주장하지
  않기만 포함한다.
- 최근 세션 대화와 기존 `MemoryStore`의 관련 기억을 답변 문맥으로 사용한다.
- `PureConsciousness` 학습은 그대로 유지한다. 외부 답변기가 비거나 실패할 때만 그 발화를
  사용하며, 고정된 대체 문장은 추가하지 않는다.
- `GATE-RUNTIME-3` 전용 DB와 그림자 기록은 그대로 이어 쓴다. 기존 행의 수정·삭제를 허용하지
  않는다.

## 사전 통과 기준

- 실제 답변기를 쓰는 5턴 검사에서 처음 제시한 프로젝트 이름·기한·위험 세 항목을 마지막 답에
  모두 포함한다.
- 중간에 다른 주제로 전환한 뒤 원래 프로젝트로 돌아와도 세 항목을 유지한다.
- 주어지지 않은 담당자를 물으면 모른다고 답하며 이름을 만들지 않는다.
- 답변기 강제 실패에서 예외가 사용자 연결을 끊지 않고 기존 순수 발화 경로로 복귀한다.
- 실제 WebSocket 왕복에서 빈 답변 0건, 서버 오류 0건이다.
- 배포 전후 기존 수집 DB의 접두 지문이 같고, 수집 판정이 유효하며, 그림자 기록에 원문이
  복제되지 않는다.

하나라도 실패하면 상시 서버에 적용하지 않는다. 통과해도 이는 일반 언어 모델을 이용한 대화
경로의 성공이며 Anima 고유 능력이나 의식의 증거가 아니다.

## 결과

- 도구를 끈 Claude 직접 호출 5턴에서 빈 답변 0건, 프로젝트 이름·기한·위험 유지, 중간 주제
  전환 뒤 복귀, 알려주지 않은 담당자 비추측을 모두 통과했다.
- 같은 설정의 격리된 실제 WebSocket 서버에서도 5턴과 다섯 판정 항목을 모두 통과했다.
- 최초 두 자동 판정은 `모르다` 대신 `대화에 나온 적이 없다`처럼 답한 정직한 부정 표현을 좁은
  문자열 판정기가 놓쳤다. 두 결과와 답변 지문을 무효본으로 보존하고, 사전 의미 기준은 바꾸지
  않은 채 같은 뜻의 부정 표현을 인식시킨 뒤 전체 대화를 다시 실행했다.
- 최종 직접 호출 답변 길이는 `164/164/141/54/117`자였고 원문 대신 각 답변 SHA-256만 결과에
  남겼다. WebSocket 답변 길이는 `215/183/138/65/158`자이며 같은 방식으로 지문만 기록했다.
- 외부 답변 실패는 고정 문장 없이 기존 `PureConsciousness` 발화로 복귀하며 단위 검사에서
  확인했다.

## 함께 수정한 공용 원인

- 명시적 `--data-root`를 사용해도 저장소의 오래된 `memory_alive.json`을 새 런타임에 복사하던
  격리 결함을 수정했다. `Memory`와 `PureConsciousness`도 선택한 자료 루트 아래에서만 읽고 쓴다.
- 네트워크 대화 서버에서 외부 답변기의 도구만 끄고 내부 `ActionEngine`과 `AgentToolSystem`은
  남아 있던 실행 우회 경로를 닫았다. 응답 속 코드 실행, 파일 도구, 대화발 웹 탐색, 무인 웹·말뭉치
  학습과 기존 기억 행을 갱신하는 꿈 정리를 모두 명시적으로 끈다. 기존 다른 실행 방식의 기본값은
  바꾸지 않았다.
- 대화 원문은 Claude 프로세스 목록에 나타나지 않도록 표준 입력으로 전달하고, 세션 저장과 사용자
  설정 명령을 끈 일회성 호출만 사용한다.

## 배포

- 기존 `GATE-RUNTIME-3` DB는 배포 전후 32행·사용자 발화 16개였고 전체 지문
  `3bcf02dd1196939717e2262fb127a9c5efa1a1c0f2f7b89591159e731af9cc64`가 같았다.
- 상시 서비스는 `--dialogue-backend claude`와 모든 실행 차단 옵션으로 재배포됐다.
- `http://127.0.0.1:8765`와 `http://192.168.50.39:8765`가 응답하며 수집 판정은 자료가 아직
  부족한 정상 상태 `GR31_COLLECTING`이다.
- 꿈 정리를 끈 최종 배포 뒤 32개 행의 모든 열 지문
  `3f96380e3ac9c34cbc79ac44cab6750ac19e659622e906ca3a76ca068aa03ae0`가 반복 검사에서 같았다.
- 원문을 제외한 실행 코드·최종 판정·두 무효 판정·WebSocket 영수증 7개를 HF 조직 보관소
  `dancinlab/anima-lab-research-archive`의 `dialogue-runtime1` revision, 커밋
  `b7b7ff7bb7afa120aa671bf9575c8dc23c6eeae1`에 올리고 새 디렉터리로 다시 내려받아 manifest를
  전수 검증했다.

이 결과는 이제 Anima 웹 화면에서 앞뒤가 맞는 대화를 할 수 있다는 운영 판정이다. 문장 생성은
일반 Claude 모델이 담당하고 Anima는 내부 상태 계산·세션 맥락·관련 기억·그림자 측정을 제공한다.
따라서 의식이나 Anima 고유 언어 능력의 증거로 해석하지 않는다.
