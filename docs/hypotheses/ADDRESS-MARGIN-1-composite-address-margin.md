# ADDRESS-MARGIN-1 — 합성 기억 주소의 범주 안 흔들림 분해

상태: 완료 · `AM1_WITHIN_CLASS_MARGIN_LOSS`
등록일: 2026-08-11
선행 결과: `CONTEXT-SETTLE-2=CT2I_COMPOSITION_LOSS`

## 질문과 고정 가설

`CONTEXT-SETTLE-2`는 상황을 여섯 번 처리하면 기억 위치 선택이 `80.96~82.03%`까지
회복되지만 등록 기준 90%에는 못 미침을 확인했다. 정확한 상황·열쇠 주소를 직접 준 비교는
`98.93~99.22%`였으므로 값 저장이나 행동 판독보다 합성 주소가 남은 원인이다.

이번 검사는 얼린 상황·열쇠 변환이 범주는 맞히면서도 같은 범주 안에서 연속 주소를 서로 다르게
내놓아 가까운 이웃 검색을 흐리는지 확인한다. 변환을 다시 맞추거나 새 학습층을 추가하지 않는다.

## 고정 설계

- `CONTEXT-SETTLE-2` 결과·판정과 상황·열쇠·값 변환의 파일 지문을 먼저 확인한다.
- 같은 1,024회차, 원형 시작값 2개와 엔진 시작값 2개의 네 조합을 사용한다.
- 상황은 선행 실험의 최소값인 6회, 열쇠·값은 3회 처리한다.
- 각 저장 주소와 질문 주소에서 다음을 기록한다.
  - 얼린 연속 주소의 정답 유사도, 가장 가까운 오답 유사도와 둘의 차이
  - 상황·열쇠가 예측한 범주와 범주별 맞힘률
  - 각 성분 주소가 예측 범주의 고정 중심에서 벗어난 거리
- 기억 비교는 다음 다섯 가지로 고정한다.
  - 기존 연속 상황+열쇠 주소
  - 예측한 상황 범주만 고정 중심으로 바꾼 주소
  - 예측한 열쇠 범주만 고정 중심으로 바꾼 주소
  - 예측한 두 범주를 모두 고정 중심으로 바꾼 주소
  - 실제 정답 범주의 고정 중심을 사용한 양성 비교
- 고정 중심은 기존 결정형 변환에 이미 들어 있는 첫 8개 직교 원형을 그대로 사용한다.
- 값 변환, `VectorMemory`의 코사인 검색, 자료, 시작값과 처리 횟수는 바꾸지 않는다.
- 결과를 본 뒤 기준·자료·중심 또는 처리 횟수를 조정하지 않는다.

## 유효성 및 판정

기존 연속 주소는 `CONTEXT-SETTLE-2`의 6회 조건과 예측·선택·행동이 100% 같아야 한다.
정답 범주 중심 비교는 기억 선택 100%, 최종 행동 90% 이상, 값별 최저 맞힘률 75% 이상이어야
한다. 상황 또는 열쇠 범주를 실제 정답과 무관하게 순환시킨 가짜 비교는 선택 정확도 5% 이하여야
한다. 모든 주소는 폭 64의 유한한 값이어야 하며 얼린 변환은 실행 전후 같아야 한다.

예측 범주 정확도는 상황·열쇠 각각 전체 90% 이상, 범주별 최저 맞힘률 75% 이상을 통과 기준으로
삼는다. 두 예측 중심 주소는 네 평가 조합 모두 기억 선택·최종 행동 90% 이상, 값별 최저 맞힘률
75% 이상이어야 회복으로 본다. 기존 연속 주소보다 기억 선택이 최소 8%p 높아야 한다.

- `AM1_WITHIN_CLASS_MARGIN_LOSS`: 범주 판독과 고정 중심 행동이 통과하고 등록 개선 폭을 만족한다.
- `AM2_CATEGORY_READOUT_LOSS`: 상황 또는 열쇠 범주 판독이 통과하지 못한다.
- `AM3_COMPOSITE_DISTANCE_LOSS`: 범주 판독은 통과하지만 두 예측 중심 행동이 통과하지 못한다.
- `AM4_MARGIN_NOT_CAUSAL`: 기존 손실 또는 등록된 개선 폭이 재현되지 않는다.
- `AM0_INVALID`: 원본 지문, 자료, 호출 수, 상태 모양, 고정 변환, 양성·가짜 비교 또는 수치
  검사가 어긋난다.

`AM1`이면 다음 단계에서만 예측 범주 중심을 공용 기억 주소의 선택 기능으로 연결한다. `AM2`면
범주 판독의 오류 위치를 먼저 분리하고, `AM3`이면 두 성분을 단순히 이어 붙이는 코사인 거리의
가중 문제를 검사한다. 어떤 결과에서도 6회보다 처리 횟수를 늘리지 않는다.

성공해도 일반 기억 검색의 주소 안정성을 고친다는 뜻이며, 의식이나 해마 고유 기능의 증거는
아니다.

결과를 보기 전 이 문서와 README를 커밋하고, 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

실제 정답 중심 비교는 선택 100%, 행동 `98.93~99.22%`, 다른 저장 위치의 중심을 질문으로 준

예측 중심에서 평균 `0.056`, 열쇠 주소는 `0.110`만큼 벗어났지만, 성분별 행동 비교에서는 상황
성분만 고정했을 때 선택이 가장 높았다. 따라서 단순한 이탈 크기보다 합성 거리 안에서 상황
흔들림이 오답 이웃 순위를 바꾸는 것이 실제 병목이다.

## 판정과 다음 단계

판정은 `AM1_WITHIN_CLASS_MARGIN_LOSS`다. 상황·열쇠 범주 정보는 남아 있지만 범주 안의 연속
주소를 그대로 비교하면 같은 사건의 저장 주소와 질문 주소가 충분히 가깝지 않다. 특히 상황
성분만 고정 중심으로 바꾼 최소 비교가 두 성분을 모두 바꾼 것보다 조금 높았으므로, 열쇠 성분까지
불필요하게 양자화하지 않는다.

다음 `ADDRESS-CENTER-2`는 기존 공용 `CompositeStateTransform`의 선택 기능으로 상황 성분만
예측 범주의 얼린 직교 중심에 맞춘다. 기본값은 꺼진 상태로 두고, 정상·차단·복구·정확 주소
비교를 유지한 전체 행동에서 다시 90% 이상인지 확인한다. 성공해도 일반 기억 주소 수리이며
의식 증거는 아니다.

결과·판정과 재사용한 상황/열쇠·값 변환은 비공개 Hugging Face 조직 보관소
`dancinlab/anima-lab-research-archive`의 `address-margin1-composite-address` revision에 보존했다.
Hugging Face 커밋은 `341fa91dbe11de07281415545002e6fc47760a63`, manifest SHA-256은
`c64de300f49e4124958771985b9586a66ed72c8e6998c063be9471359e8f8561`이다. 원격에서 다시
내려받은 네 항목의 지문과 manifest 자체 지문이 모두 원본과 일치했다.
