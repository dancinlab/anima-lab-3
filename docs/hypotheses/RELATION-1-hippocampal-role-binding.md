# RELATION-1 — 해마식 역할·내용 관계 묶기

상태: 중단 · `R0_INVALID`
등록일: 2026-08-10  
선행 결과: `SYNERGY-1=Y3_NOT_INTEGRATED`, `WORKSPACE-1=W3_NOT_INTEGRATED`

## 질문

두 `QuantumC` 모듈에 나뉘어 남아 있는 단서를, 각 단서의 역할과 함께 한 관계로 묶으면 최종
행동에 안정적으로 사용할 수 있는가?

WORKSPACE-1에서 두 단서는 셀 평균 뒤까지 98.4~100% 남았지만, 평균 문맥 하나를 반복 전달하는
공유 공간은 두 seed에서 함께 75%를 넘지 못했다. 따라서 이번 실험은 감각 엔진·연결 폭·반복
횟수를 바꾸지 않는다. 기존 `RecurrentWorkspaceBridge`의 폭 32 변환 뒤에 역할별 변환과 두
내용의 곱셈형 결합을 한 번 추가한다. 이는 행동 정답을 입력에 넣는 장치가 아니라, 어느 단서가
첫 번째 역할이고 어느 단서가 두 번째 역할인지 보존하는 최소 관계 읽기다.

## 결과 전에 고정한 구현

- 두 모듈은 기존 `QuantumC.get_phase_states()`와 공용 `ThalamicBridge`의 셀별 96→32 변환을
  그대로 사용한다.
- 각 모듈의 셀 평균에는 서로 다른 학습 가능 역할 변환을 적용한다.
- 두 역할·내용 코드는 원소별 곱과 원래 두 요약을 함께 폭 32로 되돌린다.
- 이 관계 코드 하나만 기존 `expand → sigmoid → 중심·크기 맞춤 → 고정 언어 모델` 흐름으로
  보낸다.
- 별도 감각 엔진, 새 언어 모델, 더 넓은 연결 다리, 반복 횟수 탐색, 행동 정답 지름길은 만들지
  않는다.

## 자료와 과제

두 역할에 각각 다섯 단서를 두고 25개 조합을 균등하게 만든다. 정답은
`(첫 역할 번호 + 2 × 둘째 역할 번호) mod 5`이며 행동은 `A/B/C/D/E`다. 각 역할의 단서 하나만
보면 다섯 정답이 같은 횟수로 나타나므로 우연 정확도는 20%다. 학습과 평가는 단어 목록과 조합은
같지만 `QuantumC` 초기 상태·방해 단어·지연 표본을 겹치지 않게 만든다.

seed는 기존 계열과 같은 `1337 / 7331`로 고정한다. 학습량·폭 32·언어 보존 손실은
WORKSPACE-1과 같게 유지한다. 실행 팔은 다음 네 개다.

- `quantum_workspace_2`: 관계 묶기 없는 기존 반복 공유 공간
- `quantum_relation`: `QuantumC` 상태에 역할·내용 관계 묶기 적용
- `memory_relation`: 같은 관계 묶기에 직접 감각 기억을 넣는 일반 비교
- `gru`: 같은 자료를 순서대로 읽는 표준 순환 기억층; 과제 자체가 풀리는지 확인하는 양성 비교

각 팔의 초기 난수는 팔 이름별로 고정해 팔 순서가 달라져도 변하지 않게 한다.

## 개입과 통과 기준

정상 입력 외에 첫 역할만, 둘째 역할만, 둘째 단서를 다른 예제와 짝짓기, 두 역할의 입력 맞바꾸기,
정상 복구를 검사한다.

관계 묶기 통과 조건은 두 seed 모두 다음을 만족하는 것이다.

- 정상 정확도 75% 이상
- 한 역할만 남긴 정확도 40% 이하
- 다른 예제와 짝지은 정확도 40% 이하
- 두 역할을 맞바꾼 정확도 40% 이하
- 정상과 가장 좋은 단일 역할 조건 차이 35%p 이상
- 정상 복구 정확도와 출력 점수가 원래 정상 계산과 완전히 같음
- 일반 문장의 출력 변화 0.5 nat 이하

표준 `GRU`는 정상 정확도 80% 이상과 같은 개입·언어 기준을 만족해야 전체 실험이 유효하다.
자료 균형, seed, 팔, 파일 지문, 유한 수치 중 하나라도 어긋나면 결과를 판정하지 않는다.

## 사전 판정

- `R1_BOUND_NOT_UNIQUE`: `QuantumC` 관계 묶기가 통과하지만 일반 비교보다 낫지 않음
- `R2_QUANTUM_ADVANTAGE`: 두 seed 모두 일반 비교 최고값보다 5%p 초과 우세
- `R3_NOT_BOUND`: `QuantumC` 관계 묶기가 두 seed에서 함께 통과하지 못함
- `R4_CONFOUNDED`: 행동 기준은 통과하지만 일반 문장 변화 기준 실패
- `R5_EXISTING_WORKSPACE_SUFFICIENT`: 관계 없는 기존 공유 공간도 두 seed에서 통과해 새 기능의
  필요성이 지지되지 않음
- `R0_INVALID`: 자료·양성 비교·등록 사양·복구·파일 지문 검증 실패

`R1`이나 `R2`일 때만 이 관계 묶기를 공용 실행 경로의 선택 가능한 정식 기능으로 유지한다.
`R3`이면 결과를 보고 층이나 폭을 더 붙이지 않고 중단한다. `R5`이면 더 단순한 기존 공유 공간을
선택한다. 성공해도 의식 증명은 아니며, 두 내부 경험의 역할 관계가 행동의 실제 원인이 된다는
근거까지만 뜻한다.

## 1차 본실험 무효와 역할 학습 수리 사전등록

1차 실행은 `R0_INVALID`다. 과제를 검증해야 하는 표준 `GRU`가 seed 1337에서 정상 24%,
일반 문장 변화 1.475 nat로 실패했다. seed 7331은 정상 100%였지만 역할 맞바꾸기 정확도가
46%로 등록 상한 40%를 넘었다. 따라서 `QuantumC` 관계 묶기의 성공·실패를 판정하지 않는다.
이 실행의 결과·로그·체크포인트는 삭제하지 않고 `relation1-invalid` 보관본으로 남긴다.

원인은 학습 자료와 난수 흐름에 있다. 모든 학습 예시는 A 단어가 첫 역할, B 단어가 둘째 역할에만
들어갔지만 평가에서는 두 내용을 맞바꿨다. 표준 비교층도 반대 역할의 단어를 학습한 적이 없으므로
이 조건은 역할 사용 검사가 아니라 처음 보는 입력 위치 검사가 됐다. 또한 표준 `GRU`는 선행
SYNERGY-1에서 검증된 `seed + 200,000` 대신 새 팔 목록의 `seed + 300,000`을 사용했다. 이는
WORKSPACE-1에서 이미 수리했던 팔 순서 난수 결함과 같은 종류다.

수리 실행은 새 구조나 새 기준을 추가하지 않는다.

- 매 학습 묶음은 네 정상 예시와 그 네 예시의 역할을 맞바꾼 사본으로 구성해 등록 배치 크기 8을
  유지한다.
- 맞바꾼 사본의 정답은 원래 정답이 아니라 등록 식의 `(B + 2 × A) mod 5`로 다시 계산한다.
  따라서 역할 정보는 가르치되 평가 정답을 입력으로 누출하지 않는다.
- 모든 팔에 같은 역할 균형 학습을 적용한다.
- `GRU` 난수는 선행 실험에서 검증된 `seed + 200,000`으로 복구한다. 다른 팔의 이름별 난수,
  800단계, 학습률, 자료, 구조, 개입, 판정 문턱은 바꾸지 않는다.
- 수리 코드를 Git에 고정한 뒤 네 팔·두 seed를 모두 새 `relation1-role-repair` 체크포인트에서
  처음부터 다시 실행한다.

수리 후에도 표준 `GRU`가 실패하면 추가 조정 없이 `R0_INVALID`로 중단한다. 통과하면 원래
등록한 R1~R5 판정을 그대로 적용한다.

## 역할 학습 수리 결과 — R0_INVALID, 중단

수리 실행은 등록된 네 팔·두 seed를 모두 새 체크포인트에서 800단계 완료했다. 파일 지문 8개와
판정 재실행은 일치했고, 자료 균형·역할 교환 정답 재계산·복구 계산도 등록 사양과 같았다.

하지만 과제 양성 비교인 표준 `GRU`의 정상 정확도는 seed 1337에서 35%, seed 7331에서 19%로
등록 문턱 80%를 모두 넘지 못했다. 일반 문장 변화도 각각 `0.0022 / 0.6222 nat`로 두 번째
seed가 상한 0.5를 넘었다. 따라서 수리 실행도 `R0_INVALID`이며 역할 묶기 효과를 판정할 자격이
없다.

참고 수치는 판정 근거로 승격하지 않는다. 관계 없는 기존 공유 공간은 정상 `18% / 20%`,
`QuantumC` 역할 묶기는 `19% / 19%`, 직접 기억 역할 묶기는 `45% / 20%`였다. 우연 기준은
20%다. `QuantumC` 관계 팔의 일반 문장 변화도 `2.7259 / 2.0255 nat`로 상한을 크게 넘었다.

정확한 결론은 **현재 5개 행동 역할 과제와 고정된 800단계 언어 연결 학습이 표준 비교층조차
안정적으로 학습시키지 못해, 해마식 역할·내용 묶기의 효과를 알 수 없다**는 것이다. 이는
`R3_NOT_BOUND`가 아니며 관계 묶기가 틀렸다는 증거도 아니다. 결과를 본 뒤 학습률·단계·난수를
더 고르는 일을 막기 위해 사전 중단 기준대로 세 번째 실행은 하지 않는다. `bind_roles`는 기본값이
꺼진 실험 기능으로만 보존하며 Anima 정식 실행 흐름에는 활성화하지 않는다.

1차 무효 실행과 수리 실행의 체크포인트 16개, 결과·판정·로그·SHA-256 목록 22개 항목은 비공개
HF 조직 보관소 `dancinlab/anima-lab-research-archive`의 `relation1-role-binding` revision에
보존했고, 다시 내려받아 전체 지문을 확인했다.
