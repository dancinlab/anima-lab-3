# CONJUNCTION-2 — 안정 값 표현을 사용한 상황·열쇠 결합 재검사

상태: 사전등록 · 실행 전
등록일: 2026-08-11
선행 결과: `VALUE-2=VT1_STABLE_VALUE_PATH_VALID_NOT_UNIQUE`

## 질문

`CONJUNCTION-1`은 정확 주소가 저장 위치를 100% 찾았지만 값 판독 양성 비교가 실패해 합성 주소를
판정하지 못했다. 시간에 안정적인 값 표현으로 양성 비교를 복구하면, 공용 상황+열쇠 주소가 두
부분을 함께 사용해 16개 사건 중 정답을 찾는가?

## 고정 흐름

- `CONJUNCTION-1`의 1,024회차, 질문 삼중 조합 균형, 4×4 라틴 정사각형과 네 평가 조합을 그대로
  쓴다.
- `CONTEXT-2`에서 얼린 폭 32 상황 변환과 폭 32 열쇠 변환, 두 부분의 같은 비중과 폭 64 합성
  주소를 다시 맞추지 않는다.
- `VALUE-2`의 폭 32 값 변환 체크포인트를 다시 맞추지 않고 공용 `VectorMemory.value_transform`에
  연결한다.
- 회차당 상황+열쇠 원시 입력 두 부분, 주소 변환 17회, 값 변환 16회, 저장 16회, 검색 1회다.
- 감각 흐름, 자체 갱신, 질문 순서, 장치 CPU와 파일 지문을 유지한다.

## 비교 조건

1. 공용 합성 주소 + 공용 안정 값 정상 조건
2. 장치 밖에서 같은 주소와 값을 변환한 기준
3. 공용 주소의 상황 부분만 가린 조건
4. 공용 주소의 열쇠 부분만 가린 조건
5. 정확한 상황+열쇠 주소 + 공용 안정 값 양성 비교
6. 정확 주소에서 상황만 남긴 비교
7. 정확 주소에서 열쇠만 남긴 비교
8. 변환 전 저장 내용을 한 값씩 돌린 가짜 비교
9. 정상 내용을 새 공용 기억에 다시 저장한 복구 비교
10. 값 변환을 끈 원시 값 비교

## 유효 조건과 문턱

- `CONJUNCTION-1` 자료·주소 체크포인트와 `VALUE-2` 결과·판정·값 체크포인트 지문 일치
- 1,024회차 고유성, 질문 512조합 각 2회, 16개 쌍 고유성과 행·열 값 균형 유지
- 정확 주소 + 안정 값: 선택 99%, 최종 판독 90%, 값별 최저 맞힘률 75% 이상
- 정상 합성 주소: 선택·최종 판독 90%, 값별 최저 맞힘률 75% 이상
- 상황 차단·열쇠 차단과 정확 한쪽 주소: 각각 최종 판독 35% 이하
- 공용 정상과 장치 밖 기준의 예측·선택 100% 일치
- 가짜 내용 5% 이하, 복구 예측과 기억 API 100% 일치
- 주소·값 변환은 평가 전후 얼린 상태이고 가중치가 완전히 같음
- 등록된 호출 횟수, 입력 수, 주소·값 폭 유지

## 사전 판정

- `CJ2_1_CONJUNCTION_VALID_NOT_UNIQUE`: 정상 합성 주소와 모든 통제 통과
- `CJ2_2_COMPONENT_COLLISION`: 정확 주소 양성 비교는 통과하지만 정상 합성 주소 선택 실패
- `CJ2_3_STABLE_VALUE_INTEGRATION_LOSS`: 정상 선택은 통과하지만 안정 값 최종 판독 실패
- `CJ2_4_NOT_CONJUNCTIVE`: 정상 팔이 통과해도 한쪽 성분 통제가 35% 초과
- `CJ2_0_INVALID`: 선행 자료, 정확 주소 양성 비교, 호출 흐름, 가짜·복구 조건 실패

판정 우선순위는 `CJ2_0 → CJ2_4 → CJ2_2 → CJ2_3 → CJ2_1`이다. 성공해도 표준 합성 주소와
일반 기억 표현으로 가능한 기능이므로 의식 증거가 아니다.
