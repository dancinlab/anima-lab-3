# DECAY-1 — 기억 경쟁과 시간 경과 분해

상태: 실행 규약 수리 등록
등록일: 2026-08-10  
선행 결과: `CAPACITY-1=C3_CAPACITY_BOUNDARY_2`

## 질문

`CAPACITY-1`에서 안정 주소는 사건 두 개를 통과했지만 세 개부터 등록 기준을 벗어났다. 사건이
늘면서 기억 후보가 서로 경쟁한 것인지, 세 번째 사건을 처리하는 동안 내부 상태가 바뀐 것인지,
질문 전 시간이 더 지나 주소가 흐려진 것인지 분리한다.

이번 검사는 주소 변환이나 기억 장치를 고치지 않는다. `EPISODE-2`의 얼린 폭 32 안정 주소,
기존 `VectorMemory`, 값 상태 판독과 `CAPACITY-1`의 감각 흐름을 그대로 사용한다. 통과해도 일반
기억보다 고유하거나 의식의 증거라는 뜻은 아니다.

## 중첩 실행 흐름

모든 회차는 서로 다른 `상황 → 열쇠 → 값` 사건 세 개를 미리 만든다. 질문 대상은 첫 두 사건에
정확히 균형화한다. 같은 회차와 같은 난수에서 아래 세 조건을 중첩 비교한다.

1. `two_stream_two_candidates`: 첫 두 사건만 감각하고 두 주소를 저장한다.
2. `three_stream_two_candidates`: 세 사건을 모두 감각하지만 첫 두 주소만 저장한다.
3. `three_stream_three_candidates`: 세 사건을 모두 감각하고 세 주소를 모두 저장한다.

1과 2의 첫 두 사건 상태가 한 비트라도 다르면 무효다. 2와 3은 같은 세 사건 상태와 같은 질문
상태를 쓰고 기억에 세 번째 후보를 넣는지 여부만 다르다. 각 조건에서 마지막 사건 뒤 방해 입력을
`0 / 2 / 4 / 8`개 넣은 다음 질문 열쇠를 다시 감각한다.

- 1과 2의 차이: 저장 후보 수와 무관한 세 번째 사건 처리 이력
- 2와 3의 차이: 같은 내부 이력에서 기억 검색 후보가 두 개에서 세 개로 늘어난 효과
- 같은 조건의 방해 입력별 차이: 질문까지 시간이 더 지난 효과

## 고정 사양

- seed: `1337 / 7331`
- 회차당 준비 사건: `3`
- 질문 대상: 첫 두 사건, 위치별 정확한 균형
- 평가 회차: 방해 입력 수별·seed별 `768`
- 열쇠·값·상황 종류: 각각 `8`
- 질문 전 방해 입력: `0 / 2 / 4 / 8`
- 주소 변환: `KEY-1` seed별 폭 32 얼린 선형 변환
- 기억: 기존 `VectorMemory`, cosine top-1
- 상태 특징 폭·감각 단계·값 원형: `EPISODE-1`과 동일
- 셀 수: 엔진의 등록 범위 2~48, 주소 입력은 기존과 같은 셀 평균
- 장치: CPU

768회차는 목표 값·질문 위치·질문 열쇠·질문 상황을 정확히 균형화한다. 모든 seed·회차·조건·문턱과
자료 생성 seed는 구현 단계의 `measurement/decay_registry.py`를 단일 기준으로 고정한다. 그
파일의 `preregistration_commit`은 README와 이 문서를 먼저 고정한 Git 커밋을 가리켜야 한다.

## 비교와 통제

각 방해 입력 수에서 다음 팔을 기록한다.

1. 위 세 안정 주소 조건
2. `raw_three_stream_three_candidates`: 주소 변환을 끈 원시 내부 주소
3. `exact_three_candidates`: 정확한 원-핫 주소 세 개를 같은 `VectorMemory`에 저장
4. `exact_three_partner_swap`: 정확 주소의 내용을 한 칸 돌려 원인을 끊음
5. `exact_three_recovered`: 정상 연결을 새 기억에 다시 저장해 복구

각 팔에는 최종 정확도, 저장 위치 선택 정확도, 값별 재현율, 올바른 값 상태 판독, 기억 API와 직접
cosine 선택의 일치율, 주소 여유를 기록한다. 안정 주소 변환은 두 후보 조건에서 회차당 3번, 세
후보 조건에서 4번만 호출되어야 하며 평가 전후 가중치가 같아야 한다.

## 무효 조건

- 사전등록 뒤 seed·회차·방해 입력 수·팔·문턱·자료 흐름을 결과에 맞춰 바꿈
- `EPISODE-2` 결과·판정·주소 변환·값 원형 파일의 SHA-256 지문이 달라짐
- 주소 변환이나 값 원형을 새로 학습하거나 평가 중 가중치가 바뀜
- 회차 지문이 중복되거나 목표 값·질문 위치·질문 열쇠·질문 상황 균형이 맞지 않음
- 같은 회차의 2사건·3사건 흐름에서 첫 두 열쇠와 값 상태가 완전히 같지 않음
- 방해 입력 수 하나라도 정확 주소 선택이 99%, 최종 정확도가 90%, 값별 최저 재현율이 75% 미만
- 내용 한 칸 맞바꾸기가 5% 초과 또는 복구 예측 일치가 100% 미만
- 기억 API가 직접 cosine top-1 선택과 한 회차라도 다름
- 셀 수·주소 폭·변환 호출 수가 등록 범위를 벗어남
- seed·방해 입력 수·팔·필수 수치가 빠지거나 NaN·무한값이 있음

## 조건 통과 기준

한 조건은 두 seed 모두 다음을 만족할 때만 통과한다.

- 안정 주소 저장 위치 선택 정확도 90% 이상
- 안정 주소 최종 정확도 90% 이상
- 안정 주소 값별 최저 재현율 75% 이상
- 올바른 저장 내용의 값 판독 정확도 90% 이상

`two_stream_two_candidates`의 방해 입력 2개 조건이 통과하지 못하면 `CAPACITY-1`의 사건 두 개
양성 결과를 재현하지 못한 것이므로 결론을 내리지 않는다. 방해 입력이 늘어난 뒤 실패한 조건이 더
긴 방해 입력에서 다시 통과하면 비단조 결과로 보존하고 원인을 고르지 않는다.

## 사전 판정

- `D1_RETRIEVAL_COMPETITION`: 방해 입력 2개에서 2사건·2후보와 3사건·2후보는 통과하지만
  3사건·3후보만 실패하며, 3후보는 방해 입력 0개에서도 실패
- `D2_STREAM_HISTORY_LOSS`: 방해 입력 2개에서 2사건·2후보는 통과하지만 3사건·2후보부터 실패하며,
  3사건·2후보는 방해 입력 0개에서도 실패
- `D3_DELAY_INTERACTION`: 방해 입력 0개에서는 더 긴 흐름 또는 세 후보 조건이 통과하지만 방해
  입력 2개에서 처음 실패해, 단일 요인보다 시간과의 결합이 경계를 만듦
- `D4_BOUNDARY_NOT_REPRODUCED`: 방해 입력 2개에서 세 안정 주소 조건이 모두 통과
- `D5_NON_MONOTONIC_OR_MIXED`: 더 긴 방해 뒤 재통과하거나 두 seed의 최초 실패 위치가 다름
- `D0_INVALID`: 원본·지문·얼림·자료·중첩 상태·양성 비교·가짜 비교·복구 조건 중 하나라도 무효

판정 우선순위는 `D0 → D5 → D3 → D2 → D1 → D4`다. `D1`이면 검색 후보를 구분하는 최소
분리 기능을 검토한다. `D2`면 세 번째 사건 처리 중에도 주소 정체성을 유지하는 상태 갱신 방식을
검토한다. `D3`면 고정 시간 기억 또는 주소 새로고침을 먼저 검토한다. `D4`나 `D5`면 구조를
추가하지 않고 더 큰 독립 회차로 경계를 다시 확인한다.

결과를 본 뒤 방해 입력 수, 회차 수, 문턱, seed나 가중치를 조정하지 않는다.

## 실행 전 규약 수리

실행기 고정 커밋 `d86651093`의 최초 전체 실행 뒤, 시간 조건마다 `delay_seed_stride`를 더해 서로
다른 `QuantumC` 초기 상태를 사용한 사실을 발견했다. 이는 같은 회차에서 방해 입력 수만 바꾼다는
위 중첩 흐름을 위반하므로 최초 결과와 판정은 연구 결론으로 사용하지 않는다. 해당 산출물은
`measurement/decay_invalid_rng_results.json`과
`measurement/decay_invalid_rng_verdict.json`에 원형 보존한다.

수리는 결과값·회차·방해 입력 수·팔·문턱·주소 가중치를 바꾸지 않는다. 모든 방해 입력 조건의
`trial_seed`를 `episode_seed_base + seed × seed_stride + 회차 번호` 하나로 통일하고, 판정기가
각 seed의 네 조건에서 `episode_seed_sha256` 완전 일치를 요구하게 한다. 첫 두 사건 상태의 완전
일치 검사는 그대로 유지한다. 이 수리를 README와 원장에 먼저 고정한 커밋을 구현 사양의
`protocol_repair_commit`으로 기록한 뒤 전체 실험을 처음부터 다시 실행한다.
