# VALUE-2 — 시간에 안정적인 값 표현의 공용 기억 연결

상태: 완료 · `VT1_STABLE_VALUE_PATH_VALID_NOT_UNIQUE`
등록일: 2026-08-11
선행 결과: `VALUE-MECHANISM-1=VP2_LATE_POSITION_LOSS`

## 질문

같은 값을 나타내는 내부 위상 상태가 앞선 감각 흐름에 따라 달라져 5번째 이후 판독이 실패했다.
기존 결정형 주소 맞춤을 값 상태에 재사용해 같은 값의 시간별 상태를 하나의 공통 표현으로 바꾸면,
공용 기억 경로가 모든 위치에서 저장된 답을 안정적으로 읽을 수 있는가?

## 최소 공용 수정

- 기존 `fit_stable_key_projector(..., method="canonical_ridge")`를 변경 없이 재사용한다.
- 입력 폭 96, 출력 폭 32, 값 8종의 고정 직교 목표를 사용한다.
- `VectorMemory`에 선택형 `value_transform`을 추가한다. 값 저장 경계에서 셀 평균을 낸 뒤 변환을
  정확히 한 번 적용하며, 검색된 값은 이미 변환된 공통 표현이다.
- `value_transform=None`인 모든 기존 호출의 저장·검색 동작은 바꾸지 않는다.
- 값 변환의 출력은 비어 있지 않은 유한 1차원 텐서여야 하며, 저장 도중 폭이 바뀌면 거부한다.

## 고정 자료와 흐름

- 맞춤 자료 512회차는 평가와 겹치지 않는 고정 seed를 쓴다.
- 두 엔진 시작값 1337·7331에서 회차당 16개 값 상태를 모두 수집해 총 16,384개를 한 번에 맞춘다.
- 값 8종은 각각 2,048개이며 맞춤 순서와 무관하게 같은 가중치가 나와야 한다.
- 평가는 `VALUE-MECHANISM-1`의 512회차, 질문 위치 `1·5·9·13·16번째`, 값 원형 seed 2개 ×
  엔진 시작 seed 2개를 그대로 쓴다.
- 정확한 상황+열쇠 주소로 검색 위치를 고정하고, 값 상태 변환만 바꾼다.
- 평가 중 다시 맞춤, 결과를 본 뒤 폭·문턱·자료량 변경은 하지 않는다. 장치는 CPU다.

## 비교 조건

1. 공용 `VectorMemory(value_transform=...)` 정상 조건
2. 장치 밖에서 같은 값을 변환해 저장한 기준
3. 값 변환을 끈 원시 상태 비교
4. 변환 뒤 저장 내용을 한 값씩 돌린 가짜 비교
5. 정상 내용을 새 공용 기억에 다시 저장한 복구 비교

## 유효 조건과 문턱

- 선행 결과·판정과 값 원형 파일 지문 일치
- 맞춤·평가 회차가 겹치지 않고 맞춤 값 8종이 정확히 균형
- 결정형 맞춤의 반복 실행과 입력 순서 역전 결과가 완전히 같음
- 겹치지 않는 평가 상태의 값 분류 정확도 90%, 값별 최저 맞힘률 75% 이상
- 다섯 위치의 공용 정상 최종 정확도 90%, 값별 최저 맞힘률 75% 이상
- 공용 정상과 장치 밖 기준의 예측 100% 일치
- 값 변환 차단 시 5번째 이후 조건 중 하나 이상이 85% 이하이며 정상 대비 15%p 이상 하락
- 가짜 내용 정확도 5% 이하, 복구 예측과 기억 API 일치 100%
- 공용 정상은 회차당 값 변환 16회, 저장 16회, 검색 1회, 값 폭 32
- 기존 변환 없는 `VectorMemory` 회귀 검사 통과

## 사전 판정

- `VT1_STABLE_VALUE_PATH_VALID_NOT_UNIQUE`: 값 분류와 공용 기억의 다섯 위치 및 모든 통제 통과
- `VT2_VALUE_TRANSFORM_INVALID`: 겹치지 않는 상태의 값 분류가 문턱 미달
- `VT3_MEMORY_INTEGRATION_LOSS`: 값 분류는 통과하지만 공용 기억 최종 판독이 실패
- `VT4_NOT_CAUSAL`: 원시 상태 차단 비교가 선행 위치 실패를 재현하지 않음
- `VT0_INVALID`: 선행 자료, 맞춤 독립성·결정성, 호출 흐름, 가짜·복구 조건 실패

판정 우선순위는 `VT0 → VT4 → VT2 → VT3 → VT1`이다. `VT1`이면 다음 `CONJUNCTION-2`에서
안정 값 표현과 상황+열쇠 합성 주소를 함께 사용해 두 부분 결합 기억을 다시 검사한다. 성공해도
일반 기억 표현 수리이며 의식 증거가 아니다.

결과를 보기 전 이 문서와 README를 커밋하고 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 판정과 다음 단계

판정은 `VT1_STABLE_VALUE_PATH_VALID_NOT_UNIQUE`다. 같은 값의 시간별 위상 상태를 하나의 결정형
표현으로 맞추자 모든 처리 위치에서 공용 기억 판독이 회복됐고, 변환 차단 시 선행 실패가 다시
나타났다. 이는 공용 값 저장 경계의 근본 수정이지만 일반 기억 표현이므로 의식 증거는 아니다.

다음 `CONJUNCTION-2`는 이 얼린 값 변환을 `CONJUNCTION-1`에 연결한다. 정확 주소 양성 비교를
먼저 복구한 뒤에야 상황+열쇠 합성 주소가 두 부분을 실제로 구분하는지 판정한다.
