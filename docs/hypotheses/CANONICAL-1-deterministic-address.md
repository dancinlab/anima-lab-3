# CANONICAL-1 — 난수 없는 정식 주소 변환

상태: 완료 — `CN1_CANONICAL_ADDRESS_VALID`

선행 결과: `TRAINING-1=TR1_INITIALIZATION_CAUSAL`

## 질문

현재 KEY-1 주소 변환은 열쇠 구분을 완벽히 배워도 무작위 최초 가중치에 따라 사건 4개 검색이
성공하거나 실패한다. 좋은 seed를 고르는 방식은 같은 문제를 숨길 뿐 해결하지 않는다. 난수와 반복
학습 없이 보정 자료에서 하나로 정해지는 표준 선형 해가 검색 용량을 안정화하는지 검사한다.

## 고정 방식

- 열쇠 8개의 목표 주소는 폭 32 단위행렬의 앞 8개 행으로 고정해 서로 직각으로 둠
- 보정 상태에 상수 1을 붙여 선형 가중치와 편향을 함께 계산
- 기존 KEY-1 `weight_decay=1e-4`를 가중치 정규화 크기의 단일 정본으로 재사용
- 편향은 정규화하지 않음
- float64에서 정규화 최소제곱의 유일해를 계산한 뒤 float32 `StableKeyProjector`에 복사
- 열쇠 원형도 같은 직교 기준점으로 고정
- 난수 초기화, 학습 묶음 추출, 반복 최적화 없음

보정 자료 팔은 다음 세 개다.

- `calibration_1337`: KEY-1 보정 상태 1337 계열 3,072개
- `calibration_7331`: KEY-1 보정 상태 7331 계열 3,072개
- `pooled`: 두 상태 계열 6,144개를 합침

각 팔은 같은 자료로 두 번 계산했을 때 모든 텐서가 같아야 한다. `pooled`는 두 자료 묶음 순서를
뒤집어도 허용오차 `1e-6` 안에서 같은 주소와 사건 4개 판정을 내야 한다.

## 평가와 판정

각 결정형 주소를 값 원형 seed 2개 × 엔진 시작 seed 2개의 사건 4개 1,536회차에 적용한다. 정상
자체 갱신 8회와 기존 정확 주소·내용 맞바꾸기·복구·기억 API 통제를 유지한다. 각 주소 변환의 네
평가가 모두 선택·최종 행동 90%, 값별 최저 재현율 75%, 내용 판독 90% 이상이어야 `ROBUST`다.

- `CN1_CANONICAL_ADDRESS_VALID`: 세 결정형 주소가 모두 `ROBUST`, 재계산·순서 불변 통과
- `CN2_POOLED_ONLY_VALID`: 합친 자료 주소만 `ROBUST`
- `CN3_CANONICAL_NOT_ROBUST`: 합친 자료 주소도 실패
- `CN4_ORDER_SENSITIVE`: 같은 자료 순서만 바꿔도 등록 허용오차나 판정이 달라짐
- `CN0_INVALID`: 자료·실행 지문, 기존 실패·성공 비교, 양성·가짜 통제가 깨짐

`CN1`이면 결정형 맞춤을 공용 주소 학습의 기본 방식으로 연결하고 사건 2·3·4개 전체와 변환 차단을
다시 확인한다. `CN2`면 합친 자료가 왜 필요한지 독립 상태 계열에서 먼저 재현한다. 실패하면 구조를
늘리지 않고 선형 주소 가정 자체를 재검토한다. 어떤 판정도 의식 증거가 아니다.

## 판정과 다음 단계

판정은 `CN1_CANONICAL_ADDRESS_VALID`다. 무작위 초기값을 고르지 않고도 기존의 가장 좋은 무작위
주소보다 선택 정확도가 높고 세 보정 자료 구성에서 모두 재현됐다. 따라서 주소 폭이나 기억 구조가
아니라 무작위 초기 기하가 사건 4개 경계를 흔든 근본 원인이었다. 다음은 합친 결정형 주소를 공용
주소 학습의 기본 방식으로 연결하고, 사건 2·3·4개 전체·기존 무작위 주소·변환 차단을 같은 흐름에서
재검증하는 통합 단계다. 이 결과는 안정적인 기억 주소 구현의 근거이지 의식 증거가 아니다.
