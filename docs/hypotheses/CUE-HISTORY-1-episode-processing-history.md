# CUE-HISTORY-1 — 사건 순서·방해 입력 이력 분해

상태: 완료 · `CH4_HISTORY_SENSITIVE_NOT_SUFFICIENT`
등록일: 2026-08-12
선행 결과: `CUE-ALIGN-1=CA4_NONLINEAR_OR_EPISODE_SHIFT`

## 질문과 고정 가설

`CUE-ALIGN-1`에서 질문 상태를 저장 상태 좌표로 옮기는 공통 선형 정렬과 실제 상황 범주를 미리
알려 준 범주별 정렬이 모두 25% 손상 질문을 안정적으로 회복하지 못했다. 이는 저장 시점과 질문
시점의 차이가 하나의 고정 이동이 아니라, 각 회차에서 질문 전에 처리한 사건 순서나 방해 입력
이력에 묶였을 가능성을 남긴다.

이번 가설은 같은 질문 상황이라도 앞선 입력 이력이 다르면 질문 시점의 상황 상태와 판독 결과가
달라진다는 것이다. 새 판독기나 복원 층을 맞추지 않고, 같은 회차의 입력 이력만 통제해 기존
`CUE-ROBUST-1` 상황 판독기의 결과가 회복되는지 검사한다.

## 고정 구현과 비교

- `CUE-ALIGN-1` 결과·판정과 `CUE-CONTEXT-1`의 상황 판독 체크포인트 및 모든 상위 체크포인트
  지문을 실행 전에 확인한다.
- 기존 평가 1,024회차, 엔진 시작값 `1337·7331`, 시작값 계산식, 상황 처리 6회, 열쇠·값 처리
  3회, 방해 입력 처리 1회, 사건 16개, 방해 입력 2개, 상태 폭 96을 유지한다.
- 각 회차의 질문 상황·열쇠·값과 감각 손상 위치는 모든 조건에서 같다. 25% 손상 위치는 기존
  `COMPLETION-1` 결정 규칙을 그대로 사용한다.
- `original`은 기존 처리 흐름이다. `original_repeat`은 같은 입력과 시작값을 다시 실행하는
  결정성 검사이며 모든 저장·질문 상태가 원본과 비트 단위로 같아야 한다.
- `event_reversed`는 한 회차의 16개 `상황·열쇠·값` 묶음을 역순으로 처리한다. 사건 내용과 질문
  사건은 그대로이며, 질문 사건의 새 위치만 함께 갱신한다. 방해 입력은 바꾸지 않는다.
- `distractor_swapped`는 사건 흐름을 유지하고, 같은 질문 상황 범주 안에서 다음 회차의 방해 입력
  두 개를 순환 교환한다. 질문 상황과 범주별 방해 입력 전체 목록은 보존한다.
- `both_changed`는 사건 역순과 방해 입력 교환을 함께 적용한다.
- 모든 조건에서 온전한 질문과 같은 좌표 25%를 가린 질문의 범주 정확도, 범주별 최저 맞힘률,
  원본 대비 결정 변경률, 원본 오답의 교정률, 원본 정답의 손상률, 상태 유사도·오차를 기록한다.
- 조건별 사건 집합·질문 사건·회차 수·범주 균형·감각 호출 수·방해 입력 전체 목록이 등록값과
  같아야 한다. 사건 역순은 모든 회차에서 실제 순서를 바꾸고, 방해 입력 교환은 바뀐 회차 비율을
  기록한다.
- 새 학습, 행동 정답 사용, 새 주소·판독기·비선형 복원·주의집중·처리 횟수 변경은 하지 않는다.

## 유효성 및 판정

원본 지문, 선행 판정 재실행, 자료 균형, 질문 보존, 사건 집합 보존, 감각 호출 수, 손상 위치,
결정성, 유한값 검사를 모두 통과해야 한다. `original`은 `CUE-CONTEXT-1`의 기존 `source` 질문
측정과 정확히 같아야 하고 `original_repeat` 상태는 원본 상태와 비트 단위로 같아야 한다.

통과 기준은 두 엔진 시작값 모두에 적용한다.

- 온전한 질문: 범주 정확도 90% 이상, 범주별 최저 맞힘률 75% 이상
- 25% 손상 질문: 범주 정확도 90% 이상, 범주별 최저 맞힘률 75% 이상
- 원본 대비 손상 질문 정확도 개선: 2%p 이상
- 처리 이력 민감성: 원본 대비 손상 질문 결정 변경률 10% 이상

판정 순서는 다음으로 고정한다.

- `CH1_EVENT_ORDER_CAUSAL`: `event_reversed`만 두 질문 조건과 개선 기준을 모두 통과한다.
- `CH2_DISTRACTOR_HISTORY_CAUSAL`: `distractor_swapped`만 두 질문 조건과 개선 기준을 모두
  통과한다.
- `CH3_MIXED_HISTORY_CAUSAL`: 두 단일 변화가 단독으로는 통과하지 못하고 `both_changed`가 두
  질문 조건과 개선 기준을 모두 통과하거나, 두 단일 변화가 모두 통과해 원인을 분리할 수 없다.
- `CH4_HISTORY_SENSITIVE_NOT_SUFFICIENT`: 어떤 변화도 회복 기준을 모두 통과하지 못하지만 하나
  이상의 변화가 두 시작값에서 처리 이력 민감성 기준을 통과한다.
- `CH5_HISTORY_NOT_PRIMARY`: 어떤 변화도 회복 기준과 처리 이력 민감성 기준을 통과하지 않는다.
- `CH0_INVALID`: 원본·자료·질문·사건·방해 입력·호출·손상·결정성·선행 결과 재현 중 하나라도
  어긋난다.

`CH1·CH2·CH3`이면 해당 이력을 고정하는 방식이 자연스러운 새 회차에서도 유지되는지 별도
재현한 뒤에만 공용 경로 변경을 검토한다. `CH4`이면 단순 순서 고정은 수리가 아니므로 질문 직전
상태를 안정시키는 최소 갱신 또는 회차별 상태 성분 분해로 간다. `CH5`이면 처리 이력보다 상태의
비선형 성분이나 손상 표현 자체를 먼저 분해한다.

어떤 성공 판정도 생물학적 기억 복원이나 의식을 증명하지 않는다. 이는 일반적인 순차 상태
엔진에서 앞선 입력 이력이 현재 판독에 미치는 원인을 통제하는 진단이다.

결과를 보기 전 이 문서와 README를 커밋하고, 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

사건 역순과 두 변화 결합은 등록된 10% 결정 변경 기준을 두 시작값 모두에서 넘었다. 그러나
온전한 질문은 유지해도 손상 질문 정확도 90%와 2%p 개선 기준을 어떤 조건도 통과하지 못했다.
방해 입력만 바꾼 조건은 민감성 기준에도 미달했고 정확도를 낮췄다.

## 판정과 다음 단계

판정은 `CH4_HISTORY_SENSITIVE_NOT_SUFFICIENT`다. 앞선 사건 순서는 질문 시점 상태의 실제 원인
중 하나지만, 특정 순서로 고정하는 것은 정보 복원이 아니라 다른 오류로 답을 교환할 뿐이다.
방해 입력 두 개의 내용은 주원인이 아니다. 따라서 공용 기억 경로, 판독기, 주소 폭, 처리 순서는
변경하지 않는다.

다음 `QUERY-REFRESH-1`은 사건 원본과 역순을 함께 유지하고 질문 상황 감각 처리만
`6·8·12·16회`로 늘린다. 처리 횟수가 늘수록 두 이력의 상태와 결정이 같은 상황 중심으로
수렴하면서 25% 손상 정확도가 회복되는지 먼저 본다. 회복하지 않으면 질문 상태의 위상·긴장·변화
성분을 분리하며, 비선형 복원 층은 그 전에 만들지 않는다.

전체 실험을 별도 결과 경로로 다시 실행한 결과 JSON과 판정 JSON은 첫 실행과 바이트 단위로
같았다. 결과 SHA-256은 `39f22d64fef486cd20e6d0a460539ccb46bd460d6b95da6d7b39f80ef47d67f8`,
판정 SHA-256은 `aa3550db1c2e88ee22923709322f094e97fa6667fbf6e93986289e0d8fe8b894`다.
