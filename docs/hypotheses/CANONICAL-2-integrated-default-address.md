# CANONICAL-2 — 결정형 주소의 공용 기본 연결

상태: 사전등록

선행 결과: `CANONICAL-1=CN1_CANONICAL_ADDRESS_VALID`

## 질문

결정형 주소는 사건 4개에서 세 보정 자료 구성 모두 통과했다. 이제 실험용 함수에만 남기지 않고
공용 주소 맞춤의 기본 방식으로 연결했을 때 사건 수 전체에서 안정적이며, 주소 변환이 실제 원인인지
확인한다.

## 구현 고정

- `key_stability.fit_stable_key_projector()`를 공용 진입점으로 추가
- 기본 `method=canonical_ridge`
- 기본 방식은 CANONICAL-1의 고정 직교 목표·float64 정규화 최소제곱 해를 사용
- 이전 `train_projector()`와 KEY-1 체크포인트 형식은 변경하지 않음
- 명시하지 않은 기존 호출의 결과는 비트 단위로 유지
- 1337·7331 보정 상태 6,144개를 합친 공용 주소 하나를 새 진입점으로 계산
- 계산된 가중치는 CANONICAL-1 `pooled` 체크포인트와 텐서 단위로 같아야 함

## 평가

- 사건 수 `2 / 3 / 4`
- 각 사건 수에서 값 원형 seed `1337 / 7331` × 엔진 시작 seed `1337 / 7331`
- 각 1,536회차, 질문 직전 정상 자체 갱신 8회
- 정확 주소·내용 맞바꾸기·복구·기억 API 통제
- 공용 `VectorMemory(key_transform=...)` 저장·검색 경로

12개 정상 조합 모두 주소 선택 90%, 최종 행동 90%, 값별 최저 재현율 75%, 내용 판독 90% 이상을
통과해야 한다. 사건 4개에서 변환 차단 팔은 정상보다 주소 선택과 최종 행동이 각각 50%p 이상
낮아야 한다.

## 판정

- `CI1_CANONICAL_DEFAULT_INTEGRATED`: 전체 12조합 통과, 사건 4개 차단 효과와 기존 호환 통과
- `CI2_PARTIAL_COUNT_BOUNDARY`: 사건 2개부터 연속된 일부 사건 수만 통과
- `CI3_TRANSFORM_NOT_CAUSAL`: 전체 성능은 통과하지만 사건 4개 차단 효과가 기준 미달
- `CI4_INTEGRATION_REGRESSION`: CANONICAL-1 재현 또는 기존 호출 호환 실패
- `CI0_INVALID`: 자료·실행 지문이나 양성·가짜 통제 실패

`CI1`이면 무작위 KEY-1 학습은 역사적 비교로만 남기고 결정형 맞춤을 이후 기억 주소의 단일 기본
방식으로 사용한다. 다음 연구는 다시 `SEPARATION-2`로 돌아가 비슷한 사건 구분을 검사한다. 어떤
판정도 의식 증거가 아니다.
