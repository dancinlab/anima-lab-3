# QUERY-REFRESH-2 — 공용 기억 경로의 질문 새로 고침

상태: 완료 · `QRI2_CONTEXT_PATH_RECOVERED`
등록일: 2026-08-12
선행 결과: `QUERY-REFRESH-1=QR1_REFRESH_RECOVERS_AND_CONVERGES`

## 질문과 고정 가설

`QUERY-REFRESH-1`은 질문 상황 감각을 6회가 아니라 8회 처리하면 25% 손상 상황 판독이
회복되고, 서로 다른 사건 순서의 결정 차이도 줄어든다는 것을 확인했다. 이번에는 확인된 8회를
공용 `VectorMemory` 기억 호출에 선택적으로 연결했을 때 저장 위치 선택과 최종 행동까지
회복되는지 검사한다.

가설은 질문 상황을 8회 처리한 경로가 온전한 행동을 유지하면서 상황 25% 손상 행동을
회복한다는 것이다. 열쇠 감각 처리는 3회로 유지하므로 열쇠 손상과 양쪽 손상이 남으면 이를
질문 상황 새로 고침의 실패로 섞지 않고 잔여 열쇠 경로 손실로 분리한다.

## 고정 구현과 비교

- `QUERY-REFRESH-1` 결과·판정과 `CUE-ROBUST-1` 손상 대응 판독기·값 판독기·원형 지문을
  실행 전에 확인한다.
- 기존 평가 1,024회차, 원형 시작값 `1337·7331`, 엔진 시작값 `1337·7331`, 사건 16개,
  방해 입력 2개, 저장 상황 처리 6회, 열쇠·값 처리 3회, 방해 입력 처리 1회, 상태 폭 96을
  유지한다.
- 공용 `VectorMemory`의 합성 주소 변환, 상황 범주 중심, 안정 값 변환, 저장·검색 API를
  그대로 사용한다. 새 판독기·주소·복원 층·주의집중은 추가하지 않는다.
- 질문 상황 처리만 `baseline_6`, `refreshed_8`, `disabled_6`, `recovered_8`로 바꾼다.
  `disabled_6`은 기존 실패를 재현하고 `recovered_8`은 다시 켠 결과가 최초 8회 결과와
  완전히 같은지 확인한다.
- 각 처리 조건에서 `full_cue`, `context_quarter_missing`, `key_quarter_missing`,
  `both_quarter_missing`의 기억 위치 선택·최종 행동·값별 맞힘률을 기록한다.
- 정확한 상황+열쇠 주소와 내용 맞바꾸기를 양성·가짜 비교로 유지한다.
- 저장 상태·라벨·사건·손상 위치·체크포인트는 처리 조건 사이에서 같아야 하며, 저장과 질문
  감각 호출 수를 따로 센다.

## 유효성 및 판정

선행 결과 재판정, 원본 지문, 자료 균형, 공용 기억 API 호출 수, 모델 고정, 유한값, 저장 상태
동일성, 6회 기준 재현, 8회 복구 재현을 모두 통과해야 한다. 아래 기준은 네 원형·엔진 조합
모두에 적용한다.

- 온전한 행동: 기억 선택·최종 정확도 90% 이상, 값별 최저 맞힘률 75% 이상
- 손상 행동 회복: 해당 기억 선택·최종 정확도 90% 이상
- 인과 효과: 8회 상황 손상 최종 정확도가 6회보다 5%p 이상 높음
- 차단·복구: 차단한 6회는 90% 미만이고, 다시 켠 8회는 최초 8회와 예측·선택이 100% 일치
- 정확 주소: 선택 99% 이상, 최종 90% 이상, 값별 최저 맞힘률 75% 이상
- 내용 맞바꾸기: 최종 정확도 5% 이하

판정 순서는 다음으로 고정한다.

- `QRI1_FULL_PATH_RECOVERED`: 온전·상황·열쇠·양쪽 손상 행동이 모두 회복되고 인과 효과와
  차단·복구가 성립한다.
- `QRI2_CONTEXT_PATH_RECOVERED`: 온전한 행동과 상황 손상은 회복하지만 열쇠 또는 양쪽 손상은
  회복하지 못하며, 인과 효과와 차단·복구는 성립한다.
- `QRI3_BEHAVIOR_IMPROVED_NOT_RECOVERED`: 온전한 행동은 유지되고 상황 손상 행동이 5%p 이상
  좋아지지만 90%에는 못 미친다.
- `QRI4_REFRESH_NOT_CAUSAL`: 온전한 행동은 유지되지만 상황 손상 개선이 5%p 미만이거나
  차단·복구가 성립하지 않는다.
- `QRI5_FULL_BEHAVIOR_REGRESSION`: 8회 온전한 행동이 90% 기준을 통과하지 못한다.
- `QRI0_INVALID`: 선행 결과·지문·자료·호출·API·모델 고정·양성·가짜 비교 중 하나라도
  어긋난다.

`QRI1`이면 질문 8회를 공용 실험 기본값으로 적용하고 `COMPLETION-2`로 간다. `QRI2`이면 상황
처리 8회만 적용하고 다음은 열쇠 질문 처리 시간을 분리한다. `QRI3·QRI4`이면 질문 상황의
처리 횟수만으로 행동을 고칠 수 없으므로 주소 합성 단계로 돌아간다. `QRI5`이면 8회 통합을
폐기한다. 어떤 성공 판정도 생물학적 기억이나 의식을 증명하지 않는다.

결과를 보기 전 이 문서와 README를 커밋하고, 그 커밋을 실행 사양의
`preregistration_commit`으로 고정한다.

## 실행 결과

사전등록은 GitHub `main`의 `cde0a15a4`에 고정했다. 기존 평가 1,024회차, 원형·엔진 시작값
`1337·7331`, 사건 16개, 손상 위치, 손상 대응 상황·열쇠 판독기와 안정 값 판독기를 유지했다.
공용 `VectorMemory` 합성 주소 호출에서 질문 상황 처리만 6회와 8회로 바꿨다. 안정 값 경로는
원형 시작값에 의존하지 않으므로 실제 계산은 두 엔진 시작값 × 두 처리 횟수의 네 고유 실행으로
수행하고, 네 원형·엔진 조합의 등록 결과를 모두 남겼다.

| 조건 | 6회 최종 행동 | 8회 최종 행동 | 판정 |
|---|---:|---:|---|
| 온전한 질문 | 92.68~92.77% | 96.29~96.58% | 유지·개선 |
| 상황 25% 손상 | 85.84~86.43% | 94.82~95.31% | 회복 |
| 열쇠 25% 손상 | 87.11~87.21% | 89.94~90.53% | 엔진 불일치 |
| 양쪽 25% 손상 | 80.86~81.45% | 88.57~89.26% | 90% 미달 |

상황 손상 행동의 개선 폭은 `+8.40~9.47%p`로 등록된 5%p를 넘었다. 8회 온전한 행동과 상황
손상 행동은 모든 조합에서 선택·최종 정확도 기준을 통과했다. 열쇠 손상은 엔진 1337에서
90.53%로 통과했지만 엔진 7331에서 89.94%여서 전체 통과로 세지 않았고, 양쪽 손상은 두
엔진 모두 기준 아래였다.

정확 주소는 모든 조건에서 선택 100%, 최종 `98.93~99.22%`였고 내용 맞바꾸기는
`1.37~1.46%`였다. 모든 공용 기억 API 호출이 일치했고 모델 가중치는 변하지 않았다. 처리
조건 사이에서 저장 상황·열쇠·값과 라벨 지문은 같았으며, 6회 차단은 선행 결과를 완전히
재현하고 8회 복구는 최초 8회와 예측·선택·상태 지문이 모두 같았다.

전체 실험을 별도 출력 경로로 다시 실행한 결과 최초 결과와 판정 파일이 바이트 단위로 같았다.
최초 결과 JSON SHA-256은
`97d5fd66d55fe9bf0462041a77d3111d559f1e5c883b688a7e0b436431a12b53`, 판정 JSON은
`a2cf3f2d6c17abc1f75df3bc13317a8ca0d8ee434418e9b794276de1adac98f7`다.

## 판정과 다음 단계

판정은 `QRI2_CONTEXT_PATH_RECOVERED`다. 질문 상황을 6회에 읽은 것은 공용 기억 행동에서도
너무 이르며, 8회 처리는 상황 손상 행동의 실제 원인이다. 다만 열쇠 질문은 계속 3회만 처리했고
열쇠·양쪽 손상이 기준 바로 아래에 남았다. 다음 `KEY-REFRESH-1`은 상황 8회를 고정하고 열쇠
질문 처리 횟수만 늘려 최소 회복 시간을 찾는다. 새 판독기나 주소 구조는 그 결과 전에는
추가하지 않는다.

이 결과는 공용 기억 통로의 처리 시점을 수리한 것이며 생물학적 기억이나 의식의 증거가 아니다.
