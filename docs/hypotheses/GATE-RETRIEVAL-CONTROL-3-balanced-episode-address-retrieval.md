# GATE-RETRIEVAL-CONTROL-3 — 순서·회차 누출 제거 검색 양성 비교

상태: 완료 — `GRC3B_CONTENT_RANKING_LOSS`
등록일: 2026-08-12

## 질문과 범위

`GATE-RETRIEVAL-CONTROL-2`는 정상 검색 상위 1개가 거의 100%였지만, 사실이 같은 주제의 두 문장
중 항상 앞에 있었고 서로 다른 회차의 글자 주소도 구분하지 못했다. 이번 검사는 검색 모델을 조정하지
않고 이 두 자료 누출만 제거했을 때, 주제 주소로 회차 안의 후보를 찾고 내용 점수로 사실을 고르는
표준 양성 검색 경로가 유효한지만 묻는다.

자료 생성기가 알고 있는 주제와 고정 난수 대응표를 사용하는 통제 실험이다. 실제 대화에서 주제를
찾는 능력, Anima 고유 기능, 주관적 이해 또는 의식을 검사하지 않는다. 실제 사용자 대화의 저장·검색
기본값도 변경하지 않는다.

## 고정 자료와 검색 흐름

- `GATE-2`와 같은 seed `1337`, `7331`, 평가 1,024회차, 회차당 후보 8개, 사실 네 종류와 문장
  틀을 사용한다.
- 사실은 네 주제 구간과 각 구간의 앞·뒤 위치를 조합한 8개 위치 `0~7`에 정확히 128회씩 놓는다.
  사실 종류별로도 앞·뒤 위치가 균형을 이루게 한다.
- 각 회차의 네 주제 구간에는 seed와 회차로 고정된 독립 64차원 주소를 배정한다. 주소는 정규화한
  고정 난수 벡터이며 문장 글자나 후보 위치를 입력으로 쓰지 않는다.
- 질문 주소는 같은 회차에서 사실이 있는 구간의 주소다. 후보는 자신의 회차·구간 주소를 사용한다.
- 주소 유사도 상위 2개 후보만 읽기 목록에 둔다. 두 후보의 주소 점수는 같으며 같은 점수에서는 후보
  위치가 빠른 순서로 고정한다.
- 내용 점수는 `GATE-RETRIEVAL-CONTROL-2`와 같은 고정 다국어 문장 의미 표현, 결정형 ridge 보정
  자료와 중요도 점수를 그대로 사용한다.
- 최종 순위는 주소로 고른 두 후보 안에서 내용 점수가 높은 순서이며, 동점은 후보 위치 순서다.
- Python 3.13, `torch==2.8.0`, `transformers==4.55.4`, CPU와 고정 모델 revision을 유지한다.

## 고정 비교

- `balanced_split`: 정상 회차·주제 주소로 후보 2개를 찾고 정상 내용 점수로 순위화
- `topic_only`: 같은 후보 2개를 주소 점수와 위치만으로 순위화
- `content_only`: 주소 분리 없이 전체 문장 의미 가까운 정도로 순위화
- `shuffled_episode_address`: 질문 주소를 다음 회차 주소와 맞바꾼 가짜 비교
- `shuffled_content`: 정상 후보 안에서 내용 점수를 다음 회차와 맞바꾼 가짜 비교
- `oracle_memory`: 정답 사실만 남긴 양성 비교
- `no_memory`: 검색 후보가 없는 정보 없음 비교

각 조건은 상위 1개와 상위 3개 정답률, 사실 종류별·8개 위치별 정답률, 정답 순위와 결과 지문을
기록한다. 자료·모델·환경·지문·유한값·결정성이 다르면 닫힌 판정기가 무효 처리한다.

## 사전 판정

두 seed 모두 다음 조건을 만족해야 한다.

- 정상 분리 검색 상위 3개 정답률 95% 이상, 상위 1개 90% 이상
- 사실 네 종류와 8개 위치의 정상 상위 1개 정답률 각각 85% 이상
- 정답 사실만 남긴 비교 상위 3개 99% 이상, 기억 없음 5% 이하
- 주제만 사용한 상위 1개 정답률 45~55%, 상위 3개 95% 이상
- 다음 회차 주소를 쓴 상위 3개 정답률 35% 이하
- 다음 회차 내용 점수를 쓴 상위 1개 정답률 60% 이하
- 정상 상위 1개가 다음 회차 내용보다 30%p 이상 높음
- 정상 주소 후보 목록의 정답 포함률 99% 이상
- 사실 위치가 8곳에 각각 128회이고, 각 회차·주제 주소가 모두 고유함

판정은 다음과 같다.

- `GRC3A_BALANCED_SPLIT_VALID`: 모든 통제와 두 seed의 전체·종류·위치 기준 통과
- `GRC3B_CONTENT_RANKING_LOSS`: 주소·양성 통제는 유효하지만 정상 내용 순위 기준 미달
- `GRC3C_EPISODE_ADDRESS_LOSS`: 정상 주소 또는 다른 회차 주소 통제 실패
- `GRC3_0_INVALID`: 자료·모델·환경·지문·결정성·양성·정보 없음·위치 균형 중 하나라도 무효

`GRC3A`여도 실제 대화 기본값은 바꾸지 않는다. 다음에는 이 고정 검색 경로 위에서 `GATE-2`의
저장 선택을 별도 사전등록해 다시 판정한다. 다른 판정이면 결과를 보고 후보 수, 주소 차원, 문장,
모델, 학습량 또는 기준을 조정하지 않고 처음 실패한 주소 또는 내용 단계만 후속 검사한다.

결과를 보기 전에 README와 이 문서를 GitHub `main`에 먼저 고정하고 그 커밋을 실행 사양의
`preregistration_commit`으로 사용한다.

## 실행 결과

사전등록은 GitHub `main`의 `b26e3587a`에 고정했다. 등록 환경에서 두 자료를 실행했고 독립 전체
재실행 결과와 최종 판정은 바이트 단위로 일치했다.

| 조건 | seed 1337 상위 1개 / 3개 | seed 7331 상위 1개 / 3개 |
|---|---:|---:|
| 정상 회차 주소·내용 순위 | 99.61% / 100% | 100% / 100% |
| 회차 주소만 | 50% / 100% | 50% / 100% |
| 전체 문장 의미만 | 5.66% / 19.92% | 0.39% / 2.34% |
| 다음 회차 주소 | 25.10% / 25.20% | 24.90% / 24.90% |
| 다음 회차 내용 점수 | 82.23% / 100% | 81.54% / 100% |
| 정답 사실만 | 100% / 100% | 100% / 100% |
| 기억 없음 | 0% / 0% | 0% / 0% |

정상 주소 후보 목록의 정답 포함률은 두 자료 모두 100%였다. 정상 검색의 사실 종류별 최저 상위
1개 정답률은 98.44% / 100%, 위치별 최저 정답률은 98.44% / 100%였다. 회차 주소만 사용하면
앞·뒤 선택이 정확히 50%였고 다음 회차 주소에서는 약 25%로 떨어졌다. 따라서 앞선 실험의 후보
순서 누출과 회차 주소 충돌은 제거됐다.

반면 다음 회차의 내용 점수를 사용해도 상위 1개가 80% 이상 유지됐다. 정상과의 격차는
17.38%p / 18.46%p라 등록 기준 30%p에 못 미쳤다. 자료 전체의 사실 위치는 균형이지만 생성 순서가
사실 종류 네 개씩 같은 위치를 공유하도록 묶여 있어, 바로 다음 회차로 점수를 옮기는 가짜 비교가
같은 후보 쪽을 자주 유지한다. 이 관찰은 다음 실험의 원인 후보이며, 이번 사전 판정을 바꾸는 근거로
사용하지 않는다.

## 판정과 다음 단계

사전 판정은 `GRC3B_CONTENT_RANKING_LOSS`다. 독립 회차 주소와 정상 내용 점수를 쓴 검색 자체는
거의 100%였지만, 등록한 내용 교환 통제가 충분히 무너지지 않았으므로 유효한 검색 양성 비교로
승격하지 않는다. 실제 대화 저장·검색 기본값도 변경하지 않았다.

최초 실행에서는 결과 생성기의 자료 감사 항목이 이전 실험의 위치 목록 `0·2·4·6`만 사용해 홀수
위치 네 개를 기록하지 않았고 `GRC3_0_INVALID` 처리됐다. 측정 점수와 순위는 최종본과 같지만
감사 기록이 등록된 8개 위치를 전부 증명하지 못한 실행이므로 원자료와 최초 판정을 삭제하지 않고
보존했다. 공용 자료 감사 호출이 이번 등록 사양을 받도록 고친 뒤 전체를 다시 실행했고, 별도 출력의
독립 재실행이 최종 원자료와 바이트 단위로 일치했다.

다음은 검색 모델이나 기준을 조정하지 않고 내용 교환 통제만 분리한다. 사실 위치와 무관한 회차를
짝지어 내용 점수를 바꾸고, 짝 대응표가 위치·종류와 독립이며 두 seed에서 동일한 통계 조건을
만족하는지 결과 전에 검사해야 한다. 이 통제가 유효해진 뒤에만 `GATE-2`의 저장 선택과 검색을
합친다.
